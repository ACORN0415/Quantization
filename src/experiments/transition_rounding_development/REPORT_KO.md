# 전환을 고려한 V rounding — 대수 게이트에서 중단

2026-10-29. 사용자가 승인한 다음 후보를 구현·검토했지만, **첫 단순화 설정에서는 독립적인 전환 목적이 생기지 않아 실제 모델 실험으로 진행하지 않았다.** 이는 실영상에서 품질 개선이 없었다는 결과가 아니다. 실제 연구 캡처·모델·GPU를 사용하지 않은 수학적 타당성 검사와 CPU 합성 확인이다.

## 발견한 문제

처음 제안은 K를 BF16으로 유지하고, V rounding만 고정 scale의 이웃 코드 중 선택하는 것이었다. 같은 query에 대해 캐시 삭제 전후의 평균 출력 오차와 전환 오차를 줄이려 했다. head별 AV 출력, 즉 W_O 이전의 제곱 오차로 시작했다.

실제 encoder는 새 청크의 원본 V는 알지만 이미 압축한 과거의 BF16 원본은 버렸다고 가정한다. 추가 원본 버퍼 없이 직접 계산할 수 있는 첫 surrogate는 **새 청크의 양자화가 추가한 출력 오차**다. 기존 과거 오차를 surrogate에서 제외한 것이지 실제 과거 오차가 없다는 뜻은 아니다.

같은 query·K를 유지하고 다른 과거 토큰만 삭제하면, 살아남는 attention 확률은 공통 상수 c로 재정규화된다. 따라서 새 청크의 오차에 대해 head/query별로

\[
 e_1=c e_0,
\qquad
 D+\lambda J=
 [\tfrac12(1+c^2)+\lambda(c-1)^2]\|e_0\|^2.
\]

즉 **전환 항을 추가한 목표가 query/head별 가중 출력 오차와 정확히 같다.** RTN보다 좋아지더라도, 같은 후보·가중치·탐색을 쓰는 weighted-output 기준선보다 독립적인 목표를 만들었다는 근거가 되지 않는다. 제가 먼저 V만 보자고 단순화한 설정에서는 제안의 차별성을 검사하기 어렵다는 점을 구현 전 검토에서 확인했다.

## 과거 전체 오차와 적용 범위

과거 원본까지 알면 삭제될 토큰의 오차 r이 남는다. 전체 오차를 E로 쓸 때 `e1=cE+d`, `d=−cr`이므로 단순 비례하지 않는다. 이때 전체 목표는 **가중치와 target offset을 바꾼 이차 출력 목표**로 정리할 수 있다. 단순히 첫 공식을 적용해 모든 과거 RTN 오차도 비례한다고 주장하면 틀린다.

정확한 offset에는 삭제될 과거 V의 원본 오차가 필요하다. 이를 평가용 BF16 원본으로 계산하는 offline 진단은 가능하지만, 원본을 버린 배포 codec이 그 정보를 공짜로 얻는 것은 아니다. 그 정보를 저비용으로 추정하거나 저장하는 알고리즘은 아직 없다.

또한 다음은 이번 단순 가정 밖이다.

- query가 실제로 달라지는 경우와 K 코드 선택으로 logit이 바뀌는 경우.
- W_O 이후의 head 혼합을 포함한 출력 오차. head별 c가 다르면 단순 scalar 가중치 식을 그대로 적용할 수 없다.
- 기존 오류의 추가 통계/스케치나 상태별 grouping/code 변화를 사용하는 경우.

따라서 **모든 전환 기반 압축의 불가능성이나 모든 출력 목표와의 동일성을 증명한 것이 아니다.** 이 간단한 첫 버전이 곧 새 방법이라는 설명만 유지할 수 없게 됐다.

## 실행한 검사

실수 산술 유도는 [상세 문서](../TRANSITION_EQUIVALENCE_GATE_KO.md)에 기록했다. 형식 검증 도구의 전 입력 증명이 아니라, 범위를 명시한 대수 유도와 다음 CPU float64 property check다.

| 확인 항목 | 결과 |
|---|---|
| 무작위 attention 32개 × λ 4개 목적·gradient | 128건 일치 |
| 이웃 rounding 조합 | 16개 목적 일치, 동일 후보 선택 |
| 과거 전체 오차의 단순 비례 반례 | 비례가 깨지는 사례 확인 |
| 전체 prefix 오차의 shifted-target 목적 | λ 4개 일치 |
| 최대 목적값 차이 | 3.55×10⁻¹⁵ |
| 최대 gradient 차이 | 1.55×10⁻¹⁵ |

고정 FP16 scale·불변 과거 prefix·동일 32회 후보 예산의 rounding core도 작성하고 CPU 검사 6개를 통과했다. **이 core는 실제 모델 데이터에 실행하지 않았다.** 전체 원본 V를 받는 offline 진단 도구이며, 그대로 배포 encoder라고 부를 수 없다. 코드/scale 바이트 집계도 CPU 검사만 했으므로 배포 메모리·속도·품질 수치는 없다.

서로 다른 에이전트가 비례식과 전체 prefix 예외를 검토했고 루트가 CPU 검사를 다시 실행했다. 같은 작성 주체의 검토이며 외부 독립 검증이 아니다. 결과·코드 해시는 [property_checks.json](property_checks.json)에 보존했다. 최초 구현 커밋 `1bb1669`, W_O 범위 명시 `36f268d`다. 영상 사전 등록이나 보류 실험을 했다고 주장하지 않는다.

```bash
cd ~/Quantization
~/sfq_data/py tools/transition_equivalence_gate.py
~/sfq_data/py tools/test_transition_round_core.py
bash tools/watch_progress.sh 0
```

이번 단순화 후보는 여기서 중단한다. 새 GPU 작업은 없고, 새로운 영상·대형 캡처도 만들지 않았다. K/query 변화·post-W_O·과거 오차 정보를 도입하려면 그 자체의 실행 가능한 알고리즘과 강한 기존 기준선 차이를 먼저 정해야 한다. 단순히 손실 항을 바꿔 다음 대규모 실험으로 넘어갈 근거는 확보하지 못했다.
