A-2 완료: 기존 자동 튜닝 INT8 GEMM·행 scale 융합 경로의 제한 검사
2026-11-04 / RTX 4090 / torch 2.6.0+cu124

결론
Q 투영 한 캡처에서 기존 실행 경로의 이득을 확인했다. FFN 확장은 진행 기준에 미달했고,
FFN 축소는 튜닝 BF16 대조군의 사전 정확성 조건 실패로 속도를 판정하지 않았다.
이는 1개 형상의 실행 기준선 확보이며 새 양자화 방법·전체 영상 가속·품질 보존의 증거가 아니다.
A-1 결과에 따라 근거가 있는 A-2를 수행하라는 사용자 지시의 분기를 완료했다.
B의 GPU 실험이나 A-3 설정 탐색을 자동으로 붙이지 않는다.

왜 A-2였는가
A-1 기본 torch.compile은 입력 양자화와 후처리 비용을 줄였지만 외부 cuBLAS INT8 GEMM은
유지했다. 세 형상 모두 BF16보다 30.9~38.1% 느렸다. 설치된 PyTorch에는 그 경로와 다른
INT8 GEMM 자동 튜닝 및 행 scale 융합 lowering이 있었고 공개 torchao에서도 이를 사용했다.
이를 확인하는 것이 새 정책이나 커널을 만들기 전에 필요한 기존 기준선 점검이었다.
가중치 전치 contiguous, 양자화식·그룹·dtype·입력은 유지했다. BF16에도 GEMM 자동 튜닝을 허용했다.

Q만 통과했다. 부호가 음수인 값은 느려졌다는 뜻이다. 각 조건은 캡처 하나이며 구간은 같은 입력의
반복 측정 변동을 나타낸다. 새 입력·다른 층·다른 denoising 단계의 일반화 구간이 아니다.
형상당 독립 프로세스, 유효 형상당 4팔×12라운드×10호출, 4순환 실행 순서, 각10회 워밍업.
X 양자화부터 최종 BF16 출력까지 시간에 포함했다. 정적 W 준비와 첫 컴파일 호출은 별도다.

실제로 생성된 구현과 메모리
유효한 두 형상의 trace와 생성 코드를 연결하면 다음 세 커널을 확인한다.
1) 입력별 scale과 INT8 입력을 만드는 Triton reduction
2) INT8×INT8, INT32 누산, 행 scale을 곱해 FP32를 저장하는 Triton GEMM
3) 가중치 scale·bias·BF16 변환을 수행하는 Triton pointwise
외부 ampere_igemm 대신 Triton GEMM이 실행됐다. GEMM 뒤 INT32 M×N 버퍼는 없어졌지만,
동일 크기의 FP32 M×N 버퍼가 남았다. 완전한 epilogue 융합이나 큰 메모리 절감이 아니다.
추가 allocated peak(default→fused): Q 43.756→43.737 MB, FFN 확장251.677→251.658 MB.
이는 공통 입력·원래/정수 가중치가 상주한 상태의 추가량이며 전체 모델 VRAM이 아니다.

이번 변경은 GEMM 선택과 행 scale 융합을 함께 바꿨다. 융합하지 않은 autotuned W8A8 팔이
없으므로 융합 자체의 기여와 GEMM 교체의 기여를 분리할 수 없다. "융합만으로 14% 개선"도,
"모든 이득은 GEMM 교체 때문"도 확정하지 않는다. 확인한 것은 이 결합 경로의 전체 호출 이득이다.
두 tuned 팔에 ATEN,TRITON을 지정했지만 설치된 PyTorch의 INT8 lowering은 Triton 후보가
가능할 때 ATen 후보를 제외하고, fused lowering은 Triton 템플릿만 생성한다. BF16과 실제
후보 집합이 동일하다는 뜻은 아니다. 원기록 compiler_config는 전역 기본값이고 팔별 옵션은
options_by_arm에 있다. 소스 근거:
https://github.com/pytorch/pytorch/blob/v2.6.0/torch/_inductor/kernel/mm.py
https://github.com/pytorch/ao/blob/v0.9.0/torchao/kernel/intmm.py
https://github.com/pytorch/ao/blob/v0.9.0/torchao/quantization/utils.py

정확성 및 미판정 형상
세 형상 모두 eager BF16은 원래 캡처와 원소 바이트가 같았다. 별도 고정 정수 GEMM의
eager/tuned 전체 INT32 출력도 일치했다. 읽기 전용 CPU 감사에서 전체 정수 출력을 다시 계산했다.
default/fused W8A8 최종 BF16 출력은 세 형상 모두 서로 원소 바이트가 같다.
원래 BF16 대비 상대 L2는 .00553464/.01184685/.00542272이며 둘 다 사전 조건을 통과했다.
이는 원래 BF16과의 정확 일치나 영상 품질 보존을 뜻하지 않는다.
별도 정수 GEMM의 일치와 최종 출력 일치는 fused 호출 내부의 모든 INT32 값을 직접 검증한
것은 아니다. 중간값을 추가 계측했다고 주장하지 않는다. 독립 compiled quant의 정수 차이
1259/0/571개 역시 전체 호출 내부 관측과 구분한다.

FFN 축소의 유일한 실패는 tuned BF16 상대 L2 .00239828 > 등록 한도 .002였다.
W8A8 후보의 정확성 실패나 성능 실패로 집계하지 않는다. 전체 팔 유효성 게이트에 따라
해당 형상은 타이밍/trace 없이 종료했고 기준을 완화하지 않았다. 누산 순서나 반올림이 원인일
가능성은 있으나 직접 원인을 분리하지 않았다. 표준 BF16 자체의 수학적 정확도가 더 높다는
결론도 없다. 최종 분류는 '대조군 정확성 조건 실패로 성능 판단 불가'다.

다음 판단
전체 linear 교체나 새 연구 채택은 보류한다. Q 형상의 이득은 보존할 가치가 있는 기존 기준선이다.
후속 자원을 쓴다면 먼저 이 Q 경로의 다른 실제 입력에서의 정확성·재현성을 확인하고,
원래 BF16을 유지하는 선택적 적용의 전체 비용을 검토하는 편이 B로 즉시 이동하는 것보다 근거가 있다.

검사하려면 대조군 정확성 요구부터 별도 등록해야 한다. 이번 결과를 살리기 위해 허용오차를 바꾸지 않는다.
