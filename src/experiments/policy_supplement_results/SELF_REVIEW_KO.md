# 자체 리뷰: 추가 평가와 보고 과정

대상은 `10f02f6`까지의 추가 평가·집계·보고서와 완료 파이프라인이다.
같은 작성자가 수행한 자체 검토이며 외부 독립 리뷰가 아니다.
기존 생성 모델 전체나 저비트 커널의 정확성을 새로 증명한 검토도 아니다.

## 1. 높음: 시간 일관성을 충분히 평가했다고 볼 수 없다

`tools/evaluate_policy_supplement.py`의 `needed`와 `pairs`는 청크마다 가운데의
두 인접 쌍만 고른다. 각 영상의 인접 전환 500개 중 84개이며, 청크 경계 전환은
포함하지 않는다. 저장 정책 차이를 평가하면서 경계의 끊김을 놓칠 수 있다.
합성 테스트는 주어진 flow를 이용한 워핑 방향과 산술을 확인할 뿐,
RAFT가 손상 영상에서 실제 움직임을 정확히 추정한다는 검증이 아니다.

따라서 결과는 청크 내부의 표본 시간 잔차 진단이다. INT4의 시간 품질 개선을
확인하지 못했고, INT2의 전체 표본 잔차 비교는 미정의다. 이전의
“시간적 일관성 평가까지 완료”라는 넓은 표현은 부적절하다.
전체 경계 평가나 사람 평가를 수행한 것처럼 해석하면 안 된다.
원래 측정 코드와 수치는 변경하지 않고 이 한계를 보고서에 명시했다.

## 2. 높음: DINO 향상은 주체 유지의 확증이 아니다

`subject_values()`는 전체 프레임 특징의 첫 프레임·직전 프레임 유사도다.
객체 추적, 분할, 개체 식별, 프롬프트 충실도를 검사하지 않는다.
배경·카메라 움직임·정지·동작 소실의 영향을 받는다.
코드의 공식 VBench 실행 결과와의 수치 대조도 수행하지 않았다.
배치/개별 DINO 계산 일치 검사는 공식 평가 파이프라인과의 일치 검사가 아니다.

허용되는 표현은 “이 표본에서 DINO 프레임 특징 일관성이 높았다”다.
“주체가 더 잘 유지된다” 또는 “전체 영상 품질이 입증됐다”로 확대할 수 없다.
특히 INT2 P3의 추정 flow는 낮고 영상 손상도 심해 지표 해석에 주의해야 한다.

## 3. 중간: 사후 설계와 입력 단계 차이

주체·시간 평가는 MUSIQ 결과를 본 뒤 추가했고, 빈 마스크 처리도 실제 실패를
본 뒤 v2로 보완했다. 이는 문서에 기록했지만 사전 등록 확증 분석이 될 수 없다.
먼저 모든 평가를 설계했어야 했다. 지금 추가했다고 그 설계상의 한계가 사라지지 않는다.

추가 평가는 손실 압축 MP4, 주지표 MUSIQ는 원본 디코딩 프레임을 사용했다.
압축 영향에 대한 민감도 검사는 아직 없다. 총 120개 탐색 대조를 계산했고
신뢰구간에 다중 비교 보정을 하지 않았다. 양의 DINO 구간을 새로운 확증 발견으로
부를 수 없다. 별도 보류 데이터에 대한 결론도 아니다.

## 4. 중간: “독립 검증”의 범위를 과장했다 — 수정

기존 감사 코드는 해시·점 추정치·결측 규칙을 확인했지만 신뢰구간은 검증하지 않았다.
또한 작성자가 같으므로 외부 독립 검증도 아니다. 같은 데이터와 방법의 집계를
다른 코드로 재계산했다고 말하는 것이 정확하다.

이번 검토에서 정확한 프롬프트/시드 집합 검사를 추가했다. 명시한 난수 표본을
이용하되 Python 산술과 명시적 분위수 보간으로 모든 유한 신뢰구간을 다시 계산했다.
고의로 구간 끝점을 바꾼 경우 감사가 실패하는 검사도 추가했다.
260개 입력과 집계는 통과했고, 측정 불가 비교 2개(같은 INT2 FR의 전체/후반 구간)는
그대로 미정의였다. 이 검사는 지표의 과학적 타당성을 입증하지 않는다.

## 5. 중간: 재실행하면 편집한 보고서가 사라질 수 있었다 — 진입 경로 보완

`evaluate_policy_supplement.py`의 `analyze()`는 생성 보고서를 덮어쓴다.
`run_policy_supplement.py`도 완료 섹션을 다시 생성해 검토 후 추가한 해석·그림을
없앨 수 있었다. 과거 `VERIFY.md`에서 지적받은 유형의 문제가 반복된 것이다.

완료 파이프라인은 공개 결과가 있으면 기존 보고서를 재생성하지 않도록 막았다.
`tools/reanalyze_policy_supplement.py`는 임시 폴더에 재분석한 뒤 공개 집계와
비교하고, 보고서와 그림의 해시가 바뀌지 않았는지 확인한다. 실제 실행도 통과했다.

측정 당시 소스 해시를 보존하기 위해 동결된 evaluator는 수정하지 않았다.
따라서 그 원본을 직접 `--mode analyze` 또는 `--mode run`으로 실행하면 여전히
출력 보고서를 덮어쓸 수 있다. 일상적인 검증에는 아래 안전한 경로를 사용한다.

```bash
~/sfq_data/py ~/Quantization/tools/reanalyze_policy_supplement.py
~/sfq_data/py ~/Quantization/tools/audit_policy_supplement.py
```

## 유지할 수 있는 결론

기존 사전 등록 코드 해시가 일치함을 다시 확인했다. 이번 검토에서 추가 평가의
집계·신뢰구간을 뒤집는 수치 오류는 발견하지 못했다. 이는 모든 구현에 버그가 없다는 뜻은 아니다.
80개 실험의 근거로 같은 설정·명목 비트폭에서 P3의 후반 MUSIQ가 높았다는 결론은 유지한다.
추가 DINO 결과는 탐색적 보조 근거다. 시간 품질 개선, 객체 동일성 유지,
같은 메모리 예산에서의 우위, 단일 메커니즘 또는 새 방법의 신규성은 확인하지 못했다.

완료 보고 누락과 처음부터 평가를 함께 계획하지 않은 점은 작업 진행과 설계의 문제다.
후속 평가를 수행한 사실과 연구 질문이 충분히 해결됐는지는 구분해서 보고해야 한다.
