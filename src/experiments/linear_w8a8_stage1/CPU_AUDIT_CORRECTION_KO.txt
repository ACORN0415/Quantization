CPU 감사의 합산 정밀도 문제를 확인했다. GPU 재실행·모델 추가 생성은 하지 않았다.
첫 감사는 CPU FP32 norm으로 수천만 원소를 합산해 GPU 보고값과 1e-6 이내에 맞지 않았다.
실패 로그는 audit_attempt1.log에 보존한다. 원래 측정 코드·원래 결과·원래 판정 기준은 변경하지 않았다.

4680×8960 출력에서 CPU 재구성 출력의 FP32 norm:
  오차 norm 26.829761505126953, 기준 norm 2270.595947265625, 비율 0.011816175654530525.
동일 CPU 재구성 출력의 FP64 norm:
  오차 norm 26.990474333380977, 기준 norm 2278.294348410755, 비율 0.011846789837409916.
저장된 GPU 비율: 0.011846846900880337.

즉 이 차이의 주요 원인은 CPU FP32 합산의 정밀도였다. 감사의 합산을 FP64로 수정한다.
GPU W8A8 전체 출력 배열을 저장하지 않았으므로 CPU 재구성과의 원소 비트 일치를 새로 주장하지 않는다.
전체 CPU 정수 행렬곱 기반 재구성의 상대오차 수치와 저장된 GPU 수치의 일치 범위만 확인한다.
