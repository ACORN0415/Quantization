K는 모든head INT4. frame1560 단위로 8개 zero-pad, token-group16, 채널별 scale.
회전 K.float() @ Hadamard128(float32) -> BF16. scale=(absmax_BF16/7)_BF16 clamp_min1e-8 후 FP16 저장.
V는 기존 chunk4680/group16 INT4, 모든 팔 공통. 현재 K/V는 원래 BF16 그대로.
복원: intcode->BF16 * scale->BF16, padding 제거, inverse Hadamard FP32 -> BF16, attention FP32 CPU.

Hfull_damped=H+0.01*mean(diag(H))*I. Hdiag_damped=diag(diag(Hfull_damped)).
L=chol(inv(Hdamped)).T(FP64) -> FP32, 고정채널순서0..127. 보상workspace FP32.
팔:

 OBQ_FULL: 동일 grid/scale에서 full-H Cholesky 순차 error compensation으로 integer code 선택.
 OBQ_DIAG: 같은산술 diagonal-H 대조; 0 off-diagonal 보상은 생략하되 B0_FP32_RTN과 모든코드 일치를 검사.
OBQ는 원본 floor/ceil 두 값 중 선택이라는 제약이 아니며 고정 grid 위 code optimization이다.
