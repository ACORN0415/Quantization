전층 fixed-p0 OBQ capacity 점검 결과
2026-11-05, Codex. root 및 실제 Claude Fable 실행 전 코드 검토 완료.

결론: 사전 전체 적용 자원 gate를 통과했다.
신규28개 층을 빠짐없이 유효 완료했고, 기존18/24를 포함한30개 개발층 모두에서 OBQ_FULL post-Wo SSE가 BF16 RTN 및 FP32 RTN보다 작았다. 어느 층에서도 등록한10% 초과 악화가 없었다.
이는 같은 teacher 입력에서 fixed-p0-H OBQ를 각 층에 적용할 때 국소 손상이 일관되게 줄었다는 결과다. 실제 모든 층을 동시에 압축한 생성, 독립 입력 일반화, 최초 소비 Query의 인과적 이득 또는 GPU 비용은 이 검사로 입증하지 않았다.

전체30층 표

RESULT.json: 원래 함수가 반환한 모든 metric/control/hash/cost와 재사용 출처.
층18/24는 reused_original_capacity, 나머지28개는 new_cpu_extension으로 표시했다. 재사용2개를 새 반복으로 세지 않는다.

pooled 해석
층27–29가 기준선 SSE 합에서 차지하는 실제 비중은 BF16 RTN67.0849%, FP32 RTN76.2723%다. 특히 층28/29 각각의 비중은 BF16에서38.2220%/23.5183%, FP32에서44.4767%/28.3431%다. 따라서 pooled 감소율에는 후반층의 큰 손상 개선이 많이 반영된다.
이 설명은 저장된 SSE를 직접 합산한 결과다. 큰 reference_energy만으로 SSE 지배를 추론하지 않았다. reference_energy는 NSE의 분모이며, 큰 신호 에너지가 큰 절대 오류를 반드시 뜻하지 않는다. 또한 다른27개 층도 양쪽 기준선보다 모두 개선됐으므로 pooled만 좋아지고 다수 층이 나빠진 경우는 아니다.

검증 범위
- 신규28개×p0/p4 원본56개는 각 run_layer에서 manifest hash·파일 크기를 확인했다.
- 모든 새 행에서 source q/k/v 원소 바이트 보존, scale 보존, packed code roundtrip, arm 간 실제 payload 일치, OBQ_DIAG=FP32 RTN을 통과했다.
- 모든 층/팔의 기존 형식 payload는54,097,926 bytes: K27,095,046 + V27,002,880. 원본 frame/group/pad 정책을 바꾸지 않았다.
- 실행 이후 audit_result.py는 torch/GPU 없이12개 잠긴 파일, SELFTEST, lock/result 연결, 새56개와 재사용4개를 포함한 총60개 원자료 파일 hash·크기를 다시 확인했다.
- audit는 math.fsum으로 pooled 수치를 독립 재계산하고, 각 층 SSE/NSE/절대차/비율, 바이트 식, 재사용 자료 정확 일치, 최종 gate를 검증했다. 모두 통과했다.
- 이 사후 감사는 attention 전체를 다시 실행한 독립 수치 재현은 아니다. 원자료 무결성 및 저장 스칼라/판정의 독립 재계산이다.

기존 판단과의 관계
처음18/24 양성 결과를 취소하거나 문턱을 완화한 검사가 아니다. 이번에는 그때 미측정한28개 층에도 같은 방법을 적용한 추가 development 범위 검증이다. 회전 기준선 U/UHP와의 대조는 여전히18/24 두 층에서만 수행됐으며,30층 모두에서 모든 강한 회전/변환을 이겼다고 확대하지 않는다.
다음 판단은 이미 진행하도록 등록한 causal 검사와 실제 encoder 비용에 맡긴다. 국소 SSE 개선이 크더라도 GPTQ 자체의 신규성이 생기지 않으며, 전체 생성 품질·실용 비용·선행연구 차별점은 각각 남아 있다.
