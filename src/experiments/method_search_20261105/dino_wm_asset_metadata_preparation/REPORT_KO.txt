DINO-WM 지정 두 archive의 메타데이터 전용 확인
작성: Codex /root/method_gap_codex. 실제 Opus2 독립 소스/기록 검토는 별도이며 여기서 완료로 표시하지 않는다. planning pair의 임시안·결론은 읽지 않았다.

판정
두 ZIP의 중앙 디렉터리를 읽는 데 성공했다. HF 저장소 총21.93GB를 이 과제의 필수 취득량으로 간주할 필요는 없다. 지정 두 ZIP 자체는 합계3,738,509,143B이며, 그중 PushT 체크포인트/설정과 validation 파일만 따로 존재한다. 그러나 이 작은 묶음만으로 planning 실행이 가능한지는 로더·normalization·추가 backbone 의존성을 확인해야 한다. archive 크기로 GPU/RAM 성공을 주장하지 않는다.

두 묶음만 합치면 압축 member324,172,982B, 추출385,839,513B다. 이것은 선택 취득이 가능할 경우의 archive entry payload 산술이며, 현 도구가 해당 payload를 다운로드하거나 추출할 수 있다는 뜻이 아니다. 보통 전체 ZIP 다운로드를 그대로 사용하면 이 최소량으로 줄지 않는다.

train 쪽은 전체27개 validation보다 훨씬 크다. train metadata 그룹의 추출 합5,195,606,585B와 train/obses 그룹2,166,932,972B가 따로 집계됐다. training token을 기본 로더가 eager load하는지, normalization을 training action에서 다시 계산하는지, 통계가 별도 저장되는지, checkpoint가 필요한 backbone/decoder까지 포함하는지는 확인하지 않았다. hydra.yaml 내용도 아직 읽지 않았으므로 필수 최소 집합을 선언하지 않는다.

RESULT의 groups/합계는 모든18,723개 central entry를 파싱해 계산했다. selected_member_metadata는 저장량 제한상 앞2,000개만 저장하므로 dataset selected_metadata_is_complete=false다. validation 전체와 두 PushT 모델 파일은 이 범위 안에 있어 위 합계는 완전한 해당 subgroup에 대해 계산했다. 학습 파일의 전체 목록이 보존됐다고 말하지 않는다.

HTTP·자원 기록
- 코드 고정 SHA256: 65e3c24765f50a95a32b369607068c12c7d14510f4ab8b4963036e8381571c97.
- 최초 ATTEMPT 1회, 이후 코드 수정·재시도·fallback 없음.
- API JSON3424B, outputs EOF검색창65,557B, pusht EOF검색창65,557B, pusht central directory2,066,938B. 읽은 HTTP body 합2,201,476B로8MiB 이하.
- metadata API만 HTTP200을 읽었다. archive는 모두 HTTP206/정확한 Content-Range·Content-Length를 확인했다. 세 archive Range 요청의302 redirect body는 읽지 않았다. outputs 중앙 디렉터리는 EOF창 안에 있어 재요청하지 않았다.
- EOF 검색은 ZIP 최대 comment를 포함하는65,557B 표준 끝부분 범위다. outputs.zip에서는 이 검색창 중62,205B가 중앙 디렉터리 앞의 압축 member 끝부분과 겹친다. 이것을 순수 구조체 바이트만 받았다고 표현하지 않는다. 용도는 EOCD 탐색이고 해당 압축 payload를 열거나 해제·해석하지 않았다. 그 외 member payload를 목표로 한 Range는0회다. root가 '어떤 incidental payload byte도 금지'로 해석한다면 그 엄격한 범위 적합성은 별도로 판단해야 하며, 여기서 숨기거나 추가 다운로드로 보완하지 않는다.
- HTTP200/Range 거절은 response body를 읽기 전에 닫고 unsupported 처리하는 코드다. 실제 이번 서버는 Range를 지원했으므로 거절 분기는 실행된 서버 사례가 아니다.
- ZIP/ZIP64 parser 소규모 합성 검사7개 통과. 실제 EOCD는 두 archive 모두32bit 값으로 충분했고, dataset member ZIP64 extra는 실제 파싱됐다. full archive CRC/LFS SHA를 재계산하지 않았으므로 LFS 값은 API 선언으로만 표시한다.
- 완료시 등록 시작으로부터284.994초, peak RSS693,440,512B로1GiB 이하. RESULT.json710,364B이고 보고서/소스 포함 전체 출력은16MiB 이하이다. 실제 실행의 자원 상한은 지켰다. 이 도구는 parse/read 지점에서 guard하므로 OS 수준의 hard resource limiter라고 주장하지 않는다.
- GPU/모델·tensor load/압축 해제/패키지 설치/전체 archive 다운로드/원repo 수정/커밋0. archive metadata window 수신과 full asset acquisition을 구분한다.

다음 취득 판단에 필요한 한 가지
planner loader source에서 'PushT checkpoint+hydra+val만으로 planning하며 train 통계/추가 weights를 요구하지 않는가'를 먼저 확정한다. 이 조건이 맞고 별도 selective member 취득·무결성 검증 방식이 승인된다면, 이 세트에 한한 다음 취득 상한을 HTTP512MiB/디스크1GiB 정도로 등록할 산술적 여지는 있다. 이는 추가 DINO/backbone/env 의존성을 포함하는 실행 예산이 아니고 지금의 취득 승인이 아니다. 로더가 train 또는 다른 모델을 필요로 하면 그 요구를 더한 별도 상한으로 다시 판단해야 하며, 위 작은 수치를 실행 가능성의 근거로 사용하지 않는다.
