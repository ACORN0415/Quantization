1. native source로 정확한 미래 tap 사용식 확인 (local src/wan/modules/vae.py, upstream과 동일 sha a4c1d936)
- 저장 시점
  - ResidualBlock.forward(202-220)와 Resample upsample3d(103-137)는 현재 conv 입력 x의 마지막 CACHE_T=2 frame을 clone해 cache_x로 둔다.
  - 그다음 '이전' cache로 현재 conv를 계산하고, 마지막에 feat_cache[idx]=cache_x로 교체한다.
  - 따라서 새로 저장한 state는 현재 호출에는 쓰이지 않고 다음 호출에서만 쓰인다. 현재 출력은 원본(BF16) 값으로 이미 계산된다. 가설의 전제는 소스와 맞다.
- 다음 호출: CausalConv3d.forward(28-36)는 x=cat([s_old, s_new, cur...])이고, 앞 padding이 2−2=0인 kernel_t=3 conv다.
  - 출력 frame 0 = W0·s_old + W1·s_new + W2·cur0
  - 출력 frame 1 = W0·s_new + W1·cur0 + W2·cur1
  - 따라서 저장 오차의 국소 선형 영향은 δy0 = W0 e_old + W1 e_new, δy1 = W0 e_new다.
  - root가 쓴 식(index 0이 가장 오래된 W_old, 1이 W_prev)과 일치한다.
  - stride 1. 시간 kernel 3인 경우는 residual conv (3,3,3)와 time_conv (3,1,1)이고, kernel 1인 shortcut·conv1·conv2는 cache를 쓰지 않는다.
- 호출 형태에 따른 정정·보완(소스 관찰)
  (a) 다음 호출 입력이 1 frame이면(T=1 경로) 그 호출의 출력은 δy0 하나뿐이다.
      그런데 그 호출이 새 cache를 만들 때 cat([feat_cache[-1], cur])로 '이전 cache의 마지막 frame' s_new를 다시 carry한다(110-118, 207-213행).
      그래서 e_new는 그다음 호출에서 W0 e_new로 한 번 더 쓰인다. 미래 사용 항의 집합은 같지만 두 호출에 나뉜다.
      또 carry되는 값은 이미 양자화된 저장값이다. 재저장 시 다시 양자화하면 이중 양자화가 될 수 있다(정책 미정).
  (b) 첫 호출의 upsample3d는 'Rep' 표지를 쓰고 cache 없이 time_conv를 한다(105-108, 127-128). 다음 호출의 앞 frame은 zeros와 cat된다(119-125). 경계 호출은 식이 다르다.
  (c) T≥2 조건은 decoder 중·고해상도 단계에서 성립한다. time 2배 upsample 이후 호출당 2 frame, 그다음 4 frame이다. 즉 state 바이트가 큰 층에 해당한다.
      저해상도 첫 단계(T=1)에는 root 말대로 joint-write 가정을 적용하지 않는다.
  (d) downsample3d 경로는 encoder용이며 decode와 무관하다.
- 국소 손실 L = ||δy0||² + ||δy1||² (출력 채널과 공간 합).
  - 입력 채널 c 단위로 공간·채널 교차항을 버린 대각 proxy는 다음과 같다.
    a_c = ||W0[:,c]||², b_c = ||W0[:,c]||² + ||W1[:,c]||², c_c = <W0[:,c], W1[:,c]>
    (W의 kh·kw까지 펼친 내적)
  - root 식과 일치한다.
  - 정확한 국소 Hessian은 (C_in·k_h·k_w·2)×(C_in·k_h·k_w·2) 크기의 조밀 행렬이다. 입력 채널 사이 항 <W_t[:,c], W_t'[:,c']>와 3×3 공간 이웃 항이 있다.
  - time_conv (3,1,1)은 공간 교차항이 없지만 채널 교차항은 남는다.
- 이 손실은 다음 conv의 preactivation까지만이다. 이후 RMS norm, SiLU, 다음 층, RGB, 그리고 다른 층 state 오차와의 상호작용은 포함하지 않는다(root도 인정).

2. 일반 기법의 특수화 여부 (부모 분석과 helper의 1차 문헌, 아래 통합)
- floor/ceil 4조합 중 2차 proxy를 최소화하는 선택
  = 고정 Hessian H=W^T W(하류 weight에서 온 것) 아래에서 activation 오차 벡터의 2차 형식을 최소화하는 rounding.
  - 이는 AdaRound(가중치의 up/down을 2차 근사로 선택)와 OBQ/GPTQ(2차 오차 최소화 + 순차 보상)를 대상만 'cache state activation'으로, Hessian만 '하류 conv weight Gram'으로 바꾼 구조다.
  - 2×2 블록 대각화는 그 단순한 근사다.
- '독립 RTN보다 proxy가 증가하지 않는다'는 RTN이 후보에 포함되어 생기는 자명한 성질이다. 발견이 아니다(root 동의).
- 이 프로젝트의 기존 FULL/OBQ K-cache rounding(query Hessian H=QᵀQ, 순차 보상)과도 같은 계열이다.
  - 그 경우 국소 SSE 이득이 전체 영상 품질로 이어지지 않아 pilot이 stop_quality였다(full_obq_rollout_pilot). 이것이 강한 사전 경고다.
- 남는 차이 후보: (i) Hessian이 데이터가 아니라 고정 weight에서 와서 causal 시점에 사용 가능하다. (ii) state write 경계와 미래 tap 구조.
  - (i)은 'output-aware activation rounding with weight Gram'의 일반 형태에 포함된다.
  - (ii)는 Conv3D의 시간 kernel 구조를 Hessian 블록으로 쓴 것일 뿐이다.
  - 둘 다 새 미해결 결정이라기보다 적용 위치의 차이다(판정은 아래).

3. 강한 기준선 (같은 bit 수, 같은 scale metadata, 같은 실제 state 바이트)
B1. 같은 shared grid의 독립 RTN.
B2. scale·clipping을 MSE-optimal로 고른 RTN. 채널별 scale을 쓰면 그 metadata 바이트도 동일하게 센다.
B3. 대각 Hessian 가중 RTN 대신 '전체 2×2 블록이 아닌 순차 GPTQ식 보상'.
    - e_old를 먼저 양자화하고, 그 오차를 e_new의 연속값에 −(c_c/b_c)·e_old로 보상한 뒤 양자화한다.
    - 4조합 탐색과 계산량이 비슷하다. 가장 직접적인 일반 기법 기준선이다.
B4. state 바이트를 줄이지 않는 BF16 state. 이는 품질 상한이며, 메모리 이득의 기준이기도 하다.
- 가장 결정적인 단순 기준선은 B2와 B3다. 가설은 B3의 2변수 특수화와 거의 같다. B3 대비 이득이 없으면 기각한다.
