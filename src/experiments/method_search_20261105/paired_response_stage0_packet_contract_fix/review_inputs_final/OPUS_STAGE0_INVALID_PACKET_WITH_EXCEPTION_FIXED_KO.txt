1. 판정
원인은 계약 불일치(해시 대상의 의미 불일치)다. 파일 손상이 아니다.
- scale 비교: 일치했다.
- code 비교: 어긋났다.
  - producer(causal_obq/replay.py:52·57)는 code_sha256을 packed nibble 텐서의 해시로 기록했다.
    식: tsha(packet['packed']), uint8 [3,612,672]
  - consumer(paired_response_stage0/diagnose.py:265)는 unpack한 int8 code의 해시와 비교한다.
    식: tsha(c.unpack(kp['packed'], kp['shape'])), int8 [3,98,16,12,128]
- 두 값은 같은 정보를 담지만 바이트열이 다르다. 따라서 해시는 항상 다르다.
- 이는 실자료 유효성 실패이며 연구 후보의 효과 실패가 아니다. 후보 점수는 계산되지 않았다.

허용된 단일 tensor 로드(정확히 1회, CPU thread 1, weights_only=True, map_location=cpu)
- 대상: causal_obq/packets/l18_c1_R_bf16.pt
  - 로드 전 파일 sha256 fb372d36…, 크기 4,517,694B. binding 기록과 일치했다.
- 관찰한 것:
  - 키는 {kind, packed, scale, sentinel, shape}, kind=K, shape=(3,98,16,12,128).
  - packed는 uint8 (3,612,672), stride (1), contiguous.
  - scale은 FP16 (3,98,1,12,128), stride (150528,1536,1536,128,1), contiguous. sentinel은 uint8 (1,).
  - tsha(scale) == 기대 scale_sha256: 구 tsha와 V4 tsha 모두 True.
  - tsha(packed) == 기대 code_sha256: 구·신 tsha 모두 True.
  - tsha(unpack(packed, shape)) == 기대 code_sha256: False. 이것이 diagnose.py:265의 실패 조건이다.
  - unpack을 다시 pack하면 원래 packed와 같다(True).
- 이 로드에서 하지 않은 것: attention/SSE/오차/점수 계산, 재양자화, 다른 파일 로드, 새 파일 출력.

추론(관찰을 넘어서는 부분):
- 파일은 무결하고(파일 hash, 두 텐서 hash, packed↔code 왕복이 모두 일치), V4 tsha의 stride 처리도 원인이 아니다(구·신 tsha 결과가 같음).
- 실패 원인은 consumer가 '같은 이름, 다른 해시 대상'을 가정한 데 있다.
- 한 패킷 밖으로의 일반화는 소스로 추론한 것이며, 다른 패킷은 관찰하지 않았다.

3. 이전 검사들이 놓친 이유
- 합성 완주(paired_response_stage0_synthetic_full)
  - build_inputs.py:42가 code_sha256을 d.tsha(c.unpack(kp['packed'], kp['shape']))로 만들었다.
  - 즉 합성 fixture가 producer가 아니라 consumer의 해석으로 anchor를 생성했다. 그래서 driver와 같은 가정을 공유하는 닫힌 고리가 되었고, 실제 producer 계약과의 차이는 원리적으로 검출될 수 없었다.
  - 합성 검사는 runtime 경로 완주의 증거로는 여전히 유효하다. 다만 외부 producer 계약의 증거는 아니다.
- 제 F4 검토
  - '실파일 내용(packet kind/shape 키 등)과 hash는 manifest에서 옮겨 적었고 대조하지 않음'을 미확인으로 남겼다. 이번 실패는 그 미확인 범위에 속한다.
  - 그러나 F4는 binding과 producer를 키 이름과 개수 수준으로만 비교했다. 해시 필드가 어떤 식으로 계산됐는지(replay.py:52·57)는 대조하지 않았다.
  - 따라서 이 결함은 F4가 적어 둔 위험 범주 안에 있었지만, F4가 구체적으로 찾지 못한 검토 누락이다. 이를 숨기지 않는다.
  - 소스만으로 발견할 수 있었다(replay.py 한 줄과 diagnose.py:265 한 줄의 대조).

4. 최소 수정 가능성 (제안만, 실행·결정은 root)
- 수정안(권고 1개): diagnose.py:265의 code anchor를 producer 계약에 맞춘다.

    - shape/kind는 packet_restore_checked가 이미 검사한다.
  - 팔, 입력, 기준, 허용오차, 원본 hash는 바꾸지 않는다.
- 함께 고쳐야 할 것:
  (a) 합성 fixture build_inputs.py:42를 producer 계약(tsha(packed))으로 바꿔야 회귀가 의미를 가진다.
      더 나은 방법은 실제 replay.py의 식과 같은 helper를 쓰는 것이다.
  (b) binding 또는 amendment에 "code_sha256 = sha256(packed uint8 nibble bytes, producer replay.py:52)"를 명시한다.
- 실행 전에 확인할 계약 목록(이번 실패와 같은 종류의 위험): binding의 모든 외부 해시 필드를 producer 계산식과 일대일로 대조한다.
