저비트 저장 코덱과 native attention 입력 사이의 연구 공백 — Codex 독립 소스 검토

판단: 현재 넓은 정의의 새 방법은 채택하지 않는다. 기존 준비값 캐시의 합성 속도 이득은 확보했지만, 직접 저비트→INT8 입력으로 연결한다는 발상이나 코드북 조회만으로 신규성을 뒷받침할 수 없다. 이 판단은 현재 후보와 조사 범위에 한정한다. 연구 전체 또는 이 분야의 모든 가능성을 종료하지 않는다.

우리가 가진 관측
- 기존 Sage1 구성요소의 정적 합성 K/V에서 반복 준비 제거로 호출 시간이 약 6~19% 감소했다. 준비비용 상각을 전제하며 실제 모델·영상·실행 간 반복성은 미측정이다. 이 결과는 QVG packed 코덱의 복원 시간이나 실제 생성의 절약률을 측정한 것이 아니다.
- QVG 복원값 유지의 과거 전체 생성 이득은 별도 설정에서 작아 종료됐다. 서로 다른 코덱·출력 표현·계측 범위의 수치를 연결해 그 후보를 재개하지 않는다.
- 실제 KV에 추가 INT8 반올림을 적용했을 때의 선택적 손상, GPU 메모리 제한 아래의 이득, fused 복원-변환의 실행 비용은 이번에 측정하지 않았다.

가장 가까운 기존 방법과 그 의미
1. HyperQuant §4.8/5.2/5.3은 압축 표현을 MMA 입력 형식으로 직접 디코드·캐스팅하는 경로를 명시한다. 따라서 BF16 임시 표현을 피하고 native 형식으로 읽는다는 설명만으로는 부족하다. 품질 평가의 pseudo-quant 경로와 실제 압축 실행을 구분해야 한다. 공개 구현의 완전한 재현성은 이번에 검증하지 않았다.
https://arxiv.org/html/2606.23406v1
2. 공식 vLLM Octave 문서와 pinned reference/format 소스는 3/4비트 코드→INT8 Lloyd-Max 값의 작은 LUT와 정수 QK 계산을 이미 연결한다. 이는 직접 코드북→정수 MMA라는 일반 주장에 강한 선행 구현이다. 현재 문서는 AMD 및 특정 D256/부분 RoPE 모델을 대상으로 하므로 RTX4090/우리 D128에서 실행 가능한 속도 기준선이라고 부르지 않는다. 하드웨어 이식만으로 새 알고리즘의 근거가 생기지 않는다.
https://docs.vllm.ai/en/v0.33.0/design/rocm_octave/
https://github.com/vllm-project/vllm/blob/00b6c4c565a8732c131e1f452d4a17803bb0842b/csrc/attention/octave_format.cuh
3. CommVQ §4.2는 RoPE와 가환하는 코드북 및 attention 식 재배열을 이미 제안한다. 일반적인 pre-RoPE 복원 비용 제거도 새 질문이 아니다. 읽은 Triton wrapper에는 squeeze(2), B*8 KV head, H_RATIO=4 등 특정 decode 형상 계약이 있어 Q4680 영상 경로의 직접 실행이나 성능은 확인되지 않았다. 이러한 지원 차이가 문제의 중요성이나 신규성을 입증하지는 않는다.
https://arxiv.org/html/2506.18879v1
https://github.com/UMass-Embodied-AGI/CommVQ/blob/d1f0377429b30ff8933fd0debcbc9c0d4efd06a3/commvq/triton_kernels.py
4. NoMAD-Attention §3은 PQ 코드의 query-dependent lookup으로 QK를 계산한다. 속도 평가는 CPU 대상이다. GPU의 큰 Q 형상에서 그대로 유리하다고 일반화할 수 없지만, decode 없이 lookup한다는 넓은 신규성 주장은 이미 차단한다.
https://proceedings.neurips.cc/paper_files/paper/2024/file/ccda3c632cc8590ee60ca5ba226a4c30-Paper-Conference.pdf

로컬 소스에서 확인한 조건
- QVG prq.py는 토큰의 전체 D 벡터를 군집화한 centroid와, 블록 scale을 가진 저비트 최종 잔차를 합쳐 복원한다. 이 읽은 구현을 임의의 product-quantization 부분공간 코드북과 같다고 가정하지 않는다.
- functions.py/uncompress.py는 centroids, cluster ids, packed residual, scales, 선택적 clipping 정보를 읽어 지정 dtype으로 복원한다. 호출부의 출력 dtype/원래 반올림을 생략한 직접 INT8 변환은 동일 연산이라는 보장이 없다.
- 읽은 RoPE 커널은 각 위치의 cos/sin을 FP32로 곱하고 합친다. 임의 centroid를 한번 INT8로 바꾸는 것만으로 post-RoPE 토큰별 native 입력이 완성되지 않는다. 이는 source 계약상의 추가 단계이며 불가능성 증명은 아니다. 디코드+RoPE+quantize의 일반적 융합이나 절대위치 유지라는 단순 구현이 먼저 기준선이다.

강한 단순 기준선
A. 원 packed 코덱을 그대로 복원하고 원 RoPE/mean/scale 계약을 적용한 뒤, 기존 INT8 QK 입력으로 변환한다. 모든 전처리·workspace·읽기·최초 준비 비용과 실제 resident bytes를 포함한다.
B. 같은 변환 결과를 불변인 과거 청크마다 한번 준비한다. 추가 메모리를 실제로 계상하고 원 창/퇴거/현재 청크 처리를 일치시킨다. 이는 기존 캐싱 기준선이다.
C. 기존 integer-LUT/회전/scale 구성을 적용한 직접 소비 방식은 강한 문헌 기준이다. 현재 장비에서 실행 가능한 구현을 확보하기 전에는 수치/시간을 가정하지 않는다.
원본 BF16 attention, 저장 코덱만 적용한 attention, 저장 코덱 뒤 INT8로 변환한 attention은 목적이 다르다. 같은 바이트 수라는 이유로 출력 손상과 native 실행 비용을 분리하지 않은 비교를 만들지 않는다.

다음 자원 판단
현재 이 넓은 후보를 근거로 새 GPU 커널, 새 양자화기, 전체 영상 생성을 시작하지 않는다. 필요한 것은 구체적 후보가 어떤 기존 선택을 어느 입력에서 개선할지의 예측이다. 저비트→INT8 일반 융합을 새 방법으로 개발하는 안은 제외한다. Claude 독립안이 같은 바이트·같은 실제 attention 연산에서 기존 단순 기준선으로 해결되지 않는 구체적인 실패 조건을 제시하면 그 한 조건만 별도 등록한다. 그렇지 않으면 이번 source-only 조사를 종료하며 같은 검색을 이름만 바꿔 반복하지 않는다.
재개 가능한 가장 싼 검사는 위 조건이 먼저 특정된 경우, 이미 보존된 개발 Q/K/V의 동일 입력에서 원 BF16/저장복원/저장복원+native 형식의 출력 차이와 실제 bytes를 분리하는 CPU 검사다. 기존에 없던 효과나 새 방법의 성공을 보장하는 검사가 아니며 현재 등록의 모델·텐서 로드 0 제한 때문에 실행하지 않았다. 실제 KV 수치와 codec→native 단계의 손상은 관측 전까지 가설이다.

수행 범위와 한계
원문 관련 절: HyperQuant, CommVQ, NoMAD 및 공식 Octave 문서. 코드 고유 8개: QVG prq/functions/uncompress/rope(관련 절), pinned Octave reference/format, CommVQ compress_triton(앞 220행)/triton_kernels. READ_CODE_INDEX_CODEX.json에 SHA와 읽은 범위를 남겼다. 웹 검색 결과 전체를 읽은 것으로 세지 않는다. source fetch는 연구 소스만이며 모델·가중치·데이터·텐서 로드/torch import/GPU/설치/컴파일/실험/추가 에이전트 생성은 모두 0회다. Codex quota 실패 후 부모가 직접 수행했고 다른 계정/모델로 재시도하지 않았다. Claude의 새 결론은 읽지 않은 상태에서 이 보고서를 먼저 고정한다.
