3. 구체 반례/위험
 R1 in-place 후처리: out_에 clamp_/mul_ 등 in-place를 쓰면 out_이 cache와 storage를 공유할 경우 다음 프레임을 오염. 현재 source상 alias는 없지만 계약으로
    "decoder 출력에 in-place 금지 또는 out_ storage가 feat_cache storages에 없음을 data_ptr로 assert".
 R2 첫 프레임: i=0만 T=1이고 Resample upsample3d는 첫 호출에 'Rep' 문자열을 cache에 넣는다(107). state 관찰 시 문자열 항목은 tensor 수에서 제외하고 별도 count.
 R3 cuDNN 알고리즘 선택: benchmark off·deterministic on이어도 휴리스틱이 가용 workspace에 따라 다른 알고리즘을 고를 수 있다(PyTorch 휴리스틱 경로; 이번에
    확인 안 함). streaming은 여유 메모리를 늘리므로, 바이트 불일치가 나면 구현 오류와 알고리즘 차이를 구분할 수 없다. gate 완화는 하지 않되,
    불일치 시 "구현 무효" 판정과 함께 이 교란 가능성을 기록한다. 가능하면 두 팔에서 CUDA/cuDNN 버전과 deterministic 설정을 기록.
 R4 팔 순서: reference 팔(누적 cat+GPU float)이 먼저면 allocator 단편화가 다음 팔 peak에 영향. 팔마다 fresh 모델·이전 팔 텐서 해제 후 reset_peak.
    단일 순서이므로 peak/시간은 서술용(ROOT_SPEC과 동일).
 R5 CPU 비교 메모리: reference 전체 FP32 2.4GB + stream 전체 2.4GB = 약 4.8GB CPU(12GiB 안). reference를 permute 후 .cpu()로 옮기면 비연속 텐서가 되고,
    전체 .contiguous()는 2.4GB 추가 사본. 프레임별로 contiguous 비교해 전체 추가 사본을 피할 것.
 R6 state 관찰의 섭동: first(i=0 후)/steady(i=64)/last(i=125 후, clear 전)에서 feat_cache 텐서의 untyped_storage data_ptr로 unique 저장소 수·nbytes만 합산.
    .to()/.contiguous()/.clone() 등 GPU 연산 추가 금지. 관찰 후 다시 decode에 영향 없음을 보장하려면 관찰 코드를 읽기 전용 메타데이터로 제한.

    재구성. 두 팔이 같은 재구성 코드를 쓰면 비교가 무의미해진다.
 R8 latent 동일: 같은 latent 파일 sha, BF16 dtype, 두 팔 입력 tensor 바이트 동일 assert.
