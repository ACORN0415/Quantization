BF16 출력 스트리밍: 저장 기록 독립 감사
작성: /root/fair_comparison_codex, 2026-11-05 UTC

판정
저장 기록 감사 1,767개 조건을 모두 통과했다. 원 실행은 root의 exit0/완료 기록과 worker의 completed_exact_streaming_baseline이 일치하며, 등록된 출력 동일성·호출·자원 조건을 만족한다. 이 결과는 동일 출력의 BF16 실행 기준선 확보를 지지한다. 새 손실 압축 방법, 품질 개선 또는 반복 측정한 속도 향상 결과는 아니다.

실행과 감사의 구분
원 worker는 실제 501프레임에서 shape/dtype와 전체 logical element byte를 비교했다. 본 감사는 실제 RGB를 보관하지 않은 조건에서 그 비교 기록 501행, 각 팔의 frame_sha256 501개, 행별 두 해시의 일치를 재확인했다. 프레임 번호는 정확히 0..500이며 모든 byte-equality 기록이 참이다. 본 감사가 501 RGB 원소를 다시 계산하거나 독립 재비교한 것은 아니다.

검증 코드 verify_result.py는 worker를 import/실행하지 않고 표준 라이브러리로 JSON·AST·파일 스트리밍 SHA만 처리했다. 모델·latent·가중치·RGB 텐서를 로드하지 않았고 GPU·추가 VAE·새 생성·재실행은 모두 0회다. 새 감사는 원 실험 종료 후 1회 실행했다. helper stream_audit_contract는 worker/명세의 기록 계약을 읽기 전용으로 독립 대조했으며 GPU·텐서·결과 재계산을 수행하지 않았다.

독립 확인 항목
1. LOCK SHA 4251016b7d044491fc031c5800fbe13cc40265ccdb76f3e4ec2460464ea6e2f5가 고정값과 일치했다. 사전 source commit b89ad1d1f3f7f1c4ac50ee64ca7e24683d61d9f1 기록과 단일 attempt=1을 확인했다. RUN의 exclusive-create 소스와 root/worker 시계 포함관계를 대조했다.
2. LOCK에 묶인 소스·검토·합성·입력 25개 경로, 합계 532,911,707B를 경로 중복 제거 후 스트리밍 해시했다. 모두 일치했다. latent/checkpoint는 역직렬화하지 않았다. RESULT/RUN/LOCK/root 시작·최종 기록은 감사 전후 같은 SHA였다.
3. 원 decode AST와 wrapper AST 해시를 독립 추출했다. 허용된 출력 누적→emit/delete 및 return None 변환만 별도로 구성한 AST 해시도 원 실행 기록과 일치했다. worker 소스 변경이나 실행은 하지 않았다.
4. 각 팔의 full conv2 입력·출력 [1,16,126,60,104] 한 건과 decoder.forward 126건을 검증했다. 첫 decoder 출력 T=1, 나머지 125건 T=4이므로 총 501프레임이며 두 팔 합계 252회다. 시작 clear 0→0, 종료 clear 32→0 및 전체 trace가 두 팔에서 같다.
5. fresh checkpoint, TF32/autocast/benchmark false, deterministic true 기록을 확인했다. 이 항목들은 해시 고정 소스와 원 실행의 검사 기록을 대조한 것이며 새 모델을 로드해 다시 확인한 것은 아니다. generator_calls=0 역시 호출 hook이 아니라 실행 소스에 생성 경로가 없다는 근거와 기록된 상수다.

저장 수치의 독립 산술
GPU allocated peak:
  native_BF16 5,727,909,376B = 5.334531307GiB
  stream_BF16 4,527,433,216B = 4.216500759GiB
  차이 1,200,476,160B = 1.118030548GiB, native 대비 20.9583651% 감소

GPU reserved peak는 각각 13.48828125GiB와 6.01171875GiB로 별도 기록했다. 등록 상한은 allocated 22GiB이며 reserved를 동일 지표로 바꾸지 않았다. 이 두 peak는 각각 모델 로드/H2D/복원/RGB 처리/CPU emit을 포함한다. 두 팔 전환 시 allocated=0 확인 후 통계를 reset하는 소스와 완료 기록을 대조했다. 감사자가 GPU 상태를 직접 검사한 것은 아니다.

decode + emit + validation 시간:
  native_BF16 30.959407810초
  stream_BF16 30.374860536초
  기록된 구간의 차이는 약 0.584547274초, 감소율 1.8881087%
  setup은 각각 0.637505392초와 0.484124623초로 별도다.

순서는 native→stream 고정이며 각 1회다. hook·hash·D2H 등이 포함되고 stream에는 CPU byte 비교가 더 포함된다. 그러므로 위 시간 차이는 기술값이며 생산 환경의 순수 decode 지연, 통계적 가속 또는 Pareto 개선으로 해석하지 않는다. peak 차이도 모든 크기를 개별 버퍼의 제거량으로 분해한 결과는 아니다.

feature state:
  decoder index0: 30 tensors, logical 합 920,325,120B
  index64/125: 32 tensors, logical 합 각각 1,888,573,440B
  두 팔에서 같으며, entries의 shape×BF16 2B를 합산해 logical bytes를 독립 재계산했다.

주의: storage_group별 실제 nbytes 목록은 JSON에 없다. 따라서 unique_storage_bytes의 같은 수치는 원 실행에서 storage.nbytes를 수집한 기록 및 두 팔 일치로 확인한 것이다. 이를 일반적으로 entries의 logical 크기만으로 독립 재구성했다고 말할 수 없다. unique storage와 logical bytes가 이번 기록에서 수치상 같다는 사실도 이 한계를 없애지 않는다. feature state 크기를 GPU peak의 동시 구성비나 제거 가능한 peak 상한으로 사용하지 않는다.

시간·자원·종료
ROOT_EXECUTION_FINAL은 completed/exit0, root 저장 wall 64.757701635초다. 저장 start/finish 차이는 64.757778883초이며 약 0.077ms의 기록 차이로, 모두 600초 안이다. worker 구간은 64.250622749초이고 root 구간에 포함된다. 자동 재시도나 추가 팔은 없다.
실험 RSS는 monitor 4,298,276,864B, getrusage 4,294,295,552B로 두 값 모두 12GiB 안이다. 약 3.98MB 차이는 서로 다른 수집 방식의 기록 차이이며 결과 실패로 해석하지 않았다. 원 monitor disk peak 409,359B는 256MiB 안이다. WATCHDOG_FAILURE/FAILURE 파일이 없고 watchdog_completed_cleanly=true, 최종 source/input 재해시 성공, root exit0을 확인했다.
watchdog 및 팔별 GPU 해제는 원 worker의 assert/종료 기록을 감사한 것이다. 본 감사가 외부 프로세스나 GPU 유휴를 새로 검사한 것은 아니며, root의 별도 유휴 확인을 독립 감사 결과로 소급 집계하지 않는다.

본 CPU 감사 자체: 0.226410627초, 기록된 process RSS peak 693,440,512B로 2GiB 이하. 감사 준비·소스 독해를 포함해 배정 15분 안에 마무리했다. 출력은 소규모 JSON/텍스트이며 원 결과·LOCK·worker·기준을 수정하지 않았다.

최종 범위
이 실험은 시험한 한 latent·모델·환경에서 정확 출력 스트리밍 기준선을 확보했다. 상태 양자화의 안전성·유용성이나 새 방법의 신규성을 입증하지 않는다. 실제 Opus의 설계·소스 검토와 별도로 수행한 사후 저장 기록 감사이며, 그 과거 검토 범위를 확대해서 표시하지 않는다.
