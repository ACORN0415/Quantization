미리 해결해야 할 경계 조건
1. 직사각형 Q/K길이를host forward에서각각사용하므로noncausal Q4680,K4680/18720/32760/56160은소스차원상정의된다. head128/H12/B1은해당기본타일128x64와맞는다. GPU메모리/성능이나모든입력정확성을보장하는말은아니다.
2. quantkernel과attention K/V load가일부masked-load에other를주지않는다. Triton load문서는other=None일때masked값을undefined로정의한다. 이소스계약만으로실제NaN/오류발생을단정하지않지만4680등비정렬tail을무조건안전하다고도하지않는다.
   다음별도probe가필요하면source를고치기보다입력을Q128/K64배수로0pad하고유효K booleanmask를broadcastview로전달하는명시적adapter를먼저정의한다. 전체QxK mask를물리화하지않고,평균은유효K에서만산출하고,출력은유효Q로crop한다. 이pad+mask는아직구현·수치검사되지않았다.
3. per_block_int8는Qscale에sm_scale*log2(e)를접고Kscale에는1을쓴다. attention은exp2를사용한다. 원core의이scale계약과V를FP16으로준비하는경로를그대로유지해야한다. BF16V와FP16P를혼합dot하게내버려두지않는다. preparedK비교에서도동일centeredK/padding/code/scale/V를사용해야한다.
4. one stable KV fixture를여러Q가읽는prepared입력과전체준비를포함한호출을같은format으로비교해야한다. QVG INT2 PRQ와Sage INT8을같은코덱으로취급하지않는다. 이전복원값유지후보와다른기존baseline에대한비용학습이며새방법주장이아니다.

제안되는 후속 한 번(아직권한없음)
먼저작은불규칙형상에서수학검사를통과시키고,그뒤네큰형상의FA2/구형Sage전체준비/동일K사전준비경로의whole-callwall/CUDAevent/준비비용/최대메모리를분리한다. 작은검사는같은INT8code복원참조와native연산을비교하고,두Sage경로의codes/scales·출력원소bytes가같아야한다. BF16 FA2와저정밀출력차이는서술이며영상품질gate가아니다. 큰형상에서는같은Qfixture를교차순서반복측정하며최초JIT시간을따로기록한다. 실제native TensorCore사용은실행trace/compiled code 확인전단정하지않는다.
