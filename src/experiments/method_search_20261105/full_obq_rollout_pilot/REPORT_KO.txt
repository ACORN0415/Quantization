작성: Codex 업무2 / 2026-11-05. 최종 실제 Claude(Opus 5.5) 검토는 아직 미완료.

판정: 등록한 stop_quality. 유효한 8개 생성과 8개 영상 복원·평가를 완료했으나, 두 입력 모두에서 두 RTN을 넘는다는 사전 기준을 충족하지 못했다. rain_market에서 R_bf16 대비 MUSIQ가 2.179109점 감소하여 등록한 -2점 중단 조건을 만족했다. Q1도 rain_market의 두 비교에서 10%에 미달했다. 기준·코드·입력·상한은 결과를 보고 변경하지 않았다.

1. 고정한 검사와 실행
Self-Forcing 1.3B, RTX 4090 24GB, 30층×12head×128차원, 청크당 4 denoise+1 refresh. 각 입력 42청크/126 latent frame/501 pixel frame. 입력은 coast_cycle(seed409), rain_market(seed503) 두 개이며 PROMPTS.json의 정확한 문장을 사용했다. 개발 후 처음 시험하는 두 입력일 뿐 미학습 데이터·통계적 독립 표본 모집단이라고 주장하지 않는다.
팔: BF16 참조, R_bf16(회전 INT4 K의 BF16 나눗셈/반올림), R_fp32(같은 그리드·scale의 FP32 나눗셈/반올림), O_full_gpu(같은 그리드·scale의 full-H 순차 오차 보상). V는 공통 packed INT4, 현재/직전 pending은 BF16. 완료 청크는 한 번 encode하고, 6개 과거 청크를 유지한다. 1560-frame 그룹·g16·Hadamard·FP16 scale 저장은 고정했다.
H는 사전에 고정한 p00_s101의 30층 query에서 만든 오프라인 통계다. 새로운 두 입력의 미래 query나 출력 점수를 사용하지 않았다. GPU encoder는 검토된 layoutfix api.gpu_frames 및 원래 fused T_code 구현을 재사용했으며, 매 실제 encode에서 finite/positive scale 계약을 확인했다. fallback이나 clamp 정책 변경은 없다.

3. 설명용 관측과 한계
coast_cycle에서는 full-H가 후반 NSE를 36–60% 줄이고 DINO도 높였다. 그러나 초반 청크1–7과 중간8–20의 NSE는 R_fp32보다 각각 조금 컸다. 따라서 모든 시점·모든 척도의 단조 개선으로 표현하지 않는다.
rain_market에서는 full-H의 후반 NSE와 DINO가 두 RTN보다 개선됐지만, R_bf16이 더 높은 MUSIQ를 얻었다. BF16 자체의 MUSIQ도 64.217548로 압축 팔보다 낮았다. 이는 이 자료에서 참조 궤적 충실도와 무참조 품질 점수가 같은 순위를 보장하지 않는다는 관측이며, 어느 한 지표를 사후 폐기할 근거가 아니다.
두 입력·각 1seed이며 설정별 생성 타이밍도 1회다. 프레임 수를 독립 표본 수처럼 세지 않고 신뢰구간·통계적 유의성을 주장하지 않는다. 현재 자료는 이번 자원 배분 결정에 대한 pilot 근거다. 신규성 및 action-conditioned world-model 성능은 검증하지 않았다.

4. 비용·메모리·같은 바이트의 범위

5. 실행 증거와 사후 감사의 범위
8생성 ×210 =1,680 model forward. 압축6생성 ×30층 ×41 encode_pair =7,380회. BF16 2생성의 encode 호출은 0. 8 VAE decode가 모두 유효 완료했다. 각 압축 팔에서 reader 청크1..41/층0..29의 실제 로그 순서, source_chunk=reader_chunk-1, 층별 누적호출41, payload 산술을 다시 확인했다.
실행 전 integration 6사례는 원래 GPU 전처리의 CPU 참조 code 정확 일치, V CPU packet 및 GPU reader 일치, packet ownership/lifetime 검사를 통과했다. 전체 rollout의 packet을 전부 저장한 것은 아니므로 전체 생성 중 모든 packet byte를 사후 직접 재검증했다고 쓰지 않는다.
사후 감사 AUDIT_FINAL_CODEX.json: 709검사 통과, 249개 보호 파일의 hash 및 읽기 전후 보존 확인, 오류0/누락0, GPU호출0, 22.427836초. 이 사후 CPU 감사는 본 실험 종료 후 별도 수행했다.
실제 저장 latent 8개에서 첫3 latent frame의 원소 바이트 일치, 유한성, 후반·전체·3개 설명용 창의 NSE를 재계산했다. 42개 초기 noise chunk hash는 입력별 네 팔이 같음을 확인했으나 noise tensor를 다시 생성하지 않았다. 저장된 DINO feature에서 프레임별 cosine을 다시 계산했고, MUSIQ는 저장 점수의 평균·판정을 재계산했다. MUSIQ 네트워크나 raw RGB 프레임 metric 자체를 재실행하지 않았다.
모든 모델/설정/metric/source hash를 실제 worker의 시작·종료 검사와 사후 audit에서 확인했다. 사후 audit은 원래 결과·LOCK·코드를 변경하지 않는 읽기 전용 경로이며 새 이름으로 독립 결과를 저장했다. combined gate의 독립 계산도 stop_quality로 일치했다.

6. 다음 판단
이번 full-H 전체 생성 pilot의 성공을 선언하거나 같은 범위에서 seed/팔/지표를 더 붙이지 않는다. 부분 attention 오차의 개선이 긴 생성에서 모든 등록 기준을 충족시키지 못했다는 결과를 보존한다. 다음 한 단계는 21:50 이후 실제 Opus 5.5가 등록 명세·코드·결과·본 감사를 검토하는 것이다. 그 검토와 기존 근거를 바탕으로 별도의 후보 선택을 해야 하며, 이 보고가 자동으로 기존 실패 기준을 무효화하지 않는다.
