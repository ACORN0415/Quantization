Full-H packed KV 전체 생성 파일럿 등록 초안 — 2026-11-05
상태: 계획·코드 검토 범위만 준비. GPU 실행0, 새 생성0, 코드 구현/LOCK 이전. 아래 지표·입력은 결과 전에 제안하며 root/Fable 검토 뒤 잠근다.

1. 질문과 실행 전제
부분 attention 출력에서 확인한 fixed offline full-H 효과가, 같은 실제 저장량의 회전 RTN보다 새로운 입력의 전체 생성 궤적을 BF16 참조에 가깝게 유지하는가? 외관 품질을 해치지 않으면서 얻는 이득인가?
obq_gpu_encoder_stage2가 정확한 code·owned packet 수명·native BF16 참조 및4 endpoint 양RTN 대비20% 감소 gate를 통과하고, fused/Graph 비용에 대한 root/Fable 판단이 완료된 경우에만 실행 검토한다. 그 결과가 미달이면 본 파일럿을 시작하지 않는다.
stage2 확정본의 GPU frames, 고정 OBQ kernel, owned packet 계약, restore_gpu를 해시로 잠가 재사용한다. 여기서 full-H 양자화·CUDA kernel을 별도로 재구현하거나 설정을 고르지 않는다. 아직 stage2 확정 해시/라이브러리는 대기 상태이며, 검토 통과 전 임의 값으로 채우지 않는다.
회전 INT4가 기존 MUSIQ에서 BF16에 가까웠으므로 MUSIQ 우위를 자동 기대하지 않는다. 본 파일럿은 다음 자원 배분을 위한 두 입력 검사이며 새 방법의 신규성·확증 성공·독립 통계적 유의성을 입증하지 않는다.

3. 네 팔과 통제
각 입력에 BF16, R_bf16, R_fp32, O_full_gpu 네 팔, 총8세대(각42청크=126 latent frame=501 pixel frame)로 고정한다.
BF16: 원래 bf16_cache 경로. 나머지3팔: ChunkStore/동일 native attention, pending와현재 BF16, residual_tokens0, sink0, local21 latent frames(현재3+과거18;최대6완료청크), once encoding/동일퇴거순서.
모든압축팔의K는동일nativeGPU FP32 Hadamard→BF16→frame1560별8padding→g16 BF16 absmax/7→FP16scale다. R_bf16은BF16나눗셈round, R_fp32는동일scale FP32 round, O_full_gpu는고정full-H factor와검증된fused kernel이다. INT4 actual uint8 nibble packing,모든head4bit,head boost없음. V는동일chunk전체g16 BF16 RTN+actualpacking,현재K/V는BF16. Q 회전·attention kernel 변경없음.
stage2와같은TF32 off/FP32 matmul highest설정을BF16참조를포함한모든팔에공통으로적용하고고정한다. 팔마다산술전역설정을달리하지않는다.
K 청크4515841B, V 청크4500480B. 한층과거6청크54097926B;30층1622937780B. 이는fixed factor·현재/상호attention cache·decoder workspace를포함한전체peak가아니다. FULL factor30층 FP32 23592960B는encoder공유상태로별도보고한다. 각구간의같은payload를실제tensor numel×element_size로검사한다.
입력1실행순서BF16→R_bf16→R_fp32→O_full_gpu;입력2BF16→O_full_gpu→R_fp32→R_bf16. 캐시·cross-cache·noise·generator seed는매팔초기화하고같은prompt의noise는같아야한다. 팔별1회뿐이므로생성시간작은차이를통계적속도우위로주장하지않는다.

4. 보정원과 비용
p00_s101/l00_c7.pt..l29_c7.pt의동일call0 query만고정사용한다. manifest에30개모두존재하며총7042655940B다(층0..9는두자리파일명). 효과를보고층/damping/통계원을선택하지않는다.

IO/원본hash시간, H+factor계산시간, 저장시간, GPU전송시간을각각기록하고총보정시간도보고한다. 이준비는60분본실행상한에포함한다. 고정U를각layer encoder에한번전달하고, encode중평가Q나미래청크를사용하지않는다.

5. 주 지표와 권고 gate
Latent 주지표: 후반chunk21..41, 즉latent index63..125 전체의BF16참조NSE = sum((latent_arm-latent_BF16)^2)/sum(latent_BF16^2),FP64누적. chunk별비율을평균하는대신분자/분모를합산한다. 같은입력의두RTN각각에대해 gain=1-NSE_FULL/NSE_RTN. 분모0/비유한은판단불가(비유한출력은실행무효). 이는BF16궤적충실도의대리지표이며영상품질이나정답과동일시하지않는다.
영상 지표: 전체latent를각팔한번VAE decode해raw RGB8을만들고,MP4인코딩전동일프레임501개에서기존MUSIQ와DINO특징을계산한다. 주창pixel249..500은latent후반과같은구간이다. BF16참조와동일index DINO cosine을사용하며인접프레임DINO는보조설명만한다.
계속할 signal 권고(두새입력과두RTN에동시에적용):
 Q1. 후반latent NSE를각입력에서각RTN대비10%이상감소.
 Q2. 후반DINO_reference의각입력차이가각RTN대비 -0.005 이상이고,두입력평균차이가각RTN대비0 이상.
 Q3. 후반MUSIQ의각입력차이가각RTN대비 -1.0점 이상이고,두입력평균차이가각RTN대비 -0.5점 이상.
이마진들은검정으로입증한비열등한계가아니라사전작은투자판별규칙이다. 10% latent 감소는RTN과의명확한궤적차이를요구하고,DINO는BF16의내용/구도보존에대한보조확인,MUSIQ는참조에가까워지더라도외관이손상되는상황을거르는역할이다. BF16궤적이가장좋은영상이라는가정은하지않는다. MUSIQ 단독개선이나latent만의개선으로성공이라하지않는다.
Q1∧Q2∧Q3일때만더큰검토의진행신호다. 한입력이라도FULL의NSE가어느RTN대비10%이상증가,또는DINO차이<-0.02,또는MUSIQ차이<-2이면품질방향중단권고. 나머지미달은판단불가다. 불리한입력/팔/프레임을빼거나지표를바꾸지않는다. invalid/incomplete는유효한음성결과와분리한다.
