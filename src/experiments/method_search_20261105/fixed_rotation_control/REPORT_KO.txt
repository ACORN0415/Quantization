고정 부분 회전+RTN 대조 — 실행 결과, root 2026-11-05

기술적 판정: 등록한 국소 대조 기준 통과. 여섯 CPU endpoint 모두에서 FULL 보상은 p0로 고정한17변환 가족의 RTN보다 post-Wo SSE가10% 이상 작았다. 이것은 전체 생성 pilot의 stop_quality를 취소하지 않으며, 새로운 방법이나 공식 FlagRot 전체를 이겼다는 결과가 아니다. 실제 Claude 최종 소스/결과 검토는 미완료다.

검사
층18/24별로 p0의 query와 과거6청크 K만 사용해 I/H32 네 블록의16조합 및 H128을 전수 점수화하고 head별 회전을 고정했다. 선택 점수는 실제 BF16 복원 오차의 raw query second-moment 가중 제곱합이다. p4와 기존 causal 입력에서 재선택하지 않았다. 평가는 같은 CPU FP32 attention/FP64 제곱합이며 BF16 현재청크/V4/프레임별g16/scale정책을 맞췄다. 이 자료는 모두 이미 개발에 쓰였고 독립 신규 보류 검증이 아니다.

유효성/자원
실행 전23개 파일을 잠그고 실행 전후 해시를 검증했다. K·V stored FP16 scale 계약, 실제 nibble 패킹 왕복, p4의 기존 code/scale/SSE anchor, causal 기존 packet equality와 입력 보존이 실행 중 통과했다. 선택 회전의 무개입 BF16 roundtrip 영향은 RTN_FP32 SSE의0.00955~0.02034%로 등록1% 이하 기준을 통과했다.
모든 팔의6청크 KV payload는54,097,926B다. fixed R은 층당786,432B와 label12B, FULL U는 층당786,432B와 공유H12865,536B를 별도 상태로 보고한다. 같은 KV payload를 같은 총상주 메모리라고 표현하지 않는다. 보존용 state 파일은 R/U를 함께 담으므로 한 방법의 운영 메모리가 아니다.
supervisor81.706634초, worker81.542565초, peakRSS2.390659GiB, CPU4, GPU0, 새모델생성0. 보정 계산은 층18 약18.965초, 층24 약19.265초이며 파일 load/validation은 별도 결과 필드다. CPU 전체6청크 encode/복원 시간은 GPU 쓰기 지연이나 생성 가속으로 바꿔 읽지 않는다.

판단과 다음 자원
이번에 남은 사실은 '시험한 작은 고정 회전 가족으로 FULL의 국소 이득을 대체하지 못했다'다. 알고리즘은 여전히 알려진 GPTQ 적용이며, 전체 생성에서는 등록 기준 실패가 이미 관측됐다. 현재 FULL 구현의 seed/팔을 늘리지 않는다.
이후 paired 응답 보정 등 별도 후보를 검사한다면 강한 비교 대상에 FULL도 포함해야 한다. 같은 추가 메모리 내에서 비트 증가·PSAC·QKSA와 함께 비교하고, 현재 파일럿의 실패를 새 후보 성공의 근거로 삼지 않는다.
