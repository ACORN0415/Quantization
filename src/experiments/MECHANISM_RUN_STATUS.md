# 메커니즘 실행과 확인 방법

사용자 실행 지시 후 2026-10-29에 개발 게이트/재생 파이프라인을 시작했다.
계획 문서의 “미실행 초안” 문구는 실행 전 고정한 문서의 상태이며 현재 작업 상태가 아니다.
현재 단계와 완료 수의 원본은 `${HOME}/sfq_data/mechanism/status.json`이다.

```bash
bash ~/Quantization/tools/watch_progress.sh
tail -F ~/sfq_data/mechanism.log
```

파이프라인은 전체 모델 게이트 → 네 기존 사례의 60개 층/그룹 묶음 재생 → 고정 GO 판단으로 이어진다.
NO-GO면 진단을 정리해 종료한다. GO면 계측 ON/OFF 검증, 성능 측정, raw 평가 게이트를 거친다.
새 보류 프롬프트는 최종 등록 봉인을 커밋·푸시한 뒤에만 사용한다. 최종 분석과 결과 커밋·푸시도 자동 단계다.

초기 구현 실행에서 영역별 오차 기록 누락을 찾아 예비 실행을 중단했다.
그 예비 게이트·일부 재생·로그는 `mechanism_implementation_probe_1639af6`에 보존했다.
진행 조건/프롬프트/임계값은 바꾸지 않았고, 영역 계측을 완성한 소스로 게이트부터 다시 시작했다.
`launch.json`은 재시작 당시 코드와 source hash를 기록한다. 예비 실행을 네 사례의 최종 판단에 섞지 않는다.

query probe는 현재 관찰 경로에서 query를 제공하지 않아 미검사로 표시한다.
실제로 측정하지 않은 항목을 완료했다고 보고하지 않는다. 진단 시간은 실제 추론 속도가 아니다.
후속 지표는 원본 RGB에서 계산하며 심한 손상 영상의 flow 신뢰성과 DINO의 주체 추적 한계는 그대로다.

이미 완료된 80개 연구와 260개 사후 평가 데이터·보고서는 이 실행과 별도로 보존한다.
