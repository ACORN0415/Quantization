# rounding 탐색 품질의 마지막 개발 진단

2026-10-29. 사용자가 공통 후보군·작은 전수 검사를 승인했다. 이전 post-W_O NO-GO 결과는 유지하고 **기존 자료의 별도 탐색 진단**으로 수행한다. 이미 본 개발 p0/p4·seed101·층0/14/29를 사용하며 보류 검증·새 방법·영상 품질 결과로 부르지 않는다.

## 입력과 첫 게이트

기존 postwo_rounding의 청크6 refresh Q(선택), 청크7 첫 denoise Q(평가), 청크0..6 BF16 K, 새 청크6 V, W_O를 사용한다. 입력 캡처12개·기존코드24개·탐색24개의 SHA를 확인한다. 새 모델 생성은 없다. K16/V4·g16·FP16 scale·새 V만의 추가 출력 오차·반사실적 삭제·FP32 직접 metric 범위는 기존 계획과 같다. 과거 원본 V 오차는 넣지 않는다.

기존 세 탐색기의 32회 연산을 새 trace 도구로 재현한다. 각 셀·팔의 최종 코드와 training history가 과거 기록과 같아야 한다. 다르면 구현/재현 실패로 중단하고 새로운 과학 결과를 해석하지 않는다. 기존 수치 소스는 수정하지 않는다.

## A. 공통 후보군

RTN 1개와 세 탐색기 각각의 32개 hard 후보를 합친 **97개 슬롯/셀**을 만든다. 중복도 유지하고 고유 코드 해시 수를 공개한다. 두 선택자는 이 같은 목록에서 각각 현재 query의 full post-W_O D와 D+J를 최소화한다. 동률은 최초 슬롯이다. 평가 query는 이 선택 뒤에 선택된 코드의 평가에만 사용한다. 모든 후보를 다음 query 성능으로 골라서는 안 된다.

6셀×97=582개 training 후보 행, 6셀×2선택자=12개 평가 선택 행. 모든 후보를 대형 텐서로 저장하지 않고 metric·코드 해시·선택된 코드만 남긴다. 기록된 후보 순서·선택·예산을 재검토할 수 있어야 한다.

## B. 선택한 16개 scalar 코드의 전수 검사

나머지는 RTN으로 고정하고 16개 값만 그 값의 floor/ceil 이웃 중 고른다. **현재 query의 D에서 단일 코드를 뒤집었을 때의 정확한 이차식 개선량**이 큰 16개를 선택한다. floor=ceil/padding은 제외한다. 동률은 원래 `[token,head,channel]` flatten index가 작은 순서다. 이 블록은 평균 목표로 골랐으므로 전환 목표에 최적인 블록이라고 부르지 않는다. 미래 query를 좌표 선택에 사용하지 않는다.

공통 FP32 입력 A/W/원본 V/RTN 복원값을 FP64로 올린 선형 attention 모형에서 D/J 이차식을 만들고 **2^16=65,536개 조합 전체**를 계산한다. 전수 검사 이웃의 floor/ceil도 저장 scale과 원본 V를 FP64로 올린 나눗셈으로 정의하며, 기존 FP32 탐색의 근접 정수 경계와 수치적으로 다를 가능성을 숨기지 않는다. 실제 RTN이 이 두 이웃 중 하나인지 검사한다. bit0은 RTN 값, bit1은 해당 값의 다른 이웃 코드다. 0번 패턴이 RTN이며 두 선택자가 같은 조합 전체에서 D 또는 D+J를 최소화한다. 동률은 첫 패턴이다. 선택한 코드의 직접 FP32 train/eval metric도 별도로 계산해 근사 정밀도 차이를 공개한다. FP64 이차식의 전수 최적값이지 IEEE FP32 연산 순서를 그대로 65,536번 실행한 최적값이나 모든 코드의 전역 상한은 아니다.

각 셀에서 FP64 이차식 계수·D/J 전체 배열·16개 좌표·선택 코드·해시를 보관한다. 6셀×2선택자=12개 평가 행. 전수 블록 후보가 공통 후보의 training 목적을 이기면 현재 탐색기의 약점을 보여주는 구체 사례다. 이기지 못해도 전체 탐색기가 충분하다는 증명은 아니다.

## 지표·진행 판단

두 공간 각각에서 선택자를 비교한다. 모든 평가 D/J는 query×출력차원으로 정규화하고 3층을 동일 가중한 프롬프트별 평균이다. **두 프롬프트 모두** 전환 선택자가 평균 선택자보다 평가 J를 10% 이상 줄이고 D가 1.02배 이하인지를 기록한다. baseline J≤`1e-12*max(D,1e-30)`이면 해당 프롬프트는 비율로 통과시키지 않는다. 두 공간 결과를 따로 공개하며 적어도 한 공간이 통과한 경우에만 추가 최적화 검토의 신호로 센다. p값·확증 주장·영상 생성 확대는 하지 않는다.

각 공간에서 같은 코드가 선택됐는지, train D/D+J와 RTN·기존 후보 대비 차이, eval D/J, 실제 바이트·FP64 작업공간·단계 시간을 남긴다. 탐색 진단 비용을 배포 encode 속도로 해석하지 않는다. 두 공간이 실패하면 이 가중치·query·후보 공간에서 추가 이득을 확보하지 못했다고 정리하고 임의로 블록·λ·입력을 바꿔 구제하지 않는다.
