# 그룹 규칙 연구의 마지막 구현 검증

상태: 실행 전 고정 계획. 승인된 2회 반복 경로 재현 + 24회 단회 경로 비교만 수행한다.
논문의 중심은 기존 12프롬프트 그룹 규칙 개입의 후반 MUSIQ +5.3935점이다.
이번 검사는 그 해석을 보강하며 신규 알고리즘 또는 보편 멱등성 발견이 아니다.

## 시작과 자원 상한

K+V TT의 18개 생성·평가·보고 종료 기록, 서비스 비활성, GPU 계산 프로세스 없음이
모두 확인된 뒤 시작한다. 대기 및 사전 CPU 구현 검사는 4시간에 포함하지 않는다.
그 조건을 확인하고 실행 예산 파일을 처음 기록하는 순간부터 단조 시계로 14,400초를
측정한다. 모델 로딩, 사전 무결성 검사, 두 재현 검사, 계측, 생성, 비교, 오류 조사와
재실행을 포함한다. GPU 적재 전 시작한 worker 시도도 보수적으로 1회로 센다.
최대 26회 또는 14,400초 중 먼저 도달한 생성 상한을 적용한다. 26번째 실행은
완료할 수 있으나 27번째를 시작하지 않는다. 시간 상한에서는 실행 중인 자신의
worker만 종료하고 미완료로 표시한다. 종료 시각은 마지막 worker 종료와 결과 집계
완료 시각으로 각각 기록한다. 종료 후 정적인 문서 작성은 별도 후처리 시간이다.
필수 종료·집계를 위해 마지막60초를 남기고 생성 worker를 중지한다.
자동 재시도는 없다. 무효 시도를 삭제하거나 카운트를 초기화하지 않는다.

## 고정 입력과 순서

기존 mechanism_prompts_v0.txt의 12개 프롬프트, 시드 303/404, INT4 K/V,
group16, 21잠재프레임 문맥, sink/residual 없음, 42청크·126잠재프레임을 유지한다.
1. C_repeat p00/s303 계측 재현.
2. C_repeat p11/s404 계측 재현.
3. 두 재현이 아래 게이트를 모두 통과할 때만 p00..p11, 시드303/404 순서의 C_once 24회.
실행별 모델과 난수를 기존 경로처럼 새로 초기화한다. 기존 데이터는 덮어쓰지 않는다.
현재 작업은 이미 사용한 프롬프트의 사후 구현 검증이지 새 보류 품질 실험이 아니다.

## 실제 연산의 관찰

기존 ChunkAdapter/Quantizer/생성 함수를 변경하지 않는다. 별도 실행기에서 실제
Quantized.restore 반환값을 관찰하고, 실제 Quantizer.encode 진입/반환을 계측한다.
복원·양자화 호출을 계측용으로 추가하지 않는다. 재인코딩 입력은 해당 저장 상태가
바로 반환한 텐서 객체인지, 최초 입력은 pending 텐서 객체인지 확인한다.
이것은 실제 객체 전달 경로의 검증이며 입력 해시나 일부 통계의 전체 원소 비교가 아니다.
CPU 합성 검사로 계측 ON/OFF의 연산 호출 수와 결과를 비교한다.

층별·청크별·호출별·저장 청크별 최초/재인코딩 이벤트를 기록한다. K와 V의 실제 encode
호출을 각각 기록하고 해당 호출이 반환됐는지 확인한다. 기대값 출력으로 계측을 대신하지 않는다.
각 층은 attention 210회, 최초 K/V 각각41회다. C_repeat 재인코딩은 K/V 각각1114회,
합계 각각1155회다. C_once 재인코딩은0회다. 30층 합계 쌍 호출은34650/1230회다.
각 attention 직전 생존 청크 순서, 현재 pending 시작점, 입력 길이/dtype, group16 및
각 segment의 encode 이력을 확인한다. 원래 규칙상 마지막 청크는 pending이므로
단회 최초 인코딩은42가 아닌41회다.

## 판정

두 재현 모두: 실제 연산 경로·층별 호출 수·비교 조건 통과 + 기존 산출물과 텐서 비트 일치.
계측 재현 불일치는 gate failure이며 C_once로 진행하지 않는다.
주 비교는 tensor shape/dtype 확인 후 CPU contiguous uint8 원소 바이트의 직접 비교다.
파일 SHA256은 무결성 확인용으로 별도 기록한다. NaN/Inf는 무효 상태다.
24개 유효 쌍 모두 비트 일치하면 이 설정의 정확 일치를 보고한다. 유효한 한 쌍이라도
불일치하면 정확 일치 가설은 실패다. 허용 오차를 도입하거나 사례를 제외하지 않는다.
유효한 불일치 이후에도 남은 고정24개 비교는 자원 상한 내에서 수행하며 새 사례는 추가하지 않는다.
불일치 시 저장 텐서의 처음 다른 청크·원소 수·최대 수치 차이와 입력/소스/호출 기록을
확인한다. 구현 위반이면 무효, 실행 조건이 통과하면 유효 수치 차이, 구분 불가면 판단 불가다.
재현 실패 또는 무효 실행에서 자동으로 고쳐 계속하지 않는다. 자료를 보존하고 종료한다.

## 증거와 보고

기존 C_repeat24개의 latent/sampling48파일 해시와 소스 식별자를 검증한다.
과거24개의 인코딩 계측은 없으며 사후 복원했다고 쓰지 않는다. 직접 계측 범위는
새 반복2회와 단회24회(완료한 범위)뿐이다. 두 반복 재현이 나머지 과거22회의
실행 계측을 대신하지 않는다. 모델/환경/동결 코드/새 계측 코드의 식별자를 함께 보존한다.
결과에는 24쌍의 일치/불일치/미완료/무효, 두 재현의 판정, 실제 시도 수·완료 수,
층별 호출 기록, 시작/종료 KST와 경과 시간, 상한 도달 여부를 구분해 공개한다.
핵심 그림은 기존12개의 프롬프트별 품질 차이와 평균/구간이며 이번 결과는 보조 패널이다.
QVG에 특정 비교가 없다는 이유로 신규성을 주장하지 않는다. 결과에 맞춰 최종 초안을
확정하고 TT 또는 다른 압축 후보의 추가 탐색은 시작하지 않는다.
