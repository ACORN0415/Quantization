# QVG 복원값 유지 진단의 측정 설계

2026-10-31. **이 문서는 단계0 결과를 반영한 후속 설계다. 아래 생성·성능
실험은 아직 실행하지 않았다.** 단계0의 합성 smoke test와 구분한다.
목표는 새 알고리즘이 아니라 후속 연구의 진행/축소/종료 결정이다.

## 1. 비교 경로와 주장 범위

U: 공식 QVG read 경로. 코드 재현·중복 호출 영향 확인용.

B: U에서 단일 span의 이중 decoder 호출만 제거한다. 코드·scale·centroid,
읽는 토큰, concat, pre-RoPE K 처리, native attention은 유지한다.

R: B에서 지정한 pre-RoPE 복원 span을 제한된 공간에 유지한다. 최초 복원 비용,
검색·할당·무효화·해제·concat 비용을 포함한다. 압축 표현은 그대로 보유한다.
원본 BF16 값을 보관하는 경로가 아니다. 보관값이 있어도 출력 연결 비용은 지불한다.

주 대비는 B vs R. U vs B는 구현 정리 효과로 별도 보고한다. 동일 코덱/동일
복원 수학의 fused attention은 미확보이므로 최적 읽기 방식·fused 우위는 주장하지 않는다.
다른 코덱의 커널을 QVG의 fused 기준선으로 대체하지 않는다.

## 2. 생성 연결 및 정확성 게이트 — 단계1a

- 공식 QVG revision·INT2 설정은 단계0과 동일.
- 기존 로컬 Self-Forcing 체크포인트와 텍스트 조건을 사용하고 해시를 기록한다.
- 모델 연결 코드는 별도 adapter로 작성한다. 과거 연구 코드와 upstream을 수정하지 않는다.
- 압축주기8생성청크, 청크3잠재프레임, denoising4회+clean refresh의 native
  일정을 확인한다. 매 호출의 실제 schedule을 로그로 저장한다.
- 영상 생성 전 실제 native span 형상 `[1,12,37440,128]`의 packed 복원 검사를
  수행한다. 부분 읽기·새 쓰기·state 교체·퇴거·메모리 부족 시 우회 경로를 검증한다.
- 유지 키는 span 식별자와 압축 state 버전에 종속시킨다. raw chunk의 쓰기와
  quantized span의 교체·삭제를 관찰해 stale 값을 재사용하지 않게 한다.
- 생성 입력: 기존 개발 프롬프트 p00, seed303, 총36잠재프레임(12생성청크).
  이는 새 품질 보류 표본이 아니며 양자화가 실제 발생한 뒤의 읽기를 포함한다.
- U/B/R 각1회에서 실제 attention 입력의 형상·dtype·바이트와 최종 latent를
  직접 비교한다. 파일 해시만으로 입력 동등성을 주장하지 않는다.
- 비교 자료의 저장·CPU 전송·해시는 검증 실행에만 사용한다. timed 실행에서는 끈다.
- 불일치 시 재현 가능한 최소 원인을 조사하고 게이트 실패로 기록한다. 허용 오차를
  사후 조정하지 않는다. 같은 경로 자체의 비결정성이 확인되면 정확 일치 주장을 보류한다.

단계1 전체는 새 GPU 생성 최대12회 또는120분 중 먼저 닿는 상한을 사용한다.
최초 모델 연결 검사의 시작부터 JIT·검증·계측·warmup·timing·실패를 모두 포함한다.
최대12회의 배분: U/B/R 정확성3회 + B 프로파일1회 + B/R 전체 warmup2회 +
B/R timed3쌍6회. 실패도 횟수에 포함하며, 남은 슬롯으로 무조건 채우지 않는다.
한 쌍이 미완료면 완료된 한쪽을 대응 비교에 쓰지 않는다. 코드 준비 시간은 별도 기록한다.

## 3. 메모리 제한과 보고

단계1의 공통 한도는 전체 프로세스 GPU 사용량20GiB, R의 추가 보관 슬롯 상한1GiB다.
이는 같은 실제 사용량을 요구하지 않는다. 총량은 가중치·활성·압축 상태·BF16 pending·
복원값·작업공간·allocator 예약·CUDA context를 포함하는 범위로 점검한다.

allocator의 allocated/reserved peak와 NVML 프로세스 메모리 표본 최대를 함께 기록한다.
NVML 표본 간 transient peak를 정확히 관측했다고 주장하지 않는다. preallocated 유지
pool, per-process allocator cap, 비-allocator 사용량의 여유, 단계별 동기화 검사로 상한을
집행하고 OOM/한도 초과는 infeasible로 기록한다. 성능을 본 뒤 한도를 늘리지 않는다.

R은 고정된 층 순서와 span 순서대로1GiB 안에 들어가는 완전한 K/V span만 유지한다.
비용을 보고 유리한 층을 고르지 않는다. 전부 유지하는 값은 공간이 허용되는 별도 참고
조건일 뿐 같은 예산의 대조군으로 섞지 않는다.

표에는 매번 `(총량 상한, 추가 유지 상한, 실측 allocated/reserved/process peak, 시간)`을
기록한다. 동일 상한의 속도 개선, 동일 사용량의 개선, Pareto 곡선 개선을 구분한다.

## 4. 시간 측정과 잡음 — 단계1b

- 모델 로딩·텍스트 인코딩·VAE·저장은 별도 항목. 주 timing은 같은 생성 함수의
  시작부터 마지막 latent 완료까지이며 모든 청크의 압축·복원·연결·관리 비용을 포함한다.
- 조건별 JIT/autotune과1회 전체 warmup을 끝낸 후 timed 실행한다.
- timed3쌍의 순서를 B→R, R→B, B→R로 고정한다. 같은 입력·난수 상태를 재설정한다.
  전체 상태 reset은 동일하며 유지값의 최초 복원을 timing 바깥으로 빼지 않는다.
- 전체 구간 시작/끝 CUDA synchronize 후 monotonic wall time을 기록한다.
  내부 연산별 synchronize는 timed 실행에 추가하지 않는다.
- 프로파일은 별도 B 실행1회로 분리한다. CUDA event/Nsight 등의 계측 시간 합은
  전체 절약 가능 시간의 엄밀한 상한으로 부르지 않는다.
- GPU 외부 PID, 온도·클럭·전력·순서를 기록한다. 외부 작업·thermal 변화 등 사전
  정한 무효 조건만 적용하며 느린 결과를 사후 삭제하지 않는다.
- 각 쌍의 차이와 상대 개선율, 중앙값, 범위를 모두 보고한다.3쌍으로 정밀한 신뢰구간이나
  5% 주변의 유의한 차이를 확보했다고 주장하지 않는다.

판정은 두 근거를 함께 쓴다: (a) 프로파일의 낙관적 절약 가능 시간 추정,
(b) B/R 전체 wall-time 대응 차이. 5%는 연구 투자 판단 기준이다.
잡음 범위가5%를 가로지르거나 두 근거가 충돌하면 `판단 불가`로 남기고 자동 확장하지 않는다.
낙관적 추정치가5% 미만이라는 이유 하나만으로 엄밀한 불가능 판정을 하지 않는다.
단계1 통과는 해당 입력·메모리 조건의 구현 진단이지 일반적인 성능 우위가 아니다.

## 5. H2의 사전 예측 검증 — 단계2 설계, 미실행

단계1에서 비용 규모와 측정 안정성을 확인한 경우에만 별도 실행 manifest를 봉인한다.
단계2의 예산·반복수는 단계1의 실제 회당 시간으로 산출해 실행 전에 기록한다.
단계1의12회·120분 예산을 자동 연장하지 않는다.

예정 조건은 같은 설정의 생성 길이36/48/60/72잠재프레임과 유지 상한0.5/0.75/1GiB다.
공통 총량20GiB에서 infeasible 조건은 측정 실패로 보존하며 성능 비교에서 제외 사유를 쓴다.

- 모델 구성용: 길이36/60 × 유지0.5/1GiB, 네 조건.
- 미사용 검증용: 길이48/72 × 유지0.5/0.75/1GiB, 여섯 조건.
- 구성용 조건에서만 복원·복사·관리의 비용 계수를 추정한다. native schedule과
  텐서 크기는 사용 가능하되 미사용 조건의 timing은 모델 구성에 사용하지 않는다.
- 자유도를 제한한 모델: 복원·layout 변환 비용은 bytes와 span 수, 관리 비용은
  hit/miss/무효화 수로 설명한다. 동일 dtype·codec·attention 아래 B와 R의 차이를
  예측한다. 계수·수식·선택 규칙·오차 처리 방식을 JSON과 코드 해시로 동결한다.
- 미사용 timing을 실행하기 **전에** 조건별 예측 시간, 선택 경로, feasibility와
  예측 파일 해시를 저장한다. 결과를 본 뒤 모델을 바꿔 같은 검증을 재사용하지 않는다.

주지표는 선택 regret:

`regret(c) = T(chosen,c) - min(T(B,c),T(R,c))`.

밀리초와 `regret/min(T(B),T(R))`를 함께 보고한다. 각 T는 사전 고정된 교차 실행의
대표값이며 개별 반복의 분산도 보존한다. 평균 regret뿐 아니라 최악 조건의 regret,
예측 시간 오차, 잡음 범위를 넘는 승자 차이에서의 선택 오류를 보고한다.
잡음 안의 near-tie는 별도 표시하지만 불리한 샘플을 삭제하지 않는다.

한 경로가 모든 조건에서 우세하면 비용 모델 자체의 실패라고 판단하지 않는다.
항상B/항상R/고정 보관과 비교해 선택의 추가 효용이 없으면 동적 정책 연구를 중단한다.
단계2 평가 기준은 미사용 실행 전에 시간 잡음 수준에 맞춰 수치로 봉인한다.

## 6. 필요한 최종 산출물

1. 공식/정리/유지 경로의 정확성·실제 호출 증거와 직접 관측 범위.
2. 총량 상한·실측 peak·시간을 나란히 적은 대응 결과표, 실패·미완료 수.
3. 프로파일의 낙관적 추정과 실제 전체 wall-time 차이의 대조.
4. H2로 진행했다면 사전 예측 파일, 동결 모델, 미사용 조건별 regret.
5. `진행`, `단순 구현 개선으로 축소`, `판단 불가`, `종료` 중 하나의 결정과 근거.

어느 단계에서도 새 압축기·토큰 삭제·추가 저정밀화·fused 커널 개발을 성공을 위한
구제 후보로 붙이지 않는다. 최종 주장은 실제 완료한 비교 범위에 한정한다.
