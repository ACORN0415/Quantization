# 수학적 근거: 무엇을 증명하고 무엇을 실험으로 확인하는가

이 문서는 진행 중인 실험의 팔·주지표·진행 조건을 바꾸지 않는다.
이상적 RTN의 성질, 그룹 위치 산술, 실제 부동소수점 코드, 최종 영상 품질을 구분한다.
아래 수학은 신규성을 주장하는 새 양자화 알고리즘이 아니다.

| 대상 | 근거 | 범위 |
|---|---|---|
| 고정 그룹 RTN의 멱등성 | 아래 직접 증명 | 정확한 실수 연산·고정 그룹·결정적인 nearest rounding |
| 정렬된 이동의 그룹 구성 보존 | Lean `GroupBoundary` | 모든 자연수 위치, 양의 그룹 크기, 이동량이 그룹 크기의 정수배 |
| 그룹 재편 후 오차의 단조 증가 | 반례로 성립하지 않음 | 실제 구현의 합성 BF16 버퍼에서도 증가/감소 모두 재현 |
| attention/생성 품질 우위 | 조건부 분석과 실험 | 보편적 수학적 우위는 증명하지 않음 |

## 1. 고정 그룹에서는 RTN을 반복해도 값이 바뀌지 않는다

한 batch·head·channel의 토큰 그룹 벡터를 x, q=2^(b−1)−1, M=max_i |x_i|라 하자.
실제 RTN처럼 각 channel의 그룹을 독립적으로 처리하며 K/V에도 각각 적용한다.
정확한 연산에서 s=max(M/q,ε), ε>0로 정하고

    c_i = round(x_i / s),     Q(x)_i = s c_i

로 정의한다. ε는 고정된 최소 scale이다. 이 범위에서 |x_i/s|≤q라서 코드 clipping은 값을 바꾸지 않는다.

**정리:** 그룹 구성과 위 규칙이 고정돼 있으면 Q(Q(x))=Q(x).

**증명:**

1. M/q≥ε라면 최대 절댓값 원소의 코드는 정확히 ±q다.
   따라서 y=Q(x)의 최대 절댓값은 qs이고, 다시 계산한 scale은 max(qs/q,ε)=s다.
2. M/q<ε라면 s=ε이고 모든 코드의 절댓값은 q 이하다.
   y의 최대 절댓값은 qs 이하이므로 다시 계산한 scale도 ε=s다.
3. 두 경우 모두 두 번째 quantizer가 읽는 값은 y_i/s=c_i라는 정수다.
   정수의 nearest rounding은 자기 자신이므로 Q(y)_i=s c_i=y_i. 증명 끝.

따라서 같은 그룹에 저장한 과거 값을 다른 쓰기와 섞지 않고 유지하면
Q^r(x)=Q(x) (r≥1)다. C-repeat와 C-once가 같거나 가까울 것이라는 예측의 근거다.
멱등성은 초기 양자화 오차가 0이라는 뜻이 아니다. 첫 오차는 남되 반복만으로 더 바뀌지 않는다는 뜻이다.

**실제 코드에 대한 제한:** `kvq/quant.py`는 코드 계산을 입력 dtype에서 하고 scale을 FP16으로 저장한다.
복원 때 scale cast와 BF16 곱셈 반올림도 있다. 즉 최초 코드 계산의 scale과 실제 복원 격자가
이상적 실수 s와 정확히 같다는 보장이 없다. 위 정리는 BF16/FP16/CUDA 구현 전체의 형식 증명이 아니다.
실제 입력의 동일성은 별도 게이트와 재생 기록으로 확인해야 한다. 유한 입력만으로 FP16 scale의
overflow/underflow까지 배제할 수는 없으며 비유한 상태는 실험에서 실패로 처리한다.

## 2. 그룹 정렬과 eviction의 관계

크기 g인 물리 그룹에서 위치 p의 그룹은 floor(p/g), 내부 위치는 p mod g다.
좌표를 Δ=kg만큼 이동하면

    (p+kg) mod g = p mod g
    floor((p+kg)/g) = floor(p/g)+k

이다. 따라서 두 토큰이 같은 그룹에 속하는지 여부도 유지된다.
삭제 방향의 재색인도 p가 생존한 토큰이면 이 식을 거꾸로 적용하면 된다.

반대로 Δ가 g의 배수가 아니면 보존이 깨질 수 있다.
g=16에서 p=7과 p=8은 원래 같은 그룹이지만, Δ=4680을 더하면
4687은 그룹 292, 4688은 그룹 293으로 갈라진다.
실제 삭제 방향으로도 4688과 4696은 원래 그룹 293에 함께 있었지만,
4680토큰을 삭제하면 위치 8과 16이 되어 서로 다른 그룹으로 나뉜다.
g=24에서는 4680=195×24이므로 같은 문제가 없다.

그룹별 연산이 다른 그룹에 의존하지 않는다면, 완전한 그룹을 삭제하는 연산 P와 양자화는
Q(Px)=P Q(x)로 교환한다. 그룹 경계에 맞춰 새 청크를 붙이면 Q(h||u)=Q(h)||Q(u)다.
현재 쓰기가 과거 그룹을 바꾸지 않는 조건이다. 이 분리 성질과 읽기별 encode 횟수가 맞으면
L24와 C-repeat24가 같은 읽기 상태를 만들 것이라는 게이트를 정당화한다.
L24/C-repeat24의 스케줄 동등성과 이 산술 정리는 구분한다. Lean은 전체 캐시 수명과 모델 실행을 증명하지 않는다.

## 3. 재편은 추가 오차를 만들 수 있지만 항상 오차를 늘리지는 않는다

다음은 q=7, 그룹 크기 2의 정확한 유리수 RTN 예다. 첫 원소를 퇴거한 뒤 새 물리 그룹으로 재encode한다.

**증가 예:** x=(49/100,49/100,1,49/100).

    Q(x)                  = (49/100,49/100,1,3/7)
    퇴거 뒤 저장값         = (49/100,1,3/7)
    재편 뒤 다시 양자화     = (3/7,1,3/7)

삽입 원본의 생존 좌표 (49/100,1,49/100)에 대한 제곱 오차는 (43/700)²에서 2(43/700)²로 증가한다.
이전 그룹에서 정확했던 값 하나가 새 이웃의 scale 때문에 추가로 손상된다.

**감소 반례:** x=(1,4/5,3/2,2).

    Q(x)                  = (1,6/7,10/7,2)
    퇴거 뒤 저장값         = (6/7,10/7,2)
    재편 뒤 다시 양자화     = (40/49,10/7,2)

원본 생존 좌표 (4/5,3/2,2)에 대한 오차는
(2/35)²+(1/14)²에서 (4/245)²+(1/14)²로 줄어든다.
재편의 새 격자가 이전 반올림을 우연히 일부 보정한 것이다.

따라서 “단회 저장 오차가 반복/재편 저장 오차보다 모든 입력에서 작다”는 보편 정리는 성립하지 않는다.
이 두 방향은 실제 `Quantizer.encode`의 group=16, cache=32760, eviction=4680, INT4/BF16 합성 버퍼에서도
재현했다. 다만 그 합성 버퍼가 Wan의 실제 활성값으로 생성되는지는 입증하지 않았다.
전체 입력 분포에서 어느 쪽이 우세한지는 실제 재생과 새 FR에서 확인할 질문이다.

## 4. 단회 저장이 보장하는 것은 추가 드리프트 항의 제거다

같은 생존 토큰 좌표에서 최초 저장 오차를 e₀, 이후 재encode의 추가 변화를 δ_t라 하면

    e_T = e₀ + Σ δ_t
    ||e_T||₂ ≤ ||e₀||₂ + Σ ||δ_t||₂
    ||e_T||₂² = ||e₀||₂² + 2Σ⟨e₀,δ_t⟩ + Σ_{s,t}⟨δ_s,δ_t⟩

이다. C-once는 이미 저장한 토큰을 재encode하지 않으므로 그 토큰의 추가 δ_t가 없다.
고정 그룹의 이상적 C-repeat도 멱등성으로 δ_t=0이다. 재편된 L에는 0이 아닐 수 있는 항이 추가된다.
**추가 항을 없애는 것과 모든 입력에서 최종 오차가 더 작다고 보이는 것은 다르다.**
내적 항이 음수이면 상쇄도 가능하므로 위 반례와 모순되지 않는다.

퇴거가 있으면 e_t=P_t e_{t−1}+δ_t로 쓰고 생존 좌표로 계속 투영한다.
좌표 삭제는 L2 norm을 늘리지 않으므로 같은 삼각부등식 상계가 성립한다.
그러나 상대 L2의 분모와 살아 있는 토큰 구성이 달라지면, 단회 저장에서도 캐시 전체 상대 오차는 변할 수 있다.

같은 생존 좌표를 고정하고 추가 오차가 과거에 조건부 평균 0이라면 교차 항의 기대값을 없애
그 좌표에서 기대 제곱 오차 증가식을 얻을 수 있다. 삭제 전 전체 캐시와 삭제 후 부분 캐시의
제곱 오차를 비교해 반드시 증가한다고 말하는 것은 아니다.
하지만 결정적 RTN에 그 가정을 자동으로 적용할 수는 없다. 현재 분석에서 가정한 정리가 아니다.

## 5. 같은 KV 오차 크기가 같은 attention 손상을 뜻하지 않는 이유

한 query q의 logit 변화는 δl_i=qᵀδk_i/√d다.
같은 ||δk_i||라도 query와 직교하면 0이고 평행하면 최대 ||q||·||δk_i||/√d가 된다.
따라서 오차 norm 하나로 attention 손상을 결정할 수 없다.
오차의 평균 b와 covariance Σ에 대한 2차 모멘트는

    E[(δl_i)²] = qᵀ(Σ + b bᵀ)q / d

로, norm뿐 아니라 방향·편향·공분산이 중요하다. 이는 저장 이벤트 노름을 맞춘 잡음 대조군과
실제 양자화가 다른 결과를 낼 수 있는 수학적 이유지만 어느 구조가 원인인지 입증한 결과는 아니다.

또한 모든 key에 동일하게 더해진 logit 상수는 softmax를 바꾸지 않지만,
과거 key에만 생긴 변화는 현재 key와의 상대 attention을 바꿀 수 있다.
exp의 볼록성만으로 무작위 softmax 비율의 기대값 방향까지 바로 결론 내리지 않는다.

## 6. 영상 품질로 연결하려면 추가 가정 또는 실험이 필요하다

생성과 캐시를 포함한 상태를 z_t, 저장의 추가 교란을 η_t라 하고 국소적으로

    Δz_{t+1} ≈ A_t Δz_t + B_t η_t

라고 선형화하면 과거 교란은 이후 A 행렬들의 곱을 거쳐 영향을 준다.
어느 방향은 증폭되고 다른 방향은 줄어들 수 있다. 이는 작은 저장 교란의 피드백 경로를 설명하지만
현재 코드에서 Jacobian 크기나 증폭 방향을 검증한 것은 아니다. 근사 나머지 항도 존재한다.

상태 오차의 상계를 더 작게 만들더라도 비선형 생성기와 MUSIQ가 그 오차에 대해 단조라는 보장은 없다.
그러므로 **저장 성질은 증명하고, 실제 품질 효과는 보류 FR 실험으로 확인한다.**
현재 진행하는 실험의 의미도 이 두 근거를 연결하는 데 있으며, “P3가 수학적으로 항상 더 좋은 영상”이라는 주장은 하지 않는다.

## 7. 증명·검사 결과와 재현

Lean의 정수 성질은 모든 자연수 위치에 대한 조건부 증명이다. BF16/CUDA의 검증은 아니다.
[형식 모델과 가정](../../../lean/TARGETS.md), [Lean 모델](../../../lean/Model/GroupBoundary.lean),
[고정한 명제](../../../lean/Model/GroupBoundary.statements), [의도적 오류 검사](../../../lean/Model/GroupBoundary.mutations)를 참조한다.
저장소 루트에서 다음을 실행한다. `<skill-dir>`은 설치된 formal-verify 스킬 경로다.

```bash
bash <skill-dir>/scripts/setup.sh lean "$PWD/lean"
bash <skill-dir>/scripts/lean-check.sh "$PWD/lean" > /tmp/group_boundary_lean.log 2>&1
python3 <skill-dir>/scripts/mutate.py "$PWD/lean/Model/GroupBoundary.mutations"
python3 tools/check_quantizer_theory.py --lean-log /tmp/group_boundary_lean.log
```

Python 검사는 Lean 출력의 24개 위치 벡터를 production quantizer의 impulse 그룹/offset과 대조한다.
Python 명령은 PyTorch가 설치된 환경에서 실행한다.
이것은 인덱스 전사의 대조이지 실제 rounding 전체에 대한 증명이 아니다.
[정확한 수와 native 합성 버퍼 검사](theory_checks.json)에 반례와 일치 수를 기록한다.
실험 수치·상태·모델 소스는 이 작업에서 변경하지 않았다.

이번 실행 결과: Lean은 14개 선언을 검사해 미완성 증명/추가 공리 없이 통과했다.
1,560개 작은 입력 삼중항과 각 65개 비교 위치의 bounded 검사도 통과했고,
틀린 그룹 크기·1토큰 과다 이동·틀린 나머지 연산의 세 mutation을 모두 검출했다.
24개 differential 벡터는 실제 quantizer의 48회 encode와 일치했다.
작은 유한 검색과 모든 자연수에 대한 Lean 정리는 서로 다른 증거다.
