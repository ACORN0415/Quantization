# 전환 rounding 후보의 측정 전 대수 게이트

2026-10-29. 실제 모델 캡처·GPU 탐색 전에, 제안한 첫 설정이 기존 출력 오차 목표와 구별되는지 검사했다. 이 문서는 연구 후보를 제한하는 **실수 산술 유도와 CPU 부동소수점 확인**이다. Lean 등의 형식 증명이나 영상 결과는 아니다.

## 고정한 범위

K는 BF16으로 고정하고, 같은 query를 캐시 삭제 전후에 적용한다. 남은 토큰의 K·RoPE 위치·V 코드·scale은 바꾸지 않는다. 새 청크 U의 V만 지금 encode하며, 기존 청크의 코드는 고정한다. 실제 encoder는 새 청크의 원본 V를 알지만 과거 BF16 V 원본은 이미 버렸다고 가정한다. 따라서 여기서 실행 가능한 목적은 새 청크가 추가한 출력 오차다. 기존 과거 오차를 0이라고 가정하는 것과, 실제 과거 오차가 0이라고 주장하는 것은 다르다.

## 동일 query에서의 정확한 관계

query/head 하나를 고정한다. 삭제 전 attention 확률을 p_i, 살아남는 토큰 집합을 S, 그중 새로 압축하는 토큰 집합을 U라 하자. U는 S에 포함된다. K와 query가 같고 삭제만 일어나므로 생존 토큰의 logit은 변하지 않는다. 따라서

\[
 s=\sum_{i\in S}p_i>0,\qquad c=1/s,\qquad p_i'=c p_i\;(i\in S).
\]

새 V의 복원 오차를 Δv_i라 하면, 이 새 청크가 추가한 출력 오차는

\[
 e_0=\sum_{i\in U}p_i\Delta v_i,\qquad
 e_1=\sum_{i\in U}p_i'\Delta v_i=c e_0.
\]

그러므로 제안한 평균 출력 오차와 전환 항은

\[
 D=\tfrac12(\|e_0\|^2+\|e_1\|^2)
   =\tfrac12(1+c^2)\|e_0\|^2,
\]

\[
 J=\|e_1-e_0\|^2=(c-1)^2\|e_0\|^2.
\]

최종 목표는 정확히

\[
 D+\lambda J=\underbrace{[\tfrac12(1+c^2)+\lambda(c-1)^2]}_{w(q,\mathrm{head})}\|e_0\|^2.
\]

여러 query/head에서는 이 항을 합하거나 평균하면 된다. **새 전환 목표가 query별 가중 출력 오차와 대수적으로 같다.** 삭제되는 attention 질량이 큰 query/head에 가중치를 더 주는 해석은 가능하지만, 이것만으로 독립적인 시간 전환 손실이나 새 알고리즘의 근거가 생기지는 않는다. 같은 후보와 정확한 같은 목적·초기화·solver를 쓰면 별도의 weighted-output 구현과 최적화 문제가 같다.

이 관계는 새 V를 복원할 때 BF16으로 반올림해 ΔV가 비선형으로 정해지더라도, 그 최종 ΔV를 두 상태에서 공통으로 쓰면 실수 AV 산술에서 성립한다. 실제 BF16 attention 누산·softmax·연산 순서로 차이가 생기는 것은 수치 구현의 문제이며, 목표의 본질적 신규성을 만드는 근거가 아니다.

## 과거 원본까지 알면 왜 달라지는가

삭제될 과거 토큰의 오차 기여를 r, 생존하는 과거 토큰의 오차 기여를 b, 새 청크의 가변 기여를 z라 쓰면 전체 오차는

\[
 e_0=r+b+z,\qquad e_1=c(b+z).
\]

전환 오차는 `(c−1)(b+z)−r`가 된다. 따라서 전체 목적은 z에 대한 가중 이차항뿐 아니라 **r,b에 의존하는 선형항과 상수항**을 갖는다. 전체 과거 BF16 V를 보관한 offline 진단에서는 계산할 수 있지만, 원본 과거 V를 버린 실제 codec은 이 과거 오차를 정확히 알 수 없다. 원본 버퍼를 공짜로 사용하는 비교는 실행 가능한 방법과 구분해야 한다.

전체 과거 오차가 있는 경우에도 단순 비례라고 주장하면 안 된다. 대신 `E=e_0`, 삭제 토큰의 기존 오차 기여를 r라 두면

\[
 e_1=cE+d,\qquad d=-c r.
\]

따라서 `w=½(1+c²)+λ(c−1)²`, `β=½c+λ(c−1)`일 때 전체 목적은

\[
 D+\lambda J
 =w\left\|E+\frac{\beta}{w}d\right\|^2
 +\left[(\tfrac12+\lambda)-\frac{\beta^2}{w}\right]\|d\|^2.
\]

즉 과거 코드가 고정된 조건에서 **가중치와 목표 offset을 바꾼 출력 오차 문제**로 다시 쓸 수 있다. offset은 삭제될 과거 V의 실제 양자화 오차 r를 필요로 한다. `d=0`인 단순 후보가 가중 출력 오차와 같다는 결론과, `d≠0`인 전체 prefix도 오차가 비례한다는 틀린 주장을 구분해야 한다.

이 정보를 저비용 통계·스케치 등으로 얻는 새 알고리즘은 별도 후보가 될 수 있으나, 이번 rounding 제안이 이미 그 문제를 해결한 것은 아니다. 현재 판단은 **단순화한 V-only 후보에는 독립적인 목적이 없고, 전체 prefix 목표에는 원본을 버린 codec이 알 수 없는 과거 오차 정보가 필요하며 실행 가능한 새 방법이 아직 없다**는 범위다.

## CPU 확인과 판단 범위

`tools/transition_equivalence_gate.py`는 실제 연구 데이터를 읽지 않고 CPU float64에서 다음을 확인한다.

- 무작위 32개 attention에 λ 4개를 적용한 128개 목적값·gradient 일치 검사.
- 이웃 rounding 16개 후보의 목적값 및 선택 일치.
- 과거 토큰 오차까지 포함하면 단순 비례 관계가 깨지는 반례.
- 과거 오차를 고정한 전체 prefix에서도 shifted-target 식의 목적값·gradient가 일치하는 λ 4개 검사.

이는 유도를 보조하는 수치 property check이며 모든 입력의 형식 검증이 아니다. 산술·코드 선택 문제의 중복이 확인되면 이 설정에서 큰 모델 실험을 할 근거가 약하다. RTN보다 좋아질 수 있어도 query 가중 출력 오차 기준선보다 독립적인 기여를 보였다는 뜻은 아니다.

query가 실제로 달라지거나, K도 양자화되어 logit이 달라지거나, 과거 오차 정보가 추가로 제공되거나, grouping/code가 상태마다 달라지는 경우는 위 가정 밖이다. 이 문서는 그런 모든 전환 기반 방법의 불가능성을 증명하지 않는다.
