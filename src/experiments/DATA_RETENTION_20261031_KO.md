## 삭제 전 확인과 현재 재검증 범위

- 모든 대상 파일이 사용 중이지 않은지 확인했다.
- 삭제 전 모든 파일의 SHA-256을 계산했다. QVG 테이프는 기존 `verification.json`,
  432개 코덱 상태는 기존 `evidence.json`의 해시와 일치했다.
- 삭제 대상별 경로·크기·해시·이유는 [삭제 명세](data_retention_20261031.json)에 남겼다.
- QVG의 실제 attention 입력 전체 바이트 일치는 **삭제 전에 수행한 검증**이다.
  최종 latent 바이트 비교와 호출·자원 집계의 재검증은 남은 자료로 가능하다.
  입력 테이프 전체를 다시 대조하려면 별도로 재생성해야 한다.
- `tools/verify_kv_reuse_stage1.py`의 원래 전체 감사는 테이프를 요구하므로 지금 그대로
  실행하면 완료되지 않는다. 기존 `verification.json`을 현재 파일 존재의 보증으로 읽지 않는다.
- `tools/report_codec_order.py`의 원래 전체 감사는 432개 상태 파일을 요구하므로 현재
  그대로 실행할 수 없다. 기존 행·요약·보고서는 남아 있지만 삭제한 상태의 복원/해시를
  다시 감사하려면 해당 상태를 재생성해야 한다.
- 생성 소스·원본 입력·설정은 보존했다. 기존 실행기는 산출물 덮어쓰기를 거부하므로,
  재생성할 때는 별도 출력 경로를 준비해야 한다. 새 실행이 과거 파일과 바이트까지
  같을 것이라고 미리 보장하지 않는다. 이번 정리 과정에서는 GPU 재실행을 하지 않았다.

## 디스크 오류와 별도 조치

위 `sfq_data` 정리 합계에 포함하지 않는다.

`state_5.sqlite`, `thread_history_1.sqlite`, `goals_1.sqlite`의 `PRAGMA quick_check`는
