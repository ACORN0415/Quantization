# 공통 후보군·작은 전수 검사의 결과 — 추가 전환 선택 이득 없음

2026-10-29. [계획](../ROUNDING_SEARCH_QUALITY_DEVELOPMENT.md)과 코드를 `e957877`로 고정한 뒤 수행했다. 이전 post-W_O NO-GO는 그대로 두고 같은 개발 자료의 별도 진단으로 실행했다. 새 영상·모델 생성은 없다.

**확인한 두 후보 공간 모두에서 평균 목표와 전환 목표가 6셀 전부 동일한 코드를 선택했다.** 따라서 두 개발 프롬프트 모두 추가 전환 오차 감소는 정확히 0%였다. 한편 작은 전수 검사가 기존 탐색보다 좋은 training 후보를 찾은 셀도 있어, 기존 탐색기가 충분히 최적이었다고 결론내리지는 않는다.

## 무엇을 공정하게 비교했는가

기존 p0/p4·seed101·층0/14/29의 Q6 refresh(선택), Q7 첫 denoise(평가), BF16 K0..6, 새 V6, W_O를 재사용했다. K16/V4·g16·FP16 scale 고정이며 새 V가 추가한 출력 오차만 측정했다. 과거 전체 RTN 오차·압축 rollout·실제 전환 전체·영상 품질의 결과가 아니다. 기존 입력과 평가 query도 이미 본 개발 자료이므로 보류 일반화로 표현하지 않는다.

먼저 과거 세 탐색기×6셀의 32회 계산을 재현했다. 최종 코드와 training 손실 이력은 **18/18건 비트 일치**했다. 원본 수치 파일을 고치지 않았다.

### 공통 후보군

셀마다 RTN 1개와 세 탐색기의 32개 중간 hard 후보씩을 합쳐 **97개 슬롯**을 만들었다. 중복은 보존하고 동일한 목록에서 현재 query의 D 또는 D+J를 최소화했다. 평가 query는 선택 후 선택된 코드의 평가에만 쓰였다.

| 셀 | 97슬롯 중 서로 다른 코드 수 | 평균 목표 선택 | 전환 목표 선택 |
|---|---:|---:|---:|
| p0 층0 | 49 | 슬롯32 | 슬롯32 |
| p0 층14 | 57 | 슬롯32 | 슬롯32 |
| p0 층29 | 58 | 슬롯32 | 슬롯32 |
| p4 층0 | 56 | 슬롯32 | 슬롯32 |
| p4 층14 | 20 | 슬롯32 | 슬롯32 |
| p4 층29 | 55 | 슬롯32 | 슬롯32 |

슬롯32는 모두 전체 평균 목표 탐색의 마지막 hard 후보였다. 두 선택자가 실제로 동일한 코드 해시를 골랐으며, 선택 차이가 합산 평균에서만 상쇄된 것이 아니다. 전체 training 후보 582행을 보존했다.

### 선택한 16코드의 전수 공간

현재 query의 평균 출력 오차 D를 기준으로 단일 코드 flip의 정확한 이차식 이득이 큰 16개 scalar를 골랐다. 나머지 약 719만 scalar는 RTN에 고정했다. 각 16개 값의 이웃 두 코드 조합 **65,536개 전부**, 6셀 합계 **393,216개 조합**을 계산했다.

두 선택자는 같은 공간에서 D 또는 D+J를 최소화했다. 모든 셀에서 선택한 패턴과 코드 해시가 같았다. 선택 패턴 인덱스는 p0 층0/14/29에서 38903/58813/65535, p4에서 61277/65535/65535였다. index bit0은 첫 좌표이고, 0인 bit는 RTN 값을 뜻한다.

이는 **평균 목표가 선택한 특정 16개 좌표**, 저장 scale, FP64로 올린 고정 선형 attention 이차식에서의 유한 전수 최적값이다. 모든 코드의 전역 최적값이나 성능 상한이 아니다. 좌표 선택은 평균 목표에 유리할 수 있으며 전환 목적에 최적인 블록을 골랐다는 주장도 하지 않는다. 이웃 floor/ceil도 FP64 나눗셈으로 정의했다. 모든 실제 RTN 값이 그 두 이웃 안에 있음을 확인했다.

선택된 코드를 직접 FP32 attention metric으로도 계산했다. 이 값과 FP64 이차식의 상대 차이 최대는 D 약 8.85e−8, J 약 6.21e−7이었다. 부동소수점 연산 순서의 작은 차이를 숨기지 않았다. FP32 전체 후보를 재정렬해 primary 선택을 바꾸지는 않았다.

## 미사용 query 결과와 고정 판단

D/J는 query×출력 차원으로 정규화한 절대 추가 출력 MSE이며, 3층을 동일 가중했다. 두 선택자가 같은 코드를 고른 덕분에 각 공간의 평가 D/J도 정확히 같다.

| 공간 | 입력 | 평균/전환 선택의 평가 D(동일) | 평균/전환 선택의 평가 J(동일) | 추가 J 감소 |
|---|---|---:|---:|---:|
| 공통 후보군 | p0 | 9.34715412e−4 | 1.14391416e−4 | **0%** |
| 공통 후보군 | p4 | 5.57071717e−4 | 1.22383109e−4 | **0%** |
| 16코드 전수 | p0 | 9.35085496e−4 | 1.14402785e−4 | **0%** |
| 16코드 전수 | p4 | 5.57171517e−4 | 1.22389149e−4 | **0%** |

각 공간에서 두 프롬프트 모두 J 10% 감소·D 악화 2% 이내를 요구했다. baseline J가 충분히 커 작은 분모 문제는 없었지만, 추가 J 감소가 0%여서 두 공간 모두 NO-GO였다. p값이나 확증적 효과 부재를 주장하지 않는다. 0%는 영상 품질이 동일하다는 결과가 아니다.

## 탐색기의 약점도 실제로 확인됐다

**p4·층14에서는 16개만 바꾼 전수 후보가 기존 공통 후보군보다 선택용 D를 약 1.56% 더 줄였다.**

| 선택용 지표 | 공통 후보군 최선 | 16코드 전수 최선 | 전수 후보의 감소 |
|---|---:|---:|---:|
| D | 1.75154399e−4 | 1.72425954e−4 | 1.55774% |
| D+J | 1.76127243e−4 | 1.73400738e−4 | 1.54803% |

이는 기존 탐색기가 좋은 후보를 놓칠 수 있음을 보이는 구체 사례다. 다른 5셀에서는 그 특정 16코드 후보가 공통 후보보다 좋지 않았다. 작은 전수 해가 못 이긴 셀을 근거로 전체 탐색기의 적절성을 보증할 수도 없다.

핵심은 **탐색기의 약점과 전환 목표의 추가 이득은 다른 질문**이라는 점이다. 더 좋은 작은 후보를 찾은 p4·층14에서도 D와 D+J는 같은 코드를 골랐다. 확인한 공간에서는 탐색 경로 차이를 없애도 전환 항이 선택을 바꾸지 않았다. 그렇다고 다른 λ·query·전체 코드 공간에서도 선택이 절대 달라지지 않는다는 증명은 아니다.

이번 고정된 계열을 더 큰 영상 실험으로 확대할 양의 근거는 얻지 못했다. 추가 연구를 하려면 같은 후보를 반복 평가하기보다, 실행 가능한 새 알고리즘과 다른 조건에서의 예측 가능한 이득을 먼저 제시해야 한다.

## 비용·검증·재현

새 모델 실행 없이 전체 진단 루프는 7.41초(별도 프로세스 import/start 제외)였다. callback의 직접 metric·코드 CPU 해시·입력 IO 등을 포함하므로 배포 encode 속도가 아니다. 공통 후보 단계는 셀당 약 0.96–1.40초, FP64 좌표 선택·전수 단계는 약 0.019–0.098초였다. GPU peak allocated 1.185GiB, reserved 1.605GiB이며 실제 모델·cache 상주량이 아니다. 선택 코드와 전수 배열은 로컬 약 0.187GiB다. 전체 97개 대형 코드를 모두 저장하지 않았다.

모든 선택 코드의 새 V payload는 실제 8,100,864바이트, 가상 packed 4,500,480바이트로 같았다. 기존 scale·padding도 유지됐다. K와 원본·복원 작업공간은 이 payload 밖이며 전체 KV INT4 압축 실험이 아니다.
