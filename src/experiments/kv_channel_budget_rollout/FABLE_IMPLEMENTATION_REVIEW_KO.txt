3. 지적 (중대 아님, 기록·절차 수준)
================================================================
(1) provenance gate의 경직성: provenance()에 스크립트 자신의 sha가 들어가므로 quality() 단계에서
    버그가 발견되어 한 줄이라도 고치면 이미 생성된 8개 sampling.json이 211행 assert에서 전부 거부되고,
    생성 폴더는 overwrite 거부(120행)라 재생성도 불가하다. 지금 고치라는 뜻이 아니다. 만약 그런 상황이
    오면 "생성 시 script sha ≠ 평가 시 script sha"를 명시적으로 기록하고 generate 부분 diff가 비었음을
    보이는 절차를 미리 정해 두는 편이 낫다. 결과를 보고 판정 코드를 바꾸는 것과 구분해야 한다.
(2) decision_unit_checks.json의 provenance가 v1 script sha(5e1fd685…)다. git diff로 decisions()가
    HEAD에서 변경되지 않았음을 확인했으므로 결과는 유효하지만, 파일만 보면 현재 스크립트에 대한 검사로
    읽히지 않는다. 보고서에 "v1 시점 검사, decisions() 무변경"을 한 줄 적으면 된다.
(3) encode_events의 roundtrip_byte_equal: True는 컨트롤러가 검사한 값이 아니라 codec.encode 내부
    assert(core 57~59행: decode(payload)와 직접 복원의 byte 일치)가 통과했음을 뜻한다. 라벨을
    "codec 내부 assert 통과"로 읽어야 하며 독립 검증으로 세지 않는다.
(4) late 창의 dino_adjacent는 adjacent[248:]로 (248,249) 쌍을 포함해 252쌍/252프레임이다. 정의상
    문제는 없고 모든 팔에 동일하지만 "후반(249..500) 인접"의 첫 쌍이 248프레임을 포함함을 기록한다.
(5) 메모리 수치 해석: 복원 K가 원본 BF16 cache에 더해 GPU에 상주하므로 peak_allocated는 기준선보다
    클 수 있다. 등록대로 메모리·속도 주장이 없으니 모순은 아니나, 결과 보고에서 peak 값을 비교 지표로
    쓰지 않도록 한다. cpu_encode_restore_transfer_s도 .cuda() 전송을 포함한 진단값이다.
(6) 용어: S120의 'selected' mask는 페이지·head마다 그 페이지의 |K| 평균으로 63채널을 고르므로
    청크 간에 채널 집합이 고정되지 않는다. 등록문의 "고정 K 채널boost"는 코덱 설정이 고정이라는
    뜻으로 읽어야 하며, "고정 채널 집합"으로 오독되지 않게 결과 보고에서 한 번 명시한다.
