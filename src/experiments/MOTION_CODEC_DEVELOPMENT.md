# 움직임 정렬 KV 압축: 제한된 이동 예측의 개발 진단

2026-10-29, 측정 전 v2. **새 진단 수치를 보기 전에 정한 계획**이다. 기존 본 실험·NO-GO 판단·수치 구현을 바꾸지 않는다. 새 보류 프롬프트, 긴 생성 실험, 신규성 확정은 이 단계에 포함하지 않는다.

## 질문과 선행연구 경계

동일 위치의 복원 KV로 예측하는 단순 잔차 코드에 비해, **작은 공간 평행이동을 적용한 복원 KV**가 더 작은 복원 오차를 만드는가? 우선 코드·위치·참조 비용과 제한된 이동 예측의 가능성만 검사한다. 전역 평행이동은 물체별 움직임·가려짐을 표현하는 dense motion map이 아니다.

[TempoKV](https://arxiv.org/html/2610.15324v1)는 복원 시간 이력의 같은 위치 K 예측과 K/V 연계 예측·잔차 양자화를 이미 사용한다. [FAST-AR/TempCache](https://arxiv.org/html/2602.01801v2)는 대응을 이용한 KV 병합, [WorldCache](https://arxiv.org/html/2603.22286v1)는 latent 대응 기반 특징 warp, [WorldTrace](https://arxiv.org/html/2608.07408v1)는 위치를 분리한 canonical memory를 다룬다. 이 구성요소를 조합했다는 사실만으로 새 방법이라고 부르지 않는다. 이번 단순 동일 위치 기준선은 **TempoKV 재현이 아니며**, 이 기준선을 이긴 것만으로 기존 방법보다 낫다고 결론내리지 않는다.

## 입력·참조·저장 형식

- 이미 개발에 사용한 p0/p4, seed101만 사용한다. BF16 기준 실행의 첫 8청크를 다시 실행하고, 기존 126잠재프레임 기준 잠재 텐서의 해당 prefix와 비트 단위로 비교한다.
- 층 `{0,14,29}`, 청크 `{0,1,6,7}`의 마지막 context refresh(call4)만 캡처한다. 공간 H/W는 실제 모델 grid에서 얻으며 고정 해상도 가정으로 배열하지 않는다.
- 각 3잠재프레임 청크 안에서 `0→1`, `1→2` 두 쌍을 독립 평가한다. **매 쌍마다 참조 프레임을 직접 양자화하고 복원한 값**을 사용한다. 앞 쌍의 잔차 복원 결과를 다음 쌍의 참조로 잇지 않는다. 따라서 이 단계는 길이 1의 닫힌 참조 의존성만 검증한다.
- K는 실제 pre-RoPE 값을 캡처하여 예측·복원하고, 원래 목적 토큰의 위치로 RoPE를 적용한다. V는 원래 위치에서 그대로 복원한다. post-RoPE 값을 역회전해 얻은 근삿값을 원본 pre-RoPE로 부르지 않는다.
- K4V4, 토큰 그룹 g=16을 첫 진행 판단 설정으로 사용한다. 새 코어는 FP32 양자화 계산, 저장 FP16 scale, byte code container를 사용한다. 기존 BF16 RTN 경로와 같은 수치 구현이라고 부르지 않는다. K2V2 지원·합성 검사는 가능하지만 결과를 보고 주 판단 설정을 바꾸지 않는다.
- 범위 밖 위치는 zero predictor로 처리하여 원래 값을 잔차로 저장한다. 경계를 wrap하거나, 실제 현재 K/V를 무비용 예측값으로 복사하지 않는다. 현재 토큰 수와 원래 위치를 유지하며 병합·삭제하지 않는다.

## 비교와 실행 순서

1. **단위·위치 게이트:** lossless residual일 때 원래 입력과 복원이 같고, zero shift가 동일 위치 코드와 같아야 한다. 합성 평행이동과 경계 처리·바이트 합계를 확인한다. 무손실 pre-RoPE 복원에 원래 위치 RoPE를 적용한 값이 캡처한 원래 post-RoPE와 같아야 한다. 관찰 hook을 붙인 BF16 출력도 기존 prefix와 같아야 한다. 실패하면 수치 비교를 진행하지 않는다.
2. **동일 형식 비교:** 직접 양자화, 동일 위치 잔차, 층0 K에서 정한 공유 전역 평행이동 잔차를 비교한다. 추가로 공유 이동과 같은 유효 경계 마스크를 씌우되 내부 위치는 움직이지 않는 동일 위치 대조군을 둔다. 이동의 zero-predictor 경계 효과와 내부 대응 효과를 분리하기 위한 대조다. 참조 프레임 형식과 복원값은 두 잔차 팔에서 같다. 공유 이동은 현재 encode 시점에 이미 존재하는 현재 K와 복원 참조 K만으로 선택한다. 미래 query/미래 프레임을 사용하지 않지만, 선택·검색 계산은 공짜가 아니다.
3. **제한된 oracle 진단:** 각 층의 현재 원본 K를 보는 별도 탐색 결과를 분리한다. 이동 후보는 token 2D 좌표의 dx/dy 각각 `[-2,2]`다. oracle은 이 제한된 후보 중 진단 목적의 선택이며, 가능한 모든 대응·코드의 최적값 또는 전역 이론 상한이 아니다. 공유/층별 탐색 모두 현재 K와 복원 참조 K의 전체 원소 예측 MSE를 최소화한다. V·잔차 양자화 후 오차·미래 정보는 선택에 사용하지 않는다. 층별 선택은 지도 공유 가정만 완화한 비교이며, 실행 가능한 공유 이동과 섞지 않는다.
4. **진행 판단:** 아래 기준으로 이 제한된 이동 방식에 후속 개발 비용을 쓸지만 판단한다. 통과해도 강한 동일 위치 학습 예측기/TempoKV식 기준선과 비교하고, 실제 dense 대응·독립 코드·bounded reference 운용을 설계하기 전에는 새 보류 FR 실험을 시작하지 않는다.

## 지표·비용·진행 기준

주 요약은 대상 프레임에서 각각 `||복원−BF16||₂ / max(||BF16||₂,1e−12)`로 잰 K/V 상대 L2의 평균이다. 층·프레임 쌍·청크를 동일 가중 평균해 프롬프트별로 보고한다. 원소 수나 프레임 수를 독립 표본 수로 부풀리지 않으며 p값은 계산하지 않는다. pre-RoPE K 오차와 원래 위치 적용 후 K 오차를 구분하고, 현재 단계에 실제 attention 읽기/출력 오차를 측정하지 않았다면 명시한다.

단순 동일 위치 잔차 대비 **공유 이동 팔의 K4V4 요약 오차가 단순 동일 위치와 경계 마스크를 맞춘 동일 위치 대조군 각각에 비해 두 프롬프트 모두 5% 이상 감소**하고, 모든 게이트·finite 검사가 통과하며 비용 산출이 완전할 때만 강한 기준선·더 풍부한 대응 개발로 진행한다. 5%는 통계적 유의성이나 영상 품질 기준이 아니라 작은 추가 투자를 위한 기준이다. 제한된 oracle에서만 좋아지면 공유 이동의 통과로 세지 않는다. 실패하면 이 전역 이동 변형을 정리하고 자동으로 보류 생성에 확대하지 않는다. 실패가 모든 움직임 정렬 표현의 부재를 증명하지는 않는다.

각 팔에서 다음을 함께 기록한다.

- 참조 anchor와 잔차의 code·scale·padding, 이동 dx/dy·참조 ID·필요한 escape/유효성 정보. 매 쌍의 참조 유지 비용을 포함하며 여러 쌍의 합과 동시에 살아 있는 최대치를 구분한다. 같은 참조가 두 번 저장되지 않았다면 중복 계상하지 않는다.
- **실제 byte container 저장 바이트**와 **저비트 packed 가상 추정치**를 별도 표로 공개한다. 공유 이동 메타데이터가 늘었는데 같은 명목 비트폭만 근거로 동일 rate라고 부르지 않는다. 실제 패킹·커널 속도 이득은 측정하지 않은 상태다.
- 이번 1차 구현은 대응 검색 시간과 encode+decode+지표 계산의 묶음 벽시계를 CUDA 동기화 후 기록한다. 워밍업/반복이 없는 계측 실행이며, anchor encode·참조 restore는 이 묶음에서 빠진다. 따라서 배포 지연이나 속도 개선 근거로 사용하지 않는다. 다음 단계로 진행할 경우 참조 복원·encode·decode를 분리한 반복 벤치마크를 먼저 추가한다. 원본 BF16 캡처 텐서는 진단 입력이며 배포 시 공짜 원본 버퍼로 사용할 수 없다. 캡처 파일 용량, peak allocated/reserved, 참조 유지량도 따로 기록한다.

선택 기준을 완화하거나 p0/p4 중 하나를 빼서 GO를 만들지 않는다. 구현 오류는 가설 실패와 구분한다. 이 개발 진단의 성공도 rate-matched 우월성·FR 품질 개선·전체 codec 신규성의 증거가 아니다. 강한 동일 위치 기준선, 실제 attention 읽기 오차, 메타데이터 포함 rate–distortion, 참조 eviction·복원 비용을 순서대로 닫아야 한다.

대형 캡처·진단 원본은 `~/sfq_data` 아래 새 전용 폴더에 두고 기존 실험 자료와 분리한다. 작은 요약·프로토콜/source/artifact 해시·진행 상태를 보존한다. 최종 저장 경로와 CLI 명령은 runner가 확정한 뒤 실행 안내에 기재한다.

실행 확인: `bash ~/Quantization/tools/watch_progress.sh 0`, `tail -F ~/sfq_data/motion_codec.log`. 캡처 2회 후 분석을 순차 실행한다. 결과는 `src/experiments/motion_codec_development/`, 캡처는 `~/sfq_data/motion_codec/`에 둔다. 이 단계의 map은 실제 코어에서 K/V·층마다 4바이트씩 중복 저장하고 그 비용을 그대로 센다. 참조쌍 ID·기하·비트폭은 고정 프로토콜/파일 헤더이며, 나중에 일반 codec으로 만들면 직렬화 헤더 비용도 따로 세어야 한다.

### 측정 전 v2 수정 경위

초기 커밋 `02bb705` 뒤 합성 난수 모의 검토에서 zero-predictor 경계만으로 잔차 오차가 줄 수 있음을 발견했다. 실제 프롬프트의 K/V 캡처가 하나도 저장되기 전 모델 로딩 중 실행을 중단했고, 경계 일치 동일 위치 대조군과 그 대비 5% 조건을 추가했다. 첫 실행의 작업 경로 오류도 캡처 전에 발견하여 `src/`에서 실행하도록 수정했다. 실제 진단 수치를 보고 조건을 바꾼 것이 아니다. 경계 대조군은 기본 zero-shift 헤더 외 마스크용 int16 dy/dx 4바이트를 K/V마다 추가 집계한다.
