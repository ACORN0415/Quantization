2026-11-04 — 혼합정밀 SVD·GPU 양자화의 영상/월드 생성 적용 검토

판단: NVIDIA의 FP32→FP64 SVD 정련을 현재 KV/TT 코덱에 직접 넣을 근거는 없다.
활용할 부분은 필요한 정확도에 맞춘 계산, 양자화 이후 표현에 대한 보정,
저장 단위와 실행 단위를 함께 설계하는 원칙이다. 이것만으로 새 연구의 신규성이 성립하지는 않는다.
다음 자원은 TT 재개보다 기존 가중치·활성화 양자화 경로의 실제 청크 형상 비용 확인에 배정하는 편이 낫다.
이번에는 문헌·코드·저장 자료 확인만 했다. 새 GPU 실험, CPU SVD 실험, 모델 다운로드, 커널 빌드 모두 0회다.

실행·검토 범위

- 실제 Claude Fable 검토 2건: SVD task_8cb5567e6743 / ctx_99406bf8a131;
  GPU 시스템 task_beeb10044069 / ctx_d3c6fd352771. 원문은 FABLE_*_REVIEW_KO.txt에 수정 없이 보존했다.
- 두 검토는 최신 채팅 표시 요청 전에 Quantization의 터미널에서 시작했다.
  새 root/Fable 채팅 개설은 성공했지만 자동 Task 연결은 terminal_handle_stale로 실패했다.
  아래 조정자의 정정·통합 설명까지 Fable이 다시 승인했다고 표시하지 않는다.
- 실제 장비 확인: RTX 4090 24GB, SM89. 사용자가 인용한 RTX 3080에서 실행한 검토가 아니다.
- 개발 입력 12개는 현재 존재하며 기록된 SHA256과 전부 일치한다(input_availability.json).
  이는 codec_order가 참조하는 입력 범위다. 삭제된 QVG 60.141GiB attention 테이프의 복구/재검증이 아니다.
- 현재 자료는 주로 Self-Forcing 영상 생성이다. 행동 조건 월드 모델의 제어 반응·장기 상태 일관성은 평가하지 않았다.

1. NVIDIA SVD: 무엇을 해결하며, 왜 바로 이식하지 않는가

공식 발표는 2026-06-29다. FP32-quality 초기 SVD를 원본 행렬을 사용하는 반복 정련으로
FP64-quality까지 개선한다. 가까운 특이값 군집 처리와 복소수 확장이 핵심이다.
비교 대상은 FP64-quality cuSolver SVD다. 현재 FP32 SVD보다 5.2배 빠르다는 결과가 아니다.
최대 5.2배는 RTX PRO 6000 Blackwell WSE의 복소수·pattern(4)·에뮬레이션 FP64 조건,
표 2의 n=2048 사례에서 1.17/0.225이다. B200의 표 3 특정 사례는 실수 1.0배·복소수 0.9배다.
실험은 CUDA 13.2와 prerelease cuSolver 13.3 U1을 사용한다. 공개 구현은 이번 범위에서 찾지 못했다.
출처: https://research.nvidia.com/publication/2026-06_mixed-precision-svd-gpus-ogita-aishima-iterative-refinement
PDF Algorithm 1·4, §5, Table 2·3. PDF 해시는 source_manifest.json에 기록했다.

우리 tools/tt_rank_codec.py는 v.float()로 올리고 codec_order_core.decompose의 TT 경로는
full_matrices=False SVD 두 번 뒤 인자를 저장한다. 2–4비트 저장 손실을 FP64 정련이 자동 제거하지 않는다.
오차를 구분하는 항등식은 A-Aq=(A-Ar)+(Ar-Ar_num)+(Ar_num-Aq)다.
각각 rank 절단, 분해 계산, 인자 저장·복원에 해당한다. 제곱 오차를 독립된 양수 항으로 더할 수는 없다.
원본 A를 버린 뒤에는 그 A에 대한 정련 잔차를 이 알고리즘으로 계산할 수 없다.
반대로 원본이 있는 encode 시점의 보정은 가능하지만 비용과 저장 오차를 함께 따져야 한다.

기존 TT p0·2bit·rank192 행은 생성 558.991초, encode 432.084초다.
encode는 분해와 저장 등을 포함하므로 이를 순수 SVD 432초로 쓰지 않는다.
FP64 정련의 품질 이득도, 기존 FP32 경로 대비 실제 속도도 측정하지 않았다.
현재 TT 종료의 이유였던 품질/비용 교환관계를 해결했다는 근거는 없다.
근거: tools/tt_rank_codec.py:23, tools/codec_order_core.py:139,
src/experiments/tt_kv_final/summary.csv 및 REPORT_KO.md.

장비 관련 추가 확인: 현재 cuBLAS 13.4 지원표는 FP64 fixed-point emulation에 compute capability
8.x를 포함한다. 따라서 Ada/Ampere에서 원천적으로 불가능하다고 단정하면 안 된다.
다만 과거 실험 환경 cu124에서 바로 활성화된다는 뜻도, 4090/3080에서 Blackwell 성능을 낸다는 뜻도 아니다.
실제 라이브러리·입력 형상·작업 공간·fallback 여부는 실행 검증 전이다.
출처: https://docs.nvidia.com/cuda/cublas/index.html#floating-point-emulation

2. 요청한 네 논문의 적용 판단

AlignQuant — GPU 타일 단위 설계 참고, 현재 공개 버전의 직접 사용은 보류.
64×64 가중치 타일의 W4/W8 배분과 저장·실행을 연결하며 A8과 공통 INT8 연산을 사용한다.
prefill과 decode 경로가 모두 있으므로 decode 전용이라고 부르면 틀린다.
논문은 RTX4090 결과도 제시한다. 그러나 고정 커밋의 extension.py:209는 SM80 이외를 거부한다.
논문 수치와 공개 버전으로 즉시 재현 가능한 범위를 분리해야 한다.
논문: https://arxiv.org/html/2610.07457v1
코드: https://github.com/HanzhiZhang-Ulrica/AlignQuant/blob/0ad8206971fbfe0e5a6c573de3bae96d572e46d7/alignquant/kernels/cuda/extension.py#L208

MixLLM — 가중치·활성화 경로의 조건부 비교 대상.
전역 출력 특성 단위 정밀도 배분과 2단계 역양자화/INT8 연산을 함께 설계한다.
대표 W4.4A8은 90% W4+10% W8이며 4.4는 메타데이터까지 포함한 전체 저장 비트가 아니다.
MLSys2026 논문이지만 최초 공개는 2024년이다. 큰 토큰 수의 GEMM도 평가하므로 M=1 전용이 아니다.
고정 Makefile은 sm_80 대상이다. 이것만으로 SM89 실행 불가능을 증명하지 않으며,
우리 GPU·M=4680 형상에서의 실행/성능은 미검증이다. 논문의 LLM 보정값을 영상 모델에 재사용하지 않는다.
논문: https://proceedings.mlsys.org/paper_files/paper/2026/hash/a66caa1703fe34705a4368c3014c1966-Abstract-Conference.html
코드: https://github.com/microsoft/MixLLM/blob/00263510f9760d3a1d958a388e0e7c25961a7d59/mixllm/kernels/Makefile

Kitty — KV 표현은 가까우나 공개 attention 실행 형상이 다르다.
K 일부 채널을 4비트, 나머지를 2비트로 두고 2비트 평면 두 개에 표현한다.
채널 선택은 페이지 양자화 시점에 수행된다. 모든 과거 페이지를 매번 재선택하는 방식으로 해석하지 않는다.
공개 kitty_attention_forward는 t_query==1을 요구하고 QK 점수 버퍼를 만든 뒤 softmax·SV를 호출한다.
따라서 Q=4680인 우리 청크 실행에 바로 넣을 수 있는 완전 융합 attention 커널이 아니다.
같은 메모리 상한에서 batch를 늘린 처리량 향상을 batch1 생성 지연 향상으로 옮기지도 않는다.
MLSys2026, 최초 공개는 2025년. 실제 K/V·scale·채널 인덱스·고정밀 버퍼를 합산해야 한다.
논문: https://proceedings.mlsys.org/paper_files/paper/2026/hash/e4d8d1b5120be349d3fff8878650cf45-Abstract-Conference.html
코드: https://github.com/Summer-Summer/Kitty/blob/dfd2c07b407d6b407179359207c612ab631f3ed1/src/kitty/kvcache/kernels/kitty_attention.py#L410

FIGFLEX — 기존 GPU 적용 대상이 아닌 별도 가속기 연구.
FP-INT 연산 경로와 혼합정밀 양자화기를 함께 설계한다. 하드웨어 효율 결과는 합성·모델링 평가다.
이 수치를 RTX4090의 커널 속도 향상으로 해석하지 않는다.
GPTQ 보상 후 남는 오차를 배분에 사용하고 스케일의 수치 범위를 관리한다는 원칙은 참고할 수 있다.
하지만 그 원칙 자체도 해당 논문의 기여이므로 우리가 새 아이디어라고 주장할 수 없다.
논문: https://arxiv.org/html/2610.30480v1

3. SVD·정련에서 얻는 추가 인사이트 3개

S1. 최종 표현에 필요한 만큼만 분해를 정확히 한다.
가설: 현재 저비트 표현에서는 FP64까지 올려 얻는 품질보다 rank·scale·표현을 바꿔 얻는 품질이 클 수 있다.
이는 이번에 측정한 결론이 아니다. FP32의 단위 반올림 오차를 인자 양자화 D 비율과 나눠
10^5배 차이라고 계산할 수 없다. 특이벡터 민감도와 이후 양자화의 불연속성도 있다.
단순 기준선: 현재 FP32 SVD, 같은 rank의 FP64 참조, 필요한 경우 기존 range 방식.
최소 확인: 보존된 작은 개발 입력에서 같은 형상·rank·패킹·저장 dtype으로 최종 복원/출력 오차와 비용을 비교.
직교성이나 행렬 잔차 개선만 있고 실제 저장 후 이득이 없으면 정밀도 상향 방향은 종료한다.
우선순위: 낮음. TT 재개를 위한 검사가 아니며 이번에는 실행하지 않았다.

S2. 특이값 군집은 수치 안정성과 실행 비용을 함께 바꾼다.
논문 근거: 가까운 특이값은 별도 군집 sub-SVD를 필요로 한다.
가설: FP16/BF16 초기 분해로 더 싸게 시작하면 군집 처리량과 정련 비용이 커져 이득이 사라질 수 있다.
평균 인접 간격만 보고 모든 값이 하나의 큰 군집이라고 결론 내리면 안 된다.
최소 확인: 실제 스펙트럼에서 논문의 군집 기준에 따른 연결된 군집 크기와 r 경계의 포함 여부를 먼저 확인한다.
그다음에야 해당 작은 sub-SVD들의 비용과 전체 FP32 기준 비용을 비교한다.
가장 단순한 대조는 FP32 thin SVD와 기존 randomized range다. 군집 개수/고립 비율만으로 성능 채택하지 않는다.
수치적으로 안전하면서 총비용이 낮다는 근거가 없으면 중단한다. 현재 스펙트럼/시간은 미측정이다.

S3. 보정은 실제로 저장된 인자를 대상으로 하며, 가능한 한 준비 단계에서 비용을 지불한다.
예: 외곽 인자를 먼저 양자화해 고정한 뒤 원본이 존재하는 시점에 가운데 인자를 재적합할 수 있다.
보정 인자도 다시 양자화한 최종 결과를 평가해야 한다. 양자화 전 최소제곱 감소만으로 성공이라 하지 않는다.
이는 양자화 인지 저랭크 근사·ALS와 가까우며 새 방법이 확정된 것이 아니다.
가중치는 한 번 준비한 결과를 여러 생성에 재사용할 수 있어, 청크마다 SVD를 수행하는 KV와 비용 구조가 다르다.
가까운 비교: SVDQuant/Nunchaku, LQER/QERA, SVD-LLM. QuantWM은 영상 K의 저랭크 attention 보상까지 다룬다.
최소 확인: 동일 실제 바이트의 직접 양자화, 단순 scale 재적합, 기존 저랭크 보정과 최종 출력 오차/준비·추론비용 비교.
단순 대조를 이기지 못하거나 온라인 보정 비용을 회수하지 못하면 종료. 현재 TT 후보는 재개하지 않는다.
출처: https://arxiv.org/abs/2411.05007 ; https://arxiv.org/abs/2402.02446 ;
https://arxiv.org/abs/2410.06040 ; https://arxiv.org/abs/2403.07378 ; https://arxiv.org/html/2609.26425v1

4. 혼합정밀 GPU 시스템에서 얻는 추가 인사이트 3개

G1. 비트를 배분하기 전에 메타데이터와 패딩에 쓰는 예산을 확인한다.
관측: 개발 packed 코덱(tools/change_mixed_core.py:177)의 g16·FP16 maximum 한 개는
원소당 scale 정보 1비트다. 이상적인 긴 tensor의 INT2는
코드+scale만으로 이미 평균 3비트다. padding, offset, 인덱스, allocator는 추가 항이다.
src/kvq/quant.py의 일반 int8 컨테이너를 실제 2비트 패킹으로 세지 않는다.
Kitty형 K에서 비율 f를 4비트로, 나머지를 2비트로 두면 코드 평균은 2+2f다.
그룹을 키워 scale 예산을 줄이면 정밀도 상향에 쓸 여지가 있지만 outlier 범위 증가로 오차가 커질 수도 있다.
최소 비교: 고정 실제 바이트에서 큰 그룹 균일 정밀도, 선택 채널 상향, 무작위 채널 상향을 비교한다.
단순 그룹 변경/균일 정밀도와 같은 결과면 선택기를 만들지 않는다. scale·인덱스·패딩까지 예산에 넣는다.
현재 관측은 저장 형식뿐이며, 우리 입력에서 품질 이득은 미검증이다.
Kitty·KIVI·QuantWM과 가까워 단순 영상 적용을 신규성으로 보지 않는다.

G2. 저장 그룹, 캐시 수명, GPU 타일은 서로 다른 제약이다.
우리 기록에서 청크 길이는 4680이며 Kitty 기본 페이지 128로 나누면 나머지가 72다.
120/130 같은 청크 약수를 선택하면 경계 문제는 줄지만 GPU 타일 효율이 나빠질 수 있다.
128로 padding하면 37×128=4736, 추가 토큰은 56(약 1.20%)이다. 이 비용을 감수하는 것이
새로운 임의 크기 커널을 만드는 것보다 쌀 수도 있다. 마지막 부분 페이지 유지도 강한 대조군이다.
최소 비교: 기존 청크 고정 정책 안에서 padding·부분 페이지·지원되는 정렬 방식의 실제 바이트와 실행 비용을 비교.
청크 경계를 넘는다는 이유만으로 재양자화가 필수라고 가정하지 않는다.
인접 청크의 중요 채널이 바뀌어도 페이지별 다른 인덱스를 저장할 수 있으므로 그것만으로 실패 판정하지 않는다.
새 배치 정책 없이 단순 padding으로 충분하면 레이아웃 연구를 종료한다.
이는 완료한 반복/단회 연구를 다시 시작하는 제안이 아니라 기존 설계를 쓸 때의 이식 조건이다.

G3. 정밀도 배분의 목표는 실제 큰-query 실행의 전체 시간이어야 한다.
관측: 기존 profile_B는 생성 24.626초, self_attention 구간 11.237초, decode+layout 0.578초다.
구간은 중첩될 수 있으며 나머지를 linear 시간으로 추정할 수 없다. linear 상세 프로파일은 이 파일에 없다.
가설: 가중치·활성화 저정밀 커널의 이득이 남아 있을 수 있지만, 실제 M/N/K와 정규화·변환 비용이 결정한다.
단순 기준선은 BF16과 기존 W8A8이며, 이후에만 MixLLM/AlignQuant의 혼합 배분을 고려한다.
ViDiT-Q는 영상 DiT의 조건·시간 단계 변화와 혼합정밀을 이미 다룬다. SVDQuant는 저랭크 보정 경로의 융합 비용까지 다룬다.
따라서 '단계마다 정밀도를 바꾼다'는 일반론은 신규성이 없다.
남을 수 있는 질문은 단일 packed 가중치 표현으로 denoise와 캐시 기록을 함께 보정했을 때,
기존 단순 방식보다 품질-전체시간 교환관계를 개선하는가이다. 현재 그 실패는 관측하지 않았다.
최소 진단: 한 대표 청크의 연산자/커널 비용과 실제 지원되는 W8A8 경로를 확인한다.
커널 속도만 보고 판단하지 않고 변환·임시 버퍼·추가 weight 사본을 포함한다.
분해 가능한 시간 비중 p, 해당 부분 속도 배수 s, 추가 시간 비율 h라면 예상 시간비는
T_new/T_old≈(1-p)+p/s+h다. 중첩이 있으면 이 식도 근사이며 전체 경과시간으로 확인해야 한다.
단순 W8A8이 충분하거나 실제 전체시간 이득이 측정 잡음 수준이면 새 혼합 선택기를 만들지 않는다.
출처: https://arxiv.org/html/2406.02540v3 ; https://arxiv.org/html/2411.05007v1

5. Fable 검토에 대한 조정자의 수정·유지 판단

수용: FP64 SVD 직접 이식 비추천, 실제 원본이 필요한 점, 저장/연산/형상 조건 확인,
강한 단순 대조군부터 비교, TT 종료 유지, 행동 조건 월드 모델로 결론을 확대하지 않기.

수정/제외:
- '우리 SVD 오차보다 10^5배 크다', 'FP64가 어떤 수치도 바꾸지 못한다': 실제 동등 척도의 측정이 없어 제외.
  논문 backward error의 n 정규화와 우리 post-Wo D/RTN 비율도 서로 다르다.
- 'encode 432초=SVD 432초': encode 집계만 확인됐으며 순수 SVD 비중은 분리하지 않았다.
- '네 논문 모두 M=1 decode 전용': AlignQuant의 prefill 경로와 MixLLM 큰-M 실험 때문에 수정.
- 'SM80 빌드=SM89에서 불가능': AlignQuant의 명시적 거부와 MixLLM의 빌드 대상 지정을 구분.
- Ada emulation: 현재 cuBLAS13.4 공식 표에 8.x 지원이 있어 지원 불가로 단정하지 않는다. 로컬 실행은 미확인.
- 고립 특이값 10%, 채널 변화 30%, 층 salience 3배 등의 제안 수치는 근거 있는 보편 종료 조건이 아니다.
  특히 채널 변화가 커도 페이지별 선택이 가능하고, salience 범위만으로 실제 최선 배분을 결정할 수 없다.
- '현재 메모리가 병목이 아니다': 창/정책별로 달라진다. profile_B 자체 peak allocated는
  11248259584 bytes(약 10.48GiB), reserved 약 13.20GiB다. 다른 실행의 6.8GiB를 같은 실행으로 쓰지 않는다.
- 메모리 압축만 가능/속도 이득 불가능이라는 일반화도 하지 않는다. 임시 버퍼와 전송이 달라질 수 있다.
  다만 Kitty의 특정 처리량 수치가 우리 batch1·큰 query 조건을 보장하지 않는다는 판단은 유지한다.

6. 선택과 종료 범위

이번 문헌 검토는 다섯 요청 논문, 관련 SVDQuant·ViDiT-Q·QuantWM·저랭크 보정 계열,
세 공개 구현의 고정 버전 및 기존 저장 자료 대조로 종료한다. 새 알고리즘 채택은 하지 않는다.
다음 방향 하나는 G3: 기존 가중치·활성화 양자화 경로의 비용 진단이다.
이것은 신규성 승인도 커널 이식 착수도 아니다. GPU 진단을 별도로 진행한다면
환경/기준선 확인까지 60분, 모델 입력 수집은 대표 청크 최대 1개(현재 schedule 기준 5 forward)로 제한하고,
전체 영상 생성·추가 모델·새 커널 개발로 확대하지 않는다. 실제 비교가 가능한 경로가 없으면 이식부터 하지 않는다.
후속 실행 전 수치 정확성 기준, 워밍업/반복 순서, 측정 잡음과 최소 유의 이득을 고정한다.
이번 요청에서는 그 실행을 하지 않았다.

Fable 시스템 검토자는 G1에 해당하는 K 채널 boost를 우선 추천했다.
나는 추가 비용 지출 순서를 G3로 바꾼다. 이유는 QuantWM이 영상 K 민감도와 보상을 이미 직접 다루고,
우리에게 지금 빠진 증거는 새 채널 선택기보다 실제 linear 경로에서 남은 시간이기 때문이다.
이 이견은 연구 결과가 아니라 다음 자원의 배분 판단이다.
