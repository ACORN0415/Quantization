   B-1 packed의 첫 청크 페이지 제거로 결정을 재사용하는 것은 코덱 구조상 정당하다.
   무개입 gate → 양자화 비교 순서는 올바르며, 통과/실패 뒤 다음 단계 논리도 등록 원칙과 맞는다.
   다만 이 실험이 답하는 것은 "같은 바이트에서 S가 U보다 출력 오차가 작은가"뿐이고,
   "과거 K를 ~3bit로 줄여도 되는가"는 답하지 않는다(5절). 통과해도 그 범위로 읽어야 한다.

2. 직접 확인한 근거
 - 퇴거 로직 causal_model.py:224~257. local 창이고 current_end > global_end, 새 4680 + local_end 32760 > 용량이면
   num_evicted=4680, sink 이후 토큰을 왼쪽으로 roll(clone 사용), 새 K/V를 끝에 기록, attention은 [local_end-32760:local_end]
   = 전체 32760 토큰. sink_size=0이면 정확히 c1..c6 + c7이다. c7 call0에서만 퇴거가 일어나고 call1~4는 current_end==global_end
   이므로 현재 슬롯만 덮어쓴다(247~250행). 따라서 c7 call0의 K prefix[:28080] == c6 call4 캡처 K[4680:]라는 gate는 코드상 성립해야 하며,
   sink_size≠0이면 이 gate가 스스로 실패하므로 가정 검출 수단으로 적절하다.
 - 용량 32760 = 7청크는 lockstep.bf16_cache(local_attn_size×frame_seq_length)와 B-1 캡처의 k.shape[1]==32760 assert에서 추론.
   local_attn_size=21, sink_size=0 수치 자체는 설정 파일에서 직접 읽지 못했다(6절).
 - call 의미: lockstep.run_chunk는 denoising 단계 수만큼 generator를 호출하고 마지막에 context_noise로 한 번 더 호출한다.
   B-1 probe의 (6,4)는 context 기록 호출, (7,0)은 c7의 첫(최대 노이즈) denoising 단계다. 캐시에 남는 c6 K는 context 호출의 K이므로
   B-1 packed(c0..c6)의 c1..c6 부분을 c7의 과거로 재사용하는 것은 실제 경로와 일치한다.
 - 페이지 제거 재사용: encode의 offset/scale/mask/score는 (page,head,channel) 단위로 완전히 국소적이며 전역 통계가 없다.
   4680/120=39, 4680/156=30 페이지로 청크 경계가 페이지 경계다. 페이지당 바이트가 모두 정수(120: meta 6,144, mask 192, low 46,080,
   extra 22,680, INT3 stream 69,120; 156: meta 6,144(페이지 길이와 무관), INT3 stream 89,856)
   이므로 바이트 슬라이스가 가능하다. 단 decode는 헤더 n으로 p를 계산하므로 n=28080 새 헤더를 써야 한다.
   등록문의 "독립 복원 뒤 기존 복원 suffix와 전원소 바이트 일치" 검사는 이 재직렬화 오류를 정확히 잡는다.
 - 예상 바이트(n=28080, h=12, d=128, 등록 전 고정값으로 기록해 두길 권고):
   U120 = 28 + 234·12·128·4 + 43,130,880·3/8 = 17,611,804
   U156 = 28 + 180·12·128·4 + 16,174,080 = 17,280,028

   B-1과 같은 7/6 비율이며 S는 U120보다 39,312B 작고 U156보다 292,464B 크다.
 - attention 경로: attention.py의 flash varlen 호출, softmax_scale=None(1/sqrt(128)), causal=False, 추가 마스크 없음.
   재생이 같은 함수·같은 형상·같은 GPU·같은 dtype이면 forward는 통상 결정적이나 커널 버전은 미확인(6절).
 - 지표: post-W_o normalized squared error = Σ(cand−ref)²/Σref², FP64 CPU. 전체 4680 query. 보조 FP32는 32 query.
   진행 조건: 프롬프트별 S < U120·U156 각각 10% 이상, S < R, 3층 중 2층 이상 S < 두 U, FP32 보조도 두 U보다 작음.

3. 지적 사항
 (a) 평가 형상의 한계를 등록에 명시: c7 call0은 현재 청크가 최대 노이즈인 첫 denoising 단계다. 이 시점의 query는 과거 의존도가
     가장 낮을 가능성이 있고, 세부가 들어오는 call1~3의 attention 분포는 다를 수 있다. call0 한정 결과를 "c7 전체"로 쓰지 말고
     "c7 첫 단계"로 쓴다. call1~3 캡처는 forward 추가 0회지만 재생 예산 30회를 넘기므로 이번 평가에 넣지 않는 것이 맞다.
     저장만 해 두면 통과 후 다음 단계의 싼 사전 확인이 되지만, 이는 선택 사항이며 B-2 판정에는 쓰지 않는다.
 (b) 기준의 해석: normalized squared error는 query·head 합산이라 오차 큰 query가 지배하고, B-1 TV(평균)와 집계가 다르다.
     squared 기준 10%는 RMS 기준 약 5%다. 사전 고정이므로 문제없으나 B-1 TV 수치와 직접 비교해 "일관"이라고 쓰지 않는다.
     3층 단순평균은 B-1과 같이 l0의 큰 상대 개선이 l14 악화를 가릴 수 있다. "2층 이상" 조건이 보완하므로 층별 값 필수 보고 유지.
 (c) 유효성 바닥 사전 고정(추가 실험 없음): 현재 K와 전체 V가 BF16이고 attention 질량의 상당 부분이 현재 청크에 갈 수 있어
     모든 팔의 절대 오차가 B-1보다 훨씬 작아진다. 팔 간 차이가 BF16 재생 자체의 반올림 바닥(normalized sq로 1e-5 근방 예상)에
     가까우면 10% 비교는 의미가 없다. 이미 있는 FP32 보조(32 query)에서 BF16 원본 native 출력 vs FP32 계산의 normalized sq error를
     바닥으로 기록하고, 네 팔의 평균 오차가 그 바닥의 10배 미만이면 "판단 불가"로 사전 고정하길 권고한다. 비용 0.
 (d) 무개입 gate 운영: "모델 해제 뒤 재생"은 GPU에서 같은 flash 함수로 해야 한다(CPU 재생은 다른 커널이라 바이트 일치 불가).
     캡처 텐서는 contiguous clone으로 저장하고 재생 시 같은 device·dtype·형상을 쓴다. torch/flash_attn 버전을 manifest에 기록.
     gate 실패 시 "판단 불가"로 끝내는 규칙은 맞으나, 실패 원인이 stride/커널 선택 같은 양성 원인인지 한 번 분리 확인(6회 한도 내)은 허용된다.
 (e) 표현: "기준을 못 넘으면 종료"는 S가 U보다 나쁘다는 뜻이 아니라 10% 개발 문턱 미달이라는 뜻이다. 보고에서 두 경우를 구분한다.
     또한 S120의 K 바이트 우위는 U120 대비이며 U156 대비는 더 크다는 B-1 정정을 그대로 유지한다.

4. 강한 단순 기준선 점검
 - U120(동일 page, 동일 per-channel min/max INT3)은 KIVI식 per-channel 키 양자화의 직접 대응이며 S와 바이트가 거의 같아 적절하다.
 - R120은 선택기 효과를 분리하는 대조로 충분하다. 추가 팔은 필요 없다. 바이트는 U156 < S/R120 < U120 순이며
   B-1과 같은 방식으로 실측값을 명시하면 된다.

5. 가장 강한 반론과 대안 1개
 반론: B-2는 "같은 바이트에서 S가 U보다 낫다"만 검정한다. 과거 K만 3bit로 줄이고 V·현재 K는 BF16이므로 층당 KV 바이트 절감은
 약 34%(BF16 201.3MB → 약 132.6MB, 내 계산)이고 S와 U120의 바이트 차이는 0.2%다. S의 가치는 바이트가 아니라 "같은 바이트에서의
 오차 감소"뿐인데, U120 자체의 출력 오차가 생성 품질에 무해한 수준이라면 S의 추가 개발 가치는 사라지고, 반대로 U120이 이미
 유해하면 S의 10~17% 상대 개선으로 구제되는지도 불명이다. 즉 B-2 통과는 다음 단계의 필요조건이지 충분조건이 아니다.
 대안(B-2에 팔 추가 아님, 다음 단계 등록 권고): 통과 시 등록할 생성/자원 판별에서 "과거 K BF16(무양자화)"를 상한 기준으로 두고,
 U120의 품질 손실이 사전 고정 허용치 안이면 S 개발을 종료하는 조건을 함께 고정하라. 이 조건이 없으면 S 대 U 비교만 반복하게 된다.

6. 주장 범위
 말할 수 있는 것(통과 시): 두 개발 프롬프트, 3층, c7 첫 denoising 단계, 고정 코덱에서 native BF16 attention+W_o 출력의 상대 오차가
 S120에서 균일 INT3보다 작다. 말할 수 없는 것: 다른 timestep·청크·층, 생성 품질, GPU 속도·peak, OOM 해결, 신규성(Kitty/QuantWM 응용).
