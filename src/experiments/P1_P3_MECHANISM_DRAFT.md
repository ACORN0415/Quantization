# P1/P3 품질 차이의 메커니즘 분석 계획 v0.1

상태: **실행 전 기획 초안. 사전 등록 봉인이 아니며 대규모 실행을 시작하지 않았다.**
기존 80개 실험의 코드·계획·주지표를 바꾸지 않는다. 새 구현은 별도 경로에 둔다.
개발 검증과 시간·메모리 실측을 마친 후 최종 구현·계획·프롬프트·분석 코드의 해시를
새로 봉인해야 한다. 그 전에는 아래 새 보류 프롬프트로 BF16 생성조차 하지 않는다.

## 1. 연구 질문과 가능한 결론

출발점은 같은 명목 비트폭에서 P3가 P1보다 후반 표본 프레임 MUSIQ가 높았다는 결과다.
새 질문은 **P1에서 eviction 후 양자화 그룹이 재편되는 것을 막으면, 과거 KV의 추가 변화와
후반 영상 품질 저하가 줄어드는가?**다. 우선 INT4를 대상으로 한다.

분리해야 할 세 과정은 다음과 같다.

1. 같은 값·같은 구성의 그룹을 다시 양자화하는 연산 자체.
2. eviction으로 그룹 구성원이 바뀌는 과정.
3. 현재 청크의 새 BF16 쓰기가 과거 토큰과 공유하는 그룹의 스케일을 바꾸는 과정.

기존 코드의 P1과 P3 모두 각 attention 호출에서 현재 K/V는 새 BF16 쓰기로 읽는다.
P1은 attention 뒤 전체 버퍼를 encode하고, P3는 이전 pending 청크를 과거로 넘길 때 encode한다.
따라서 현재 attention의 BF16 여부를 두 정책의 독립적인 차이로 가정하지 않는다.
인과 주장도 “새 저장 개입의 효과”부터 평가한다. 단일 요인으로 P3의 모든 우위를
설명했다거나, 새 양자화 알고리즘·같은 메모리 예산의 우위를 입증했다고 하지 않는다.

## 2. 먼저 할 개발 진단: 같은 입력, 다른 저장 동작

기존 본 실험의 p00/p04, 시드 101/202를 **이 계획의 개발용 데이터로만** 사용한다.
이 영상의 결과는 이미 알려져 있으므로 새 확증 표본으로 세지 않는다.
새 보류 프롬프트는 개발에 사용하지 않는다.

BF16 실행의 원래 쓰기 순서를 그대로 재생한다. 42청크 × 청크당 5호출 × 30층이며,
호출별 start/global token ID, K/V, eviction, denoise/context-refresh 구분을 확인한다.
매 청크 BF16로 저장 상태를 초기화하지 않는다. 저장 이력은 끝까지 유지한다.
입력 쓰기만 같게 해 생성 피드백을 제거한다. 이 진단을 TF 영상 품질과 혼동하지 않는다.

### 저장 팔

| 이름 | 그룹 기준 | 과거의 encode | 목적 |
|---|---|---|---|
| L | 기존 P1의 물리 버퍼 위치 | 기존 P1 그대로, 호출 뒤 전체 버퍼 | 재현 기준 |
| A | 절대 토큰 ID의 16토큰 경계 | L과 같은 시점·횟수 | eviction에 따른 내부 그룹 재편 억제 |
| C-repeat | 청크마다 그룹 재시작 | 과거 청크를 각 attention 전에 재encode | 고정 그룹 반복 encode 진단 |
| C-once | C-repeat와 같은 청크 그룹 | 과거로 넘어갈 때 한 번 | 기존 P3 재현 기준 |

L/A 비교와 C-repeat/C-once 비교를 하나의 깨끗한 2×2 요인 실험이라고 부르지 않는다.
두 쌍은 encode 시점·청크 간 그룹 혼합이 다르다. 각 쌍 안에서 통제한 개입만 해석한다.

### A의 구체적인 그룹 규칙

청크당 4680토큰, 캐시 32760토큰, group=16, sink=0을 유지한다.
살아 있는 첫 토큰의 절대 ID를 s라 하면 버퍼 앞에 s mod 16개의 0을 논리적으로 덧붙여
encode하고, 복원 후 그 앞부분을 제거한다. 오른쪽에는 정렬에 필요한 0만 붙인다.
이는 attention에 보이는 토큰 수·순서·창을 바꾸지 않는다.

eviction 전에는 s=0이어서 L과 A가 같다. 이후 s mod 16은 0/8로 번갈아 바뀐다.
A는 내부의 완전한 그룹에 속한 절대 토큰 ID 집합을 유지한다. 첫 그룹에서 이미
퇴거된 구성원은 0으로 대체하므로, **첫 부분 그룹의 처리는 L과 다르며 추가 영향이 남는다.**
그 부분까지 제거한 순수한 위상 효과라고 주장하지 않는다.
이 설정에서 encode 길이는 양쪽 모두 32768이지만 실제 코드·스케일 바이트 수를 검증한다.

현재 쓰기와 과거를 공유하는 그룹도 주의한다. 창이 찬 L의 현재 청크 시작 위치는
32760−4680=28080으로 16에 정렬되지만, A에서는 절대 청크 시작의 나머지가 0/8로
바뀐다. 따라서 A가 현재 쓰기와 과거 8토큰을 함께 묶는 호출이 생길 수 있다.
L/A는 그룹 기준을 바꾸는 한 운영 개입이지만, 내부 그룹 안정화·부분 그룹·현재 쓰기
혼합의 효과가 함께 있을 수 있다. 같은 절대 토큰의 공통 내부 마스크를 정할 때 양쪽
그룹 중 하나라도 현재 쓰기/부분 그룹에 닿으면 그 토큰은 내부 집계에서 제외하고
별도 영역에 보존한다. 마스크는 토큰 ID만으로 정하고 오차 크기를 보고 고르지 않는다.
A의 품질 이득이 작거나 없어도 상쇄되는 경계 효과가 있을 수 있어 그룹 재편 가설 전체를 기각하지 않는다.

별도 first-partial-group 민감도 검사는 개발 데이터에서만 수행한다. 생존 토큰의 이전
코드·스케일을 유지하는 방법과 0 패딩 재encode를 비교해, 이 작은 영역이 내부 그룹의
이득보다 큰 영향을 주는지 본다. 최종 확증 팔의 규칙은 사전 등록 전에 하나로 고정한다.
기본 후보는 위 0 패딩 규칙이며, 다른 규칙을 채택하면 별도 개입으로 이름·계획을 수정한다.

### C-repeat/C-once의 통제

두 팔 모두 현재 청크는 원본 BF16 pending으로 유지하고 이전 pending을 과거로 넘기는
시점, 그룹 경계, 0 패딩, 창 크기, attention 입력 순서를 같게 한다.
C-repeat만 이미 저장된 과거 청크의 복원값을 같은 그룹으로 다시 encode한다.
입력이 고정된 반복 encode가 실제 BF16/FP16 스케일 구현에서도 항등인지 확인한다.
항등이면 그것 자체가 결과다. 더 큰 차이를 만들도록 연산이나 그룹을 바꾸지 않는다.
이 두 팔은 L의 현재-과거 혼합 그룹을 재현하지 않는다.

### 기록과 집계

- 살아남은 같은 절대 토큰만 대응시킨다. eviction으로 제거한 토큰은 오차 차이에 섞지 않는다.
- 매 encode 전후 변화량 ||복원후−encode직전||와 삽입 BF16 대비 상대 L2를 K/V별로 기록한다.
- 삽입 BF16 대비 SSE의 전후 차이는 부호를 보존한다. 재encode가 항상 오차를 늘린다고 가정하지 않는다.
- 영역을 내부의 완전한 과거 그룹, 현재 쓰기와 혼합된 그룹, 첫 부분 그룹으로 나눈다.
- 그룹 구성원 ID의 해시를 기록해 같은 그룹을 유지했다는 사실을 직접 검증한다.
- 청크 0–6의 eviction 전과 7–41의 이후를 구분하고, 청크·층·호출 종류별로 공개한다.
- 층별 값은 먼저 프롬프트/시드 안에서 집계한다. 30층·210호출을 독립 표본으로 세지 않는다.

선택 진단은 실제 query 방향의 K 오차 투영과 과거/현재 attention mass 변화다.
단순 KV L2와 품질 사이의 상관만으로 원인을 확정하지 않는다. query 진단은 실제
forward를 바꾸지 않는 관찰 경로가 bit-exact 출력을 유지할 때만 사용한다.
처음에는 고정한 층 0/7/14/22/29의 context-refresh 호출로 비용을 측정한다.

### 이 단계의 판단

- L/A 그룹 ID가 eviction 이후에도 의도대로 다르지 않으면 구현 실패다.
- 차이가 첫 부분 그룹이나 현재 쓰기 혼합 그룹에만 있으면 “내부 그룹 재편” 가설의
  근거가 약하다. 그 사실을 기록하고 내부 전체의 반복 손상이라고 보고하지 않는다.
- C-repeat/C-once가 일치하면 불필요한 재encode 횟수만으로 품질 차이를 설명하지 않는다.
- L/A 내부 차이가 재현되면 다음 단계로 그 개입의 실제 생성 품질 효과를 확인한다.
- 관찰 결과를 본 뒤 새 보류 프롬프트·주지표·표본 수를 조절하지 않는다. 개발 결과로
  설계를 바꿀 경우 변경 이력과 최종 계획을 봉인한 뒤 보류 측정을 시작한다.

## 3. 새 보류 데이터에서의 핵심 실험

기본 실행안은 새 프롬프트 12개 × 시드 303/404 × 네 팔 = **96개 생성 궤적**이다.
팔은 BF16, L, A, P3(C-once)다. INT4, 126잠재 프레임/42청크, 21프레임 창,
sink=0, residual=0, RTN group=16과 원래의 5호출/RNG 순서를 유지한다.
새 텍스트는 `mechanism_prompts_v0.txt`, 기계 판독 초안은 `mechanism_plan_draft.json`이다.
프롬프트 수는 정밀도/비용을 위한 고정 계획이지 검정력 보장이 아니다.

주 개입은 **A−L**이다. P3는 기존 정책의 기준점이며, 새 주 검정의 비교 팔을 결과를
본 뒤 A−P3 또는 다른 대비로 바꾸지 않는다. 이 단계에 TF/잡음 팔은 넣지 않는다.
저장 원인과 FR 품질의 연결을 먼저 확인해 실험 팔 증가를 막는다.
INT2는 우선 기존 데이터의 개발 진단에만 포함한다. 새 INT2 확증 실행은 별도 계획이다.

### 함께 측정할 지표

프레임 번호 t_c=12c−3(c>=1)를 청크 c의 VAE 매핑 기준 첫 픽셀 프레임으로 정의한다.
VAE의 시간축 수용영역 때문에 인과적으로 완전히 독립된 생성 경계는 아니다.
모든 점수는 같은 VAE·같은 raw RGB 변환에서 얻고 MP4를 주 분석 입력으로 쓰지 않는다.

**공동 주지표 두 개, 모두 A−L, 높을수록 좋음:**

1. 후반 청크 21–41의 **모든 raw 프레임** MUSIQ 평균: 픽셀 249–500, 총 252프레임.
2. 같은 후반 21개 경계의 raw 프레임 품질: 각 t_c−2부터 t_c+2까지 5프레임,
   총 105프레임의 MUSIQ 평균. 이 지표는 경계 부근의 프레임 품질이며 시간 품질 지표가 아니다.

이 두 지표는 중첩되며 독립적인 증거 두 개로 세지 않는다. Holm 보정에 독립성은 요구하지 않는다.

**주요 보조 진단:**

- 모든 청크 경계 41쌍(t_c−1→t_c)과 청크 내부 쌍을 구분한 raw 프레임 시간 잔차.
  내부 쌍은 기존 m_c−1→m_c, m_c→m_c+1(m_c=12c+3)을 고정한다.
- RAFT 설정은 이전 평가와 동일하다. 빈 mask는 null, coverage=0. 해당 창/팔의
  전체 표본 잔차 평균과 해당 짝 비교는 미정의로 두며 유한 사례만 평균내지 않는다.
- 경계 잔차−내부 잔차는 위치 차이의 기술 통계다. 실제 움직임이 다를 수 있어
  이 차이만으로 시간 품질이나 경계 인과효과를 입증하지 않는다.
- DINO 전체 프레임 특징 일관성, flow 크기, coverage와 원본 픽셀 차이를 함께 기록한다.
  DINO는 객체 동일성 지표로 부르지 않는다.
- 과거 KV L2, 그룹 재편 수, 영역별 encode 추가 변화량, peak VRAM·실행 시간·저장 바이트.
- BF16도 함께 평가해 절대 품질과 모델 자체의 긴 롤아웃 손상을 확인한다.

### 통계와 결과 판정

시드별 A−L을 계산하고 두 시드를 프롬프트 안에서 평균한다. 독립 단위는 n=12 프롬프트다.
각 주지표의 양측 정확 부호 반전 검정은 2^12개 부호 조합을 전부 사용한다.
귀무가설 아래 짝 차이의 대칭성/교환 가능성 가정과 편의 표본의 한계를 명시한다.
두 주 검정에 Holm, family alpha=.05를 적용한다.
각각 97.5% 프롬프트 클러스터 percentile bootstrap 구간(20,000회, seed 872341)을 보고한다.
작은 n에서 bootstrap 포함 확률은 근사다. 모든 대조와 음의 결과를 공개한다.
보조 지표는 95% 탐색 구간/기술 통계이며 확증 p값 주장을 하지 않는다.

- 두 주지표 모두 Holm 기준을 통과하고 효과가 양수일 때만 일반 후반/경계 부근
  품질 개선을 함께 지지한다고 표현한다. 하나만 통과하면 그 지표만 구분해 보고한다.
- 개발/재생 진단에서 내부 KV 변화 감소도 확인돼야 “그룹 재편 억제와 일관되는 근거”라고 한다.
  품질 개선만으로 내부 기전을 확정하거나 효과 전부를 이 원인에 귀속하지 않는다.
- A가 L보다 좋아도 P3의 모든 차이를 설명했다는 뜻은 아니다. 설명 비율/매개 비율은 계산하지 않는다.
- 유의하지 않으면 동등성이나 무효의 증명이 아니다. 표본 추가·시드 교체·팔 교체를 하지 않는다.

## 4. 실행 전에 통과해야 할 게이트

1. no-quant L/A/P3의 토큰 순서·attention 출력·42청크 최종 잠재 텐서가 BF16과 bit-exact.
2. INT4 L은 기존 P1, C-once는 기존 P3와 기존 개발 사례에서 bit-exact.
3. 동일 쓰기 재생에서 L/A는 첫 eviction 전까지 bit-exact.
4. A의 온전한 내부 그룹은 생존 절대 토큰 ID가 유지되고, 예상한 첫 부분 그룹만 예외.
5. C-repeat/C-once에 대해 상태·입력·연산 횟수 대조가 맞음. 일치를 강제하는 데이터 튜닝 금지.
6. 계측/비계측 실행 잠재 텐서가 bit-exact. 모델 RNG와 진단 RNG 분리.
7. raw 프레임 번호·501프레임·색 변환·전체/경계 집계 단위 테스트 및 손계산 대조.
8. 시간 잔차의 합성 이동·동일 프레임·빈 mask 테스트. 심한 손상 영상에서는 지표 타당성이 제한됨을 명시.
9. 아래 압축 민감도 검사를 마치고 새 주 분석은 raw로 고정. 압축 결과에 맞춰 지표를 선택하지 않음.
10. 실제 전체 크기 한 개발 사례로 시간·GPU/CPU peak·디스크 비용 실측.

단순 코드 오류는 개발 데이터에서 수정하고 게이트를 다시 실행한다.
봉인 이후 주 생성에서 비유한 값이 나오면 사례를 제외하지 않고 전체를 invalid pending review로 중지한다.
그 품질을 보고 양자화 강도나 그룹 규칙을 바꾸지 않는다. 인프라 재시도는 같은 설정으로 최대 2회.
보조 flow의 빈 mask는 위 사전 정의 결과이며 주 생성 실패와 구분한다.

## 5. 기존 결과의 압축 민감도 확인

기존 p00/p04 × 시드 101/202 × BF16 및 P1/P3의 INT4/INT2 FR = **20개 영상**을 사용한다.
p04에는 알려진 빈 mask 사례가 포함되며, 이는 대표 표본이 아닌 명시적 스트레스 검사다.
같은 보존 잠재 텐서를 같은 VAE로 raw 재디코딩하고 기존 MP4의 같은 501프레임과 비교한다.
subject, 잔차, flow, coverage의 raw−MP4 차이와 정책 대비의 방향/크기를 보고한다.
원래 raw MUSIQ 표본을 다시 계산해 기존 기록과 일치하는지도 확인한다.
이 검사는 선택한 20개 사례의 압축 민감도이며 전체 데이터의 압축 한계를 해소했다고 말하지 않는다.
raw를 임시 RGB 블록으로 처리하고 지표/해시를 저장한 뒤 그 블록만 삭제한다.
원본 잠재 텐서, 기존 MP4, 실패/미정의 기록은 삭제하지 않는다.

## 6. 오차 구조 대조군은 후순위의 별도 질문

핵심 L/A 비교와 동시에 여러 구조 대조군을 늘리지 않는다.
그룹 재편 분석을 마친 뒤 새 계획에서 같은 노름의 무작위 방향에 대해 다음을 분리한다.

- 같은 support에서 실제 오차 좌표를 순열해 분포/노름은 유지하고 위치 대응을 깨는 대조군.
- 그룹 평균 성분과 평균을 뺀 성분을 나누되, 임의의 재정규화가 다른 요인도 바꾼다는 점을 기록.
- query 방향 투영, K/V 분리, 시간적 상관을 독립적으로 통제할 수 있는지 개발 데이터에서 확인.

먼저 Gaussian이 무해하다고 가정하지 않는다. 기존 대조군은 이벤트별 절대 혁신 노름을
맞췄고, 누적 읽기 오차·query 투영·support 크기·동일 궤적을 맞춘 것은 아니다.
새 평균 편향 대조군 하나로 양자화의 해로운 구조를 전부 규명했다고 주장하지 않는다.
Jensen 편향과 청크 단위 단회 양자화는 이미 선행 연구에 있으므로 차별점을 먼저 검토한다.

## 7. 비용, 순서, 보고와 보관

| 순서 | 작업 | 종료 조건 |
|---|---|---|
| A | 기존 데이터의 저장 재생/압축 민감도 개발 진단 | 그룹 개입 유효성, 원본 게이트, 비용 확인 |
| B | 새 구현·분석 코드 완성, full-size 개발 게이트 | 모델/RNG/집계/결측 규칙 통과 |
| C | 최종 사전 등록 봉인 | 구현·분석·프롬프트·설정·게이트 해시 커밋, 보류 생성 0건 |
| D | 새 96개 궤적 실행 | 고정 순서 프롬프트→시드→BF16/L/A/P3, 전체 완료 |
| E | 통계·전 지표·한글 통합 보고·커밋/푸시 | 점 추정·구간·실패·부정 결과 모두 공개 |

시간은 아직 미측정이다. “하룻밤” 또는 이전 80케이스 시간을 그대로 적용하지 않는다.
초기 예산은 구현/검증 1–2작업일, GPU 실행 8–20시간의 **비보장 예산 범위**로 잡는다.
최종 봉인 전에 각 팔의 126프레임 생성+raw 평가 시간을 재고
24 × (t_BF16+t_L+t_A+t_P3) + 재생/집계 비용으로 수정한다.
예산을 넘으면 보류 데이터를 보기 전에 설계를 다시 고정하며 중간 효과를 보고 표본 수를 줄이지 않는다.

RAM/VRAM 절감: 한 GPU에 한 생성 팔씩 실행한다. 쓰기 재생 팔의 CPU 저장 상태가
RAM 예산 48GiB를 넘으면 층 0–5/6–11/12–17/18–23/24–29로 나눠 BF16을 결정적으로 재생한다.
5개 선별 층만 보고 전체 층의 기전이라고 결론 내리지 않는다. 층을 나눈 재실행의 비용도 측정한다.
전체 K/V 쓰기를 파일로 쌓지 않는다. 상태는 스트리밍하고 대표 그룹 예시의 원시 기록은
개발에서 정한 제한(합계 512MiB) 안에서 저장하며 모든 그룹의 카운터/집계는 보존한다.

raw 평가 전에는 generator/T5/attention 캐시를 해제하고 VAE 디코딩과 평가 모델의
동시 상주 비용을 개발 게이트에서 잰다. VAE 시간축 디코딩 설정·dtype·RGB 변환을
원본과 같게 유지하고, raw 블록 경계를 바꿔 디코딩 결과 자체가 달라지지 않는지도 확인한다.

로컬 최종 텐서 96개, 원본 MP4, raw 지표와 출처·소스/텐서/영상 해시를 보존한다.
일시 raw 프레임 블록과 재생 캐시만 작업 완료 후 지운다. raw 텐서는 중간 점수 때문에 삭제하지 않는다.
Git에는 계획·코드·소형 CSV/JSON·그림·보고서만 넣고 모델 라이선스·출처를 유지한다.
새 진행 상태는 기존 CLI에서 별도 연구 ID로 표시하고 본 실험 상태를 덮어쓰지 않는다.
실행 중 정기 보고는 약 5분, 실패/설계 변경/단계 완료 시 바로 보고한다.
실행 프로세스·현재 팔·완료 수·갱신 시각·남은 시간·최종 보고 경로를 CLI에 표시한다.

## 8. 선행 연구와 주장 범위

- [QVG](https://arxiv.org/html/2602.02958v1)는 청크당 단회 압축으로 재압축 드리프트를 피한다고 명시한다.
- [Quantized Keys Steal Attention](https://arxiv.org/abs/2605.26266)은 양자화된 과거 키의 Jensen 편향과 보정을 다룬다.
- [Self-Forcing 33-method study](https://arxiv.org/abs/2603.27469)는 여러 양자화/캐시 정책과 실제 메모리 통합 한계를 평가한다.

이번 계획의 가능한 기여는 특정 그룹 재편 개입을 통제하고 저장 오차 발생 위치와
실제 FR 품질 효과를 연결하는 설명이다. 그 차별성이 충분한지와 투고 수준은 결과 전에는 판단하지 않는다.
시간 품질·객체 동일성·실제 저비트 커널 이득은 별도 근거 없이는 주장하지 않는다.
