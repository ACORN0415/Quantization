## 0. 한 줄 요약

이 세션의 목적은 세션 2의 헤드라인("attention sink가 양자화 오차 누적을 차단한다")을 리뷰어 공격에 견디게 만드는 것이었는데, **검증 결과 그 주장이 틀렸습니다.**

Self-Forcing에 attention sink는 존재하지 않습니다. 첫 chunk는 토큰 비율의 **0.55배**만 받습니다(8.5% 대 14.3%). 고정해도 달라지지 않습니다.

대신 더 정확한 메커니즘이 나왔습니다. attention은 **위치 기반 최근성 편향**을 보이고(self 48%, 최근 19%, 최고령 7%), **INT2가 이 분포를 뒤집습니다** — self가 19%로 무너지고 최고령 캐시가 30%로 4.3배 올라갑니다. 모델이 자기 현재 계산을 버리고 낡은 컨텍스트에 매달립니다. 이 하나의 측정이 관문 A의 예상 밖 결과 두 가지를 모두 설명합니다.

## 1. 관문 A — sink 효과의 원인 분리 (§1)

같은 Self-Forcing 가중치에 캐시 설정만 바꿔 20회(5 설정 × 4 양자화) 실행했습니다.

### §6 검증 (다른 실험 전 선행)

| 관문 | 결과 |
|---|---|
| A1 BF16 == 세션 1 BF16 (프롬프트 0~2) | **PASS** (63/63 bit-exact) |

두 번째·세 번째가 짝을 이룹니다. sink는 퇴출이 시작되기 전까지 아무 일도 하지 않아야 하고, 실제로 그렇습니다.

### 판정

§1의 세 갈래 중 **세 번째**에 해당하지만, 단순히 "학습 정합이 원인"으로 낮출 필요는 없습니다.

**캐시 구조가 피해의 70%를 설명합니다.** A4 — LongLive의 캐시 구조를 Self-Forcing 가중치에 재학습 없이 적용 — 가 −10.97 → −3.28로 회복합니다. LongLive의 −0.3에는 못 미치므로 나머지가 학습 정합의 몫입니다. 실무 레시피("sink 3 + window 12로 바꾸면 INT4 피해가 1/3로 준다")는 살아남습니다.

### 예상 밖 결과 둘

**비트폭이 어떤 메커니즘이 작동하는지를 가릅니다.** INT4에서는 sink와 window가 각각 유의하게 기여하고 대략 가산적입니다(+5.35, +4.93 → +7.69). **INT2에서는 sink가 전혀 통하지 않습니다**(+0.35, t=0.25). 세션 2에서 "LongLive INT2가 나은 건 sink 덕"이라 읽었던 것은 틀렸고, 실제로는 **짧은 window 덕**입니다. 이유는 관문 B가 설명합니다.

**sink 크기를 키워도 나아지지 않습니다.** A5(sink 6)가 A2(sink 3)보다 낫지 않습니다(INT4 +5.43 vs +5.35, INT2에서는 둘 다 유의하지 않음). 세션 2가 남긴 "sink_size를 6, 9로 키우면 잔여 계단이 줄어드는가"에 대한 답은 **아니오**입니다.

### 모델 간 비교 — 같은 프롬프트 10개, 각자의 BF16 대비 (§6)

세션 1·2의 LongLive 수치는 프롬프트 3개였습니다. §6 요구대로 10개로 재실행해 관문 A와 한 표본으로 맞췄습니다.

|---|---:|---:|---:|---:|
| SF A1 (w21, sink 0) | −11.16 ± 3.81 | −5.74 | −52.76 ± 5.43 | −19.03 |
| SF A2 (w21, sink 3) | −6.16 ± 3.23 | −3.74 | — | — |

**LongLive의 INT4 KV 양자화는 BF16과 통계적으로 구분되지 않습니다.** 3프롬프트의 "−0.3"보다 강한 주장이고, 10개 재실행이 필요했던 이유입니다.

**재학습 없이 캐시 구조만 바꾸면 INT4 피해의 74%가 사라집니다**(−11.16 → −2.87). 남은 −2.87은 여전히 유의하므로(t=−3.82), 구조만으로 LongLive에 닿지는 못한다는 것도 통계로 확인됩니다.

## 2. 관문 B — attention mass (§2)

### 구현

flash-attn은 attention 행렬을 반환하지 않고, 만들면 레이어당 약 306MB(헤드당)입니다. 생성 forward는 FA2 그대로 두고, 훅에서 RoPE·QK-norm 적용 후 Q·K를 받아 **online-softmax로 key를 블록 단위로 훑으며 source chunk별 합만 누적**했습니다. 추가 peak 0.38GB.

**검증 3종을 통과한 뒤 측정했습니다.**

| 검증 | 결과 |
|---|---|
| online-softmax vs full softmax (mass) | max\|diff\| 3e-8 |
| 재계산 `softmax(QKᵀ/√d)·V` vs FA2 출력 | max\|diff\| **1.39e-02**, `allclose(atol=1e-2, rtol=1e-2)` PASS |
| 버킷 합 `mass_sum` | **1.0000** (누락 없음) |

FA2 등가 검증의 max\|diff\|가 atol(1e-2)을 약간 넘고 rtol 항이 받쳐 통과했습니다. 정직하게 기록합니다.

**마스크**: 실제 경로가 `attention(q, k, v)`를 `causal` 인자 없이 호출하고 기본값이 `causal=False`입니다. 즉 **마스크가 아예 없고**(캐시 전부 + 현재 chunk 전부 가시), 재계산도 동일합니다. 표준 causal 마스크를 적용했다면 현재 chunk가 하삼각으로 잘려 FA2와 조용히 어긋났을 지점입니다.

**self 버킷**: 현재 chunk의 K/V는 attention 호출 전에 캐시에 기록되므로 window에 포함되고 분모에 들어갑니다. self를 빼고 정규화하면 chunk 0이 16% 대 16.7%로 "거의 균등"으로 읽혀 정반대 결론이 날 뻔했습니다.

### 결과 — sink는 존재하지 않습니다

A1 (sink 없음), step 0 (t=1000), 프롬프트 3개 평균:

| chunk | 최고령 슬롯 | … | 최근 과거 | self |
|---|---:|---|---:|---:|
| 6 | c0 = 8.5% | c1~c4 = 4.8~8.3% | c5 = 20.1% | **47.6%** |
| 7 | c1 = 7.4% | | c6 = 18.7% | 50.2% |
| 14 | c8 = 8.4% | | c13 = 18.5% | 48.3% |
| 20 | c14 = 6.9% | | c19 = 19.3% | 47.8% |

**chunk 0은 토큰 비율(14.3%)의 0.55배만 받습니다.** §2의 판정 기준은 "30% 이상이면 sink 증명, 넘지 않으면 원인 재검토"였고, 넘지 않았습니다.

분포는 **위치 기반**입니다. 최고령 슬롯이 chunk 0을 담든(chunk 6 시점) chunk 14를 담든(chunk 20 시점) 같은 7~8%를 받습니다.

**A2(sink 3)에서 고정된 chunk 0도 7.7~10.4%**로, A1의 최고령 슬롯과 다르지 않습니다. 고정한다고 attention 자석이 되지 않습니다.

### INT2가 분포를 뒤집습니다

chunk 20, step 0:

| | self | 최근 과거 | 최고령 |
|---|---:|---:|---:|
| BF16 | 47.8% | 19.3% | 6.9% |
| INT4 | 44.2% | 17.7% | 8.4% |
| **INT2** | **19.2%** | **10.8%** | **29.8%** |

INT2에서 self가 47.8% → 19.2%로 무너지고 최고령 캐시가 6.9% → **29.8%(4.3배)** 로 올라갑니다. chunk 6에서 이미 시작되어(self 28.2%) chunk 14에 심해집니다(19.8%). INT4는 BF16과 거의 같습니다.

### 이것이 관문 A를 설명합니다

- **INT2에서 sink가 무력한 이유**: 문제가 "앵커 부재"가 아니기 때문입니다. attention은 **이미 낡은 내용에 과도하게 쏠려 있고**, 낡은 chunk를 하나 더 고정하는 것은 도움이 되지 않거나 병리를 키웁니다.
- **INT2에서 짧은 window만 효과가 있는 이유**: 과도하게 쏠릴 **낡은 토큰 자체를 줄이기** 때문입니다.
- **INT4에서 sink가 효과 있는 이유**: INT4는 분포가 아직 건강하므로(self 44%) attention mass가 아닌 다른 메커니즘 — 오염되지 않은 앵커의 존재 자체 — 로 보입니다. 이건 아직 직접 증거가 없습니다.

### 수정한 버그

슬롯 → global chunk 매핑을 `local_end_index` 기준으로 계산했는데, 캐시가 차면 이 포인터가 멈춥니다. 퇴출 후 슬롯이 chunk 14~19를 담고 있는데 0~5로 라벨됐습니다. mass 값은 영향 없었지만 해석은 정반대가 될 뻔했습니다. 현재 chunk의 끝을 기준으로 바로잡았습니다.

## 3. 관문 C — 지표 삼각측량 (§3)

프롬프트를 10개로 확장했고(앞 3개는 세션 1·2 세트와 md5 일치), 5지표를 추가 설치 없이 구성했습니다.

| 지표 | 출처 | 성격 |
|---|---|---|
| latent rel_err | 기존 | reference, 바닥선에서 포화 |
| MUSIQ | `pyiqa` | no-reference, 단일 프레임 |
| flow_err | `torchvision` RAFT warping error | **시간 축** |
| LPIPS | `pyiqa` | reference, 지각 기반 |
| CLIP score | `pyiqa` clipscore | 프롬프트 정렬 |

VBench 설치가 불필요했습니다(§3의 (a) optical-flow 옵션).

### 고친 두 가지

**LPIPS 기준.** 처음에 전체를 `A1_bf16` 기준으로 돌렸는데, A2~A5는 캐시 구조가 달라 **BF16끼리도 퇴출 후 다릅니다**(A2_bf16의 LPIPS 0.41). 설정별 피해량을 보려면 각자의 BF16이 기준이어야 하고, 그렇게 재산출했습니다.

**프롬프트별 값 저장.** 처음에는 평균만 저장해 짝지은 검정이 불가능했습니다. 독립 CI로는 A1 대 A2가 겹쳐 보였는데(±6.2 대 ±6.5) 짝지으면 t=4.59로 명확합니다. 같은 프롬프트를 쓰는 이상 이쪽이 올바른 검정입니다.

### TF 영상 MUSIQ — 전파와 주입의 분리 (§3의 열린 질문)

세션 2의 TF latent를 디코딩해 MUSIQ를 산출했습니다(프롬프트 3개).

| 설정 | MUSIQ Δ (chunk 0→20) |
|---|---:|
| BF16 | +3.73 |
| TF_w8a8 | +2.66 |
| **TF_int4** | **+1.10** |
| **FR_int4** | **−11.03** |
| TF_w4a4 | +6.17 |
| **TF_int2** | **−10.84** |
| **FR_int2** | **−42.84** |

§3의 기준("MUSIQ(TF) ≈ BF16이고 MUSIQ(FR) < BF16이면 그 차이가 카오스 무관한 전파 피해")에 부합합니다.

- **INT4**: 주입만으로는 BF16 대비 −2.6점(+1.10 대 +3.73), 자유 rollout은 −11.03. **전파가 12.1점**
- **INT2**: 주입 −14.6, **전파 32점**

**전파가 주입을 압도합니다** — INT4에서 약 5:1, INT2에서 2:1. 세션 2의 `FR−TF` 분석을 천장 없는 지표로 재확인한 것입니다.

**MUSIQ 약점 사례 추가**: `TF_w4a4`가 +6.17로 BF16보다 높습니다. chunk 0에서 이미 58.25로 낮게 시작해(다른 설정 63.7) 올라간 것이라 Δ가 오도합니다. INT4 활성화 양자화의 선명화 아티팩트를 no-reference 지표가 보상하는 것으로, 세션 2의 버그본 KIVI와 같은 양상입니다. **Δ만 보지 말고 절대값도 함께 봐야 합니다.**

## 4. 관문 D — 병목 프로파일링 (§4)

### attention은 memory-bound가 아니라 compute-bound입니다

Arithmetic intensity가 캐시 길이와 무관하게 **4680으로 일정**합니다. 수식을 정리하면 **AI = 쿼리 수**입니다 — attention FLOP은 `4·q·kv·dim`, KV 읽기는 `4·kv·dim` 바이트라 `kv`가 상쇄됩니다.

chunk당 쿼리가 4680개라 같은 KV를 4680번 재사용하므로 AI = 4680 FLOP/byte이고, 4090의 기계 균형은 163.9입니다. **LLM 디코딩과 정반대**입니다 — 거기는 스텝당 쿼리 1개라 bandwidth-bound입니다.

따라서 이 워크로드에서 **KV 캐시는 대역폭 문제가 아니라 용량 문제**입니다.

| 캐시 | KV | 생성기 가중치(2.64GB) 대비 |
|---|---:|---:|
| 12프레임 | 3.21 GB | 1.22× |
| 21프레임 (SF) | 5.62 GB | **2.13×** |
| 32프레임 (LL-2.0) | 8.57 GB | 3.24× |
| 63프레임 | 16.87 GB | 6.38× |
| 126프레임 | 33.74 GB | 12.77× |

**가장 짧은 설정(12프레임·단일 스트림)에서 이미 KV가 가중치를 넘습니다.**

### INT4의 +24%는 재구성 비용입니다

3 chunk 기준 BF16 5480 ms, INT4 KV 8709 ms.

| 연산 | BF16 | INT4 | 변화 |
|---|---:|---:|---|
| `addmm` (GEMM) | 1079 ms | 1080 ms | **불변** |
| flash-attn | 902 ms | 902 ms | **불변** |
| `aten::copy_` | 167 ms | 521 ms | +354 |
| `aten::cat` | 215 ms | 415 ms | +200 |
| `aten::mul` | 177 ms | 362 ms | +185 |
| elementwise 커널 | 107 ms | 438 ms | +331 |

**GEMM과 attention은 1ms도 변하지 않습니다.** 증가분 전체가 **매 chunk 캐시를 BF16 버퍼로 펼치는 elementwise 트래픽**입니다. 전용 역양자화 커널도, 파이썬 오버헤드도 아닙니다(전부 device 시간).

### RQ3(fused 저비트 KV attention 커널)의 정확한 동기

두 결과를 합치면 fused 커널이 무엇을 벌어주는지가 규정됩니다. **attention 대역폭이 아닙니다** — 이미 compute-bound입니다. **재구성 패스를 통째로 없애는 것**이고, 그 패스가 memory-bound elementwise 작업입니다.

## 8. 다음 세션 제안 — §5 재설계 권고

지시서 §5의 후속 실험은 **세션 3 발견을 반영해 다시 설계하는 편이 낫습니다.** 이유를 붙여 제안합니다.

**5-1 k-step delayed TF** — 원안은 "전파 horizon"을 재는 것인데, 관문 B에서 **INT2는 attention 분포 자체가 붕괴**한다는 걸 알았습니다. horizon보다 **분포 붕괴가 언제·왜 시작되는지**가 더 중요한 질문이 됐습니다. chunk 6에 이미 self가 28%로 떨어져 있으므로, chunk별 attention mass 궤적을 INT2·INT3·INT4에서 측정해 **붕괴 임계 비트폭**을 찾는 실험으로 바꾸기를 제안합니다.

**5-2 TUM Jensen-bias 보정** — 우선순위가 **올라갑니다.** 관문 B가 "양자화된 낡은 key가 mass를 과하게 받는다"를 직접 보였고, 이는 Jensen bias가 예측하는 방향과 일치합니다. 보정 항이 attention 분포를 BF16 쪽으로 되돌리는지를 **분포로 직접 검증**할 수 있게 됐습니다 — 원안의 MUSIQ 회복량보다 강한 증거입니다.

**5-3 KIVI residual window** — 우선순위 유지.

**5-4 126프레임** — 우선순위 유지하되, 관문 D에서 126프레임 KV가 33.74GB로 **4090에 안 들어간다**는 것이 확인됐습니다. rolling 캐시는 상한이 있으므로 실행 자체는 되지만, "캐시를 늘린 126프레임"은 불가능합니다. 원안이 후자를 의도했다면 재설계가 필요합니다.

**새로 제안하는 것 — INT4에서 sink가 왜 효과 있는지**: 관문 A는 INT4에서 sink가 유의하게 돕는다고 하고(+5.35, t=4.59), 관문 B는 그 이유가 attention mass가 아니라고 합니다. 남은 가설은 "오염되지 않은 앵커의 존재"인데 직접 증거가 없습니다. sink 슬롯에 **의도적으로 오염된 내용**(예: 다른 프롬프트의 chunk 0, 또는 노이즈)을 넣어 효과가 사라지는지 보면 가릅니다. 작은 실험이고 관문 A·B의 간극을 메웁니다.
