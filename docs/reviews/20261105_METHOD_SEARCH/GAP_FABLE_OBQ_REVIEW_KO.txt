1. 함수 유효성 (직접 확인)
 - OBQ 갱신(99–105행): U=chol(H⁻¹, upper), err=(w_j−q_j)/U_jj, w[j+1:] −= err·U[j,j+1:]. GPTQ Alg.1과 동일 형태. 정확.
 - 회전 정합: K는 k@hm(64행), q는 q@hm(219행), hm은 정규화 직교(1/√128). H=E[qqᵀ]를 회전 좌표에서 쓰므로 목적식 eᵀHe가 logit 오차 분산과 일치. 정확.
 - 대각 대조군이 FP32 RTN과 코드 동일(259, 284행 assert): "비대각 보상만의 효과"가 분리된다. 설계 의도대로.
 - 격자·스케일: 네 팔이 같은 scale 해시(262행)와 같은 payload 바이트(267행)를 assert. 반올림만 다름이 보장된다.
 - 패딩 행(8/1568): x=0 → 코드 0, 오차 전파 0. 무해. 복원 시 제거(120행).
 - fixed_v4는 과거 6청크만 INT4, 현재 청크 V BF16 유지(172행). 등록문 "현재 K/V BF16"과 일치. 현재 K도 원본 유지(263행).
 - bias는 metric의 차분에서 상쇄(141–144행), NSE 분모에만 들어감. 팔 간 비교에 영향 없음.
 - 셀프테스트 6항목은 코드와 일치(RTN 산술=기존 HeadRule, 단위 H=FP32 RTN, pack 왕복).

2. 정보 범위 (해석 제한, 결과에 붙여야 할 문장)
 - H는 p0 청크7 call0(첫 denoise) q = 읽기 측 q다. 쓰기 측 q(context_noise 재실행)가 아니다. 등록문이 "온라인/무보정 아님"을 이미 명시했으므로 일관. 결과는 "오프라인 보정 H(다른 prompt의 읽기 q)로 고정한 code optimization이 보류 prompt에서 단일 읽기 오차를 줄이는가"까지만 말한다.
 - 평가 q(p4)는 코드 선택에 쓰이지 않음(268행 주석대로 진단만). 누출 없음 확인.
 - p0/p4는 모두 개발 입력. 성공해도 보류 집합 결과가 아니다(등록문에 있음).
 - 단일 읽기(청크7 call0)만 본다. R-8b가 보인 "단일 단계 손상은 작고 격차는 자기 이력"과 연결되므로, 이 진단의 성공은 생성 누적에 대해 아무 것도 말하지 않는다.

3. 판정 기준에 대한 주의 (기준 변경 아님, 보고 시 함께 적을 것)
 - 주지표 'sse'는 원본 K·V 참조 대비이므로 V4 오차가 네 팔 공통 바닥으로 들어간다. 층0/14/29에서 V INT4 post NSE 4e-6~3e-4, 층18 회전 K 잔여 4.5e-3이면 바닥이 최대 ~7% 수준 → 20% 관문이 약간 희석된다.
   k_only_reference(272행)가 이미 기록되므로 두 값을 모두 보고하되 판정은 등록대로 'sse'로 한다.
 - 20%/10%는 자원배분 문턱이지 통계 기준이 아님(등록문 명시). 층 2개로 일반화하지 않는다.
 - OBQ_FULL이 B0 두 기준선 중 하나만 20%를 넘기면 '판단불가'로 떨어진다. BF16 RTN과 FP32 RTN의 코드 차이(250행)가 크면 그 자체가 보고 가치가 있다.

4. 비용에서 빠진 것 (기록 권고, 이번 실행 범위 밖)
 - 128단계 순차 루프는 GPU에서 지연 지배적이다. head 배치(w [N,H,D]로 j만 순회)하면 층당 128 launch, 30층 → 청크당 3840 launch + 층·head당 Cholesky. 실제 쓰기 시간은 미측정이며 이 진단은 CPU 초 단위만 적는다.
 - 보정 H 저장: 층·head당 128²×(FP64 8B)=131KB, 30층 12head → 47MB(FP32면 24MB). 작지만 배포 상태에 포함해야 한다. 코드는 층당 상주량만 기록(286행).
 - 보정 자료 의존: H가 prompt/denoise step/청크 위치에 따라 얼마나 이동하는지는 이 진단에서 측정되지 않는다(p0→p4 하나의 쌍). 성공 시 다음 질문이다.
 - RSS 추정: xg float 1.7GB + scales expand→reshape 복사 1.7GB + int8 코드 0.4GB + 캡처 2×235MB ≈ 4.5GB. 8GiB 안이나 여유 2배 미만. 초과 시 guard가 incomplete로 기록하므로 무효는 아님.

5. 셀프테스트가 덮지 않는 것
 - fixed_v4·pack_nibbles는 fair_comparison 라이브러리 소속이며 이 셀프테스트는 PackedChunk/HeadRule 경로만 검사. fixed_v4의 Quantizer("rtn",4,4,group=16) 산술이 B-4 등 기존 V4와 동일한지는 업무1 검토 범위로 둔다.
 - FP16 스케일 assert(70행): absmax/7 < 6.1e-5이면 FP16 subnormal로 BF16 왕복이 깨져 crash(무효 아님, incomplete). 실캡처 회전 K에서 그런 그룹은 거의 없을 것(추정).

6. HeadQ/NOVA-KV/OSCAR 본문의 순차 rounding 유무: 시간 내 미확인. 신규성 미확정 유지.
