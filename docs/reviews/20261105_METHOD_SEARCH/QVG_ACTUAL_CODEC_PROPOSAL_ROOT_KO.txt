QVG 창 수정 다음 단계: 실제 코덱 연결 판별 (준비안)
현재 CPU stage1의 실제 Opus 최종 검토와 source hash 결합을 통과한 경우에만 실행 준비를 확정한다.
목적: 원 PRQ INT2 패킷과 원 decoder, 원 RoPE 및 FlashAttention2를 주입했을 때 같은 창을 읽는 무퇴거 참조와 일치하는지 확인한다.
이 단계의 성공은 기존 기준선 실행 가능성의 근거다. 새 방법·영상 품질·속도 개선의 증거로 사용하지 않는다.

고정 조건
- upstream0601468f, 최종 CPU adapter cce683d4. sink0/initial없음/3frame/126frame horizon.
- W21/63/126, B1/H12/D128/프레임당1560토큰. 매 현재 block5번 overwrite.
- 원 triton-nstages-kmeans-int2, block64, PRQ1stage, kmeans2iter, K/V256centroids, asymmetricFalse.
- 결정적 합성 입력 seed20261106. 실제 모델·가중치·텍스트 인코더·VAE·영상 생성0회.
- 각24frame 그룹의 같은 압축 입력을 확인하고 PRQ packet을 한 번 생성해 무퇴거 참조와 세 창에 공유한다.
  encoder 두 번 실행 차이나 kmeans randomness를 cache 차이로 오해하지 않는다.
- 실제 원 compress_kv_cache 총5회. reference decoder 독립 unpack은 기존 검증된 INT2 형식과 대조하되 저장 파일을 새 해석으로 고치지 않는다.
- 모든630회 읽기에서 rawK/V·절대RoPE K/Q의 dtype/shape/원소bytes를 무퇴거 same-window 참조와 대조한다.
- native FlashAttention2 출력은 각 창의 압축 전/압축 후/부분span/최종 시점 최소각4회에서 같은QKV 기준으로 비교한다.
  동일native커널이 동일입력을 받는 검사이며 attention 알고리즘의 수학적 정확성 증명은 아니다.
- packed metadata가 수정되지 않았는지 내용hash로 확인하고 원 quantization schedule5개범위와 실제호출수를 기록한다.
- 실제PRQ에서는 CPU 합성검증의 fake decoder/attention이 사용되지 않았음을 binding과 실제 호출지점에서 기록한다.

상한·판정
- 코드 준비와 독립검토는30분 이내, GPU검사는별도등록후 단1회/최대600초, root독점시작.
- GPU allocator8GiB/RSS8GiB/CPU4/disk1GiB, external timeout강제 및 GPU사용중이면실행하지않음.
- 비교 허용오차를 사후에 바꾸지 않는다. KV·RoPE 바이트불일치/packet변경/호출수불일치면 실패.
- native attention 자체 반복의 비결정성이 발생하면 다른경로오차로 단정하지않고 판단불가로 기록한다.
- 시간초과·OOM·독립검토미완료는 판단불가. 임의재실행/별도seed구제 없음.
- 이 검사가 통과해야 원본전체pipeline/모델의 장기 생성 비교를 준비한다.

결과 전 구조 명확화: W126은 부분span이 생기지 않는다. nativeattention checkpoint는 W21(block7/8/9/41), W63(7/8/21/41), W126(7/8/21/41)이며 W126 block21은 intermediate_full_horizon_not_partial로 표시한다. 부분span 검사는 W21/63에만 적용한다. 각4회·전체630읽기·PRQ5회는 유지한다.
