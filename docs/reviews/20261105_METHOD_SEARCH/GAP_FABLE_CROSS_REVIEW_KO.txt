 (c) 정보 누출: 코드 확인(src/pipeline/causal_inference.py:259–260) 결과 KV 쓰기는 4 denoise 후 timestep=context_noise 재실행(step 3.3)에서 일어난다. 쓰기 시점에 같은 층의 q는 존재하지만 그것은
     "clean-context 재실행의 q"다. R-4 캡처의 q는 청크7 call 0(첫 denoise, noisy) = 읽기 측 q이며, 쓰기 측 q는 어떤 캡처에도 없다. 따라서 내 §5 관문 2(캡처 q 절반으로 H 추정)는
     쓰기 시점에 없던 미래·읽기 정보를 쓰는 capacity 진단일 뿐이고, 후보의 실제 주장("보정 없는 쓰기 시점 통계")은 현재 CPU 자료로 검사할 수 없다. 주 작업자 지적이 맞다.
     정직한 검사는 context_noise 재실행의 q를 1 forward 추가 캡처(GPU)해야 하며, 그 q(t=context_noise)와 미래 읽기 q(noisy, 다른 청크)의 분포 이동이 후보의 핵심 위험이다.
 (d) 그룹 경계 차이는 측정 잡음이 아니라 조건 변경이다. 내 §1 "±2 잡음" 표현을 철회한다. 다만 결론(단일 seed MUSIQ 차이 ±2는 후보 효과와 분리 불가)은 유지하며, 그 이유를 "조건 변경에 민감한 지표"로 고쳐 적는다.

2. 직접 선행 검색 결과 (KV/활성에 대한 GPTQ/OBQ형 순차 오차보상 반올림)
 검색 2회(extended 1, standard 1). 직접 일치 없음. 못 찾음 ≠ 부재. 가장 가까운 것(초록·검색 요약 수준, 본문 미확인):
 - HeadQ 2605.03562: K 오차를 score-visible 오차(logit, 상수 이동 제외)로 정의, 보정-학습 query 기저의 저랭크 잔차 side code를 읽기 시 logit에 가산. DV=잔차 상태(+바이트). 반올림 변경 아님.
 - NOVA-KV 2608.04074 "Spend Bits Where Queries Look": K 양자화를 transform coding으로 보고 attention-product 오차가 변환 영역 MSE가 되는 비직교 변환(보정 통계). DV=변환. 반올림 아님.
 - OSCAR 2605.17757: attention 유도 공분산에서 오프라인 회전. DV=회전. / MixKVQ: query-aware 채널별 혼합 정밀도. DV=비트. / Block-GTQ 2606.24033: RoPE 블록별 비트 배분. DV=비트. / WUSH-KV: 데이터 적응 변환.
 결론: "query 통계 → 기저/변환/비트/잔차 상태"는 2025–26에 포화 상태다. "query 통계 → 반올림 방향(순차 오차보상), 바이트 0"은 못 찾았으나, 위 논문들의 본문·부록에 ablation으로 들어 있을 가능성이 있다
 (GPTQ류는 흔한 ablation). 특히 HeadQ·NOVA-KV 본문의 "rounding" 절을 확인하기 전에는 신규성을 말하지 않는다. 한편 (c)의 쓰기 q 문제가 해결되지 않으면 신규성 여부와 무관하게 후보는 실행 불가다.

3. 짝 Codex 독립안에 대한 검토
 타당한 점: 6편 본문·LESS 코드 SHA까지 대조했고, 양의 feature 보정이 '압축 과거만 보정' 적용에서 과거 질량을 줄일 수 없다는 항등식(§3)은 맞다(toy_sign_check.py의 assert 논리 확인). 기준선에 PSAC(INT8 C, BF16 U)와 signed base-aware를 넣은 것은 필수였고 옳다.
 지적 1 (가장 중요): §5의 대상 층 0/14/29는 회전 후 병목이 아니다. R-4 보고(kv_alllayer_capture/REPORT 14–15행)에서 회전 후 잔여는 층18(4.5e-3)·24·22·23·15에 있고 층29는 head INT8로 이미 ×0.03–0.13이다.
   층0/14/29로 검사하면 "회전+head가 이미 푼 곳"에서 paired 상태의 필요성을 묻게 된다. 캡처는 30층 전부 있으므로(p00_s101/lXX_c7.pt) 층 집합을 {18, 24} + 대조 {29}로 바꾸길 권한다. 비용 동일.
 지적 2: PSAC 기준선의 U를 "과거 Q 공분산"으로 만들 때 캡처 q(청크7 읽기 q)를 쓰면 PSAC에도 같은 읽기-정보 누출이 생긴다. QuantWM 원래 정의(historical Q)에 맞추려면 U는 캡처 q의 앞부분/다른 prompt에서 추정하고
   평가는 나머지로 해야 한다. 명세에 이 분리를 명시해야 paired(누출 0)와 PSAC(누출 가능)의 비교가 공정해진다.
 지적 3: paired 상태 자체는 쓰기 시점 입력(K, K̂, V, V̂)만 쓰므로 정보 누출이 없다. 이것이 내 후보 대비 결정적 장점이다. 다만 학습 feature 변형은 학습 자료의 q가 들어가므로 그때 다시 누출 검토 필요.
 지적 4: 진행 기준 "p4 3층 합산 ≥10% 개선"은 층 합산이 큰 층 하나에 지배된다. 층별 보고와 "최악 층 악화 ≤5%"는 이미 있으므로, 합산 대신 층별 중앙값 또는 병목 층 개별 기준으로 바꾸는 편이 해석이 쉽다.

4. 다음 최소 검사 하나 추천 (비용·정보 누출 기준)
 추천: Codex §5 응답 잔차 진단을 택한다. 단, 층 집합을 {18, 24, 29}로 바꾸고(지적 1), PSAC U 추정/평가 q 분리(지적 2)를 명세에 넣는다.
