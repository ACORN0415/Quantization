paired 종료 뒤 다음 자원 배분 — Codex 독립 판단
2026-11-05 / 담당 /root/method_gap_codex

판단: 지금 채택할 새 방법 후보는 없다. 다음 자원은 새 잔차 보정기나 학습 feature가 아니라, 이미 실행한 QVG를 포함한 ‘압축을 실제로 필요로 하는 배포 조건’ 확인에 배정한다. 이는 연구 전체의 종료도, 긴 문맥 압축의 신규성 주장도 아니다. 현재 6과거청크 국소 오차 검사를 더 정교하게 만드는 것보다, 기존 방법으로 충족하지 못하는 실제 요구가 있는지 확인할 정보 가치가 크다.

1. 아직 답하지 못한 중요한 선택 하나
RTX 4090 24GB에서 Self-Forcing의 긴 생성에 실제로 필요한 것은 BF16의 짧은 작업 문맥인가, 기존 압축법으로 확보한 긴 문맥인가? 그 선택에서 기존 QVG로 부족한 조건이 남는가?

직접 관측한 근거는 다음으로 한정된다.
- 최종 paired RESULT는 유효 68행에서 stop_fixed_Gaussian_rank32다. 12개 비교 모두 최선의 등록 기준선보다 SSE가 1.8056~2.6813배이고 R_fp32보다도 나쁘다. fallback 제한은 통과했다. 수학식·안정성 구현 성공과 응답 근사의 유용성은 별개였다. 884개 감사 통과는 저장 스칼라·바이트 무결성 감사이며 attention 출력을 독립 재계산한 것은 아니다.
- full-H의 국소 개선은 실제로 있었지만 전체 영상 pilot은 stop_quality다. rain_market에서 후반 NSE 개선이 R_bf16 대비 5.7449%, MUSIQ 차이가 -2.1791로 등록 기준에 미달했다. DINO 참조 유사도 개선만 남겨 성공으로 바꾸지 않는다.
- 이 pilot의 생성 시간은 BF16 약 67.9초, 압축 팔 약 82.9~83.6초였다. 생성 프로세스의 모든 팔에 걸친 누적 allocated peak는 8.637GiB였다. 팔별 메모리 동등성이나 배포 최적 속도 주장은 못 하지만, 이 실행에서 24GB 용량 부족을 해결한 새 기능은 입증하지 못했다.
- 과거 63잠재프레임 창에서는 초기 BF16 선할당 OOM과, 해당 선할당을 제거한 압축 경로의 완료가 기록돼 있다. 그 긴 창의 영상 유용성은 미측정이다. 이는 이미 고친 하네스 문제이며 새로운 메모리 알고리즘의 실패 사례로 재사용하지 않는다.

따라서 남는 관측 공백은 ‘더 작은 국소 SSE’가 아니라 ‘압축으로 확보한 용량이 어떤 실제 생성 요구를 만족시키는가’다. 긴 문맥이 우리 입력에서도 유리할 것이라는 부분은 아직 가설이다. 더 많은 캐시가 언제나 더 좋은 영상이라는 전제도 두지 않는다.

2. 선택 시점에 이용할 수 있는 정보
모델·GPU·해상도·생성 길이·문맥 창·메모리 상한, 공개 구현 지원 범위, 사전에 정한 작은 보정 입력의 실제 생성 비용과 품질만 사용할 수 있다. p0의 통계나 기존 개발 영상을 새 보류 입력처럼 표현하지 않는다. 뒤에 생성할 영상의 MUSIQ, endpoint별 최선의 FULLP1/FULLP1Q, 실제로 유리했던 seed를 미리 아는 선택기는 허용하지 않는다. 특히 paired의 네 endpoint별 최소값은 강한 비교점이지 온라인 배포 가능한 선택 정책이 아니다.

3. 가장 강한 단순 해결책과 현재 증거
기본 선택은 요구 문맥이 메모리에 들어가면 BF16 고정, 압축이 필요하면 검증된 기존 QVG 설정 또는 단순 고정 회전 RTN을 실제 생성으로 비교하는 것이다. 현재 full-H/paired 결과는 BF16보다 빠른 방법이나 QVG를 이긴 새로운 배포 방법을 보여주지 않는다. p0 고정 FULL은 국소 대조로 반드시 유지할 가치가 있으나, 종료된 영상 후보를 다시 채택할 근거는 아니다.

QVG packed 경로는 kv_reuse_stage1에서 실제 실행됐다. 반면 최근 paired에 포함된 projected PSAC, FULL+P1/Q 조합은 통제된 국소 adaptation이며 QVG의 centroid 방식과 QuantWM 전체 공식 방법을 같은 실제 메모리·문맥·영상 조건에서 이겼다는 결과가 아니다. 기존 방법이 충분한지부터 비교해야 한다. ‘보정용 생성이 너무 비싸다’는 실제 요구도 확인되지 않았으므로 이 이유로 새 선택기를 정당화하지 않는다.

4. 가까운 선행연구와 차이
이번에 새로 확인한 원문은 아래 두 편뿐이다.
- QVG v5 §1/§5.1/부록 A.1: 압축으로 더 긴 작업 문맥을 확보해 긴 생성의 일관성을 유지한다는 문제와 Self-Forcing 장기 생성 평가를 이미 다룬다. 따라서 ‘긴 문맥을 위해 압축한다’, ‘같은 GPU에서 메모리-품질을 비교한다’ 자체에는 남는 새 방법 차이가 없다. 원문은 Self-Forcing의 전체 이력 조건도 명시하므로 우리 고정 6청크 창과 바로 같은 설정으로 읽으면 안 된다. https://arxiv.org/html/2602.02958v5
- QuantWM v3 §3.1/§5.1: 기존 영상 벤치마크가 실제 시각적 손상을 충분히 반영하지 못할 수 있음을 이미 지적하고, QVG 및 공식 구현을 대조한다. ‘국소/자동 지표와 눈에 보이는 품질이 다르다’ 자체도 신규성이 아니다. 현재 우리의 text-to-video 결과를 action-conditioned world model의 동작 추종 성과로 확대하지 않는다. https://arxiv.org/html/2609.26425v3

이 두 방법을 넘어서는 구체적 미해결 실패 조건은 현재 자료에서 확보하지 못했다. 최신 논문에서 동일한 제목을 못 찾았다는 이유로 차별점이 생기지 않는다. 이번에는 새 공식·학습기·rank 확장 제안을 하지 않는다.

5. 다음 자원을 어디에 쓸 것인가
새 방법 후보 수는 0개다. 대신 다음 한 번의 자원은 인접한 ‘메모리 제한 영상 추론의 배포 기준선’ 확인에 쓴다. 실행 제안이며 이번 검토에서 실행하지 않았다.

첫 단계는 최대 30분 CPU 준비다. 이미 보유한 QVG 실행 경로와 현재 BF16 경로에서 21/63잠재프레임 창, 동일 42청크 생성, 같은 모델·해상도·노이즈 일정으로 비교할 수 있는지 확정한다. 과거 선할당 문제를 다시 넣은 BF16을 약한 기준선으로 사용하지 않는다. 각 경로의 원본 코드·설정·실제 패킹·pending/sink 정책을 기록하고, 의미를 맞추기 위해 커널 이식이나 새 압축 정책이 필요하면 이 준비에서 중단한다. 모델 다운로드나 문헌 탐색 확장은 하지 않는다.

이 조건이 갖춰질 때만 두 새 입력에 BF16/QVG × 짧은/긴 창의 최대 8생성·8VAE, GPU 전체 60분 상한의 기존 방법 비교를 별도 등록한다. 현재 두 pilot 입력이나 paired 캡처는 보류 자료로 재사용하지 않는다. GPU 용량 제한은 실제 장비 24GB로 두고, 메모리 사용량을 억지로 같게 만들지 않는다. peak·생성 완료 여부·전체 시간·영상 품질을 함께 기록한다. 시간은 단회 개발 측정으로만 쓰며 속도 우위를 확증하지 않는다.

이 검사의 진행 기준은 새 방법의 성공이 아니다. 기존 QVG가 더 긴 문맥을 실제 상한 안에서 제공하는지, 짧은 창 대비 유용한 영상 변화가 있는지, 그 결과가 기존 방법으로 충분한지를 판단한다. 최종 품질의 주기준과 비열등 허용폭은 새 출력 전에 정해야 하며, 현재 NSE/MUSIQ 중 유리한 항목을 결과 후 택하지 않는다. 문맥이 다른 영상에는 BF16 짧은 창을 유일한 정답 궤적으로 놓지 않는다. 시각적 일관성과 움직임·지시 준수도 보아야 한다는 필요는 있지만, 지금 없는 검증된 지표를 이미 확보한 것처럼 주장하지 않는다.

- 기존 방법으로 요구가 충족되면: 적용 결과로 정리하고 새 양자화 방법 탐색을 다시 자동으로 시작하지 않는다.
- 긴 문맥의 유용성이 없거나 기본 BF16이 요구를 충족하면: 이 워크로드에서 추가 KV 압축 개발 투자를 중지한다. 다음 자원은 별도로 측정된 실행 병목/실제 배포 요구에 배정한다.
- 기존 방법으로 해결되지 않는 품질·실행 제약이 남으면: 그 한 조건만 다음 연구 문제로 등록한다. 해당 조건이 생겼다는 사실만으로 새 알고리즘의 신규성이 확보되지는 않는다.
- 문맥 의미 불일치, 고쳐지지 않은 선할당 오류, 구현 미지원, 품질 판정 기준 미확정, 시간 초과는 판단 불가다. 예상되는 메모리 한계에 의한 적법한 OOM은 그 설정의 실행 불가능 결과로 구분한다. 자동으로 더 긴 창·seed·새 코덱을 추가하지 않는다.

이 권고를 택한 이유는 새로운 실패를 억지로 만들기 위해서가 아니다. 지금의 반복 국소 실험은 방법의 출력 오차를 충분히 구분했지만, 더 줄여야 할 실용적 필요가 아직 약하다. GPU 시간을 추가할 경우 무엇이 달라지는지를 기존 강한 방법부터 확인하는 쪽이 낫다. 실제 요구가 확인되지 않으면 GPU 실행 없이 준비 결과에서 끝내는 것도 올바른 자원 결정이다.
