원인
causal_obq/replay.py 50행은 hashes[arm].append(tsha(packet['packed']))를 실행하고,
57행의 code_sha256에 그 값을 저장한다. 즉 이름은 code_sha256이지만 의미는 packed uint8
payload의 바이트 hash다. 현재 driver 265행은 unpack 후 signed int8 논리 코드 배열의
바이트 hash와 비교한다. 서로 다른 직렬화이므로 값의 표현이 같아도 hash는 달라야 한다.
scale anchor는 정확히 일치한다. 이번 실패는 scale 문제도 V4 tsha 수정 문제도 아니다.

직접 확인
- packed: 3,612,672개 uint8 / 3,612,672B, hash 6c3a46094eaf1174da703ee4ad9cb03352f35c3f98ca71c6e14582095e07ff21
- unpacked: 7,225,344개 int8 / 7,225,344B, hash 46b803af4c262c0fc77c5bd894fda62ed518d396d3f3e66e1885ff392b72bc9b
- manifest code_sha256은 packed hash와 일치한다.
- scale FP16 hash 3414b0e062d8e4d3a93ced67cd9256f95864fe888afb1389e7d39c3c41c04a73는 manifest와 일치한다.
- 독립 nibble 추출→부호 복원→재패킹은 packed 원소 전체와 정확히 같다.
- 기존 tsha와 V4 tsha는 이 세 표현 각각에서 같은 digest를 낸다.
소형 반례 [-8,-1,0,1,7,-3]은 packed [248, 16, 215]와 같은 코드를 뜻하지만
바이트 수와 hash는 다르다. JSON에 양쪽 표현과 hash를 기록했다.

최소 수정 제안
비교 대상을 tsha(kp['packed'])로 바꾸고 기존 scale/whole-file SHA/shape/bytes 검사는 유지한다.
unpacked-code hash가 필요하면 별도 이름으로 기록하며 원 manifest 값을 새 의미로 바꾸지 않는다.
이 변경은 source anchor의 표현 일치를 고치는 것이다. base 복원은 이미 해당 분기 전에
실행되며 digest 비교는 읽기 전용이라 quantization/restore/scoring 수식이나 값을 바꾸지 않는다.
이 사실을 확인했다고 이후 전체 실행 유효성까지 보장하지는 않는다. 실제 재실행은 하지 않았다.

즉 합성 builder와 소비자가 같은 schema 해석 오류를 공유했다. 68행 전체 합성 완주는
