구조화 moment Hessian(H ≈ D + μμᵀ + λI) OBQ 가설 검토 — Claude Fable 5.1, 2026-11-05 (10분, GPU 0, 코드 변경 0)
전제: 아직 실제 자료 효과 없음. 새 방법이라 부르지 않는다. 아래는 수학 확인(합성 수치 검사 1회 실행), 선행 중복, 가장 강한 단순 대안, 최소 CPU 검사.

1. 수학: root의 스칼라 상태 갱신식은 H = D + uuᵀ에 대한 OBQ/GPTQ의 "정확한" 특수형이다(근사 아님).
 유도: 남은 채널 집합 F에 대한 부분 Hessian H_F = D_F + u_F u_Fᵀ 의 역행렬(Sherman–Morrison): [H_F⁻¹]_jj = 1/d_j − u_j²/(d_j² c_F), [H_F⁻¹]_jk = −u_j u_k/(d_j d_k c_F), c_F = 1 + Σ_{k∈F} u_k²/d_k.
 OBS 갱신 δ_k = −e_j [H_F⁻¹]_kj / [H_F⁻¹]_jj = (u_k/d_k) · e_j u_j / (1 + Σ_{k>j} u_k²/d_k).  → 모든 남은 채널의 갱신이 (u_k/d_k) × 공통 스칼라이므로
 w_j = x_j + (u_j/d_j) S,  e = w_j − q_j,  S ← S + e·u_j / c_j,  c_j = 1 + Σ_{k>j} u_k²/d_k (head당 D개 상수, 사전 계산). root 식과 부호·분모 모두 일치.
 상태는 토큰당 스칼라 1개(N개), 분해·Cholesky·행렬 feedback 없음. λI는 D에 흡수.
 합성 검사(직접 실행, /tmp, torch FP64, D=16, N=200, 임의 d>0·u·격자 0.7·clamp[-8,7]): 밀집 GPTQ(H⁻¹ upper Cholesky, 잠긴 코드와 같은 형태) 코드와 스칼라 재귀 코드가 전 원소 동일(max|diff| 0), 목적식 eᵀHe RTN 1971.6 → 둘 다 1091.1. 식의 정확성은 확인됐다. 실제 K/q 자료 효과는 미확인.
 주의: 이 동등성은 "H가 정확히 D+uuᵀ일 때"다. 실제 H = Σ + μμᵀ(Σ = 중심 공분산)이고 가설은 Σ ≈ diag(Σ)로 바꾼다. 버리는 것은 Σ의 비대각(저랭크) 부분이며, 이것이 전체 H 이득 중 얼마를 차지하는지가 유일한 실증 질문이다.

2. 회전 좌표에서의 의미(관측과 연결, 가설 표시)
 - Hadamard 후 diag(H)는 평탄해진다(ADDENDUM: 상위 8채널 점유 0.15). 그러면 D ≈ cI에 가깝고 가설은 사실상 H ≈ cI + μμᵀ, 즉 목적식 ≈ c‖e‖² + (μᵀe)². 순차 갱신은 "평균 query에 대한 logit 오차 μᵀe를 채널을 따라 상쇄"하는 오차 확산이 된다.
 - capacity 결과의 top-16 고유값 에너지 0.62–0.81(비중심 H)에서 μμᵀ 한 방향이 차지하는 몫 ‖μ‖²/tr(H)은 아직 계산되지 않았다. 이 한 숫자가 가설의 상한을 준다(아래 4의 첫 열).
 - 가설이 맞으려면 "해로운 K 오차 = 평균 query 방향 정렬 오차"여야 한다. 이는 관측 §3-2(채널 정렬이 해롭다)와 정합하지만, 층 18/24의 잔여가 저랭크 Σ(예: RoPE 저주파 쌍) 때문이면 rank-1로는 부족하다.

3. 선행·중복(이름이 아니라 식 기준)
 - 저랭크+대각 Hessian의 Woodbury/Sherman–Morrison 기반 OBS 갱신: WoodFisher(Singh & Alistarh 2020, 2004.14340)가 가지치기에서 같은 대수를 쓴다(기억 기반, 본문 미재확인). "rank-1+diag H에 대한 OBS 폐형식"은 새 수학이 아니다.
 - QuIP의 LDLQ(2307.13304): 임의 H의 LDL로 GPTQ를 일반화. D+uuᵀ의 LDL이 바로 위 재귀다. 즉 가설 = "구조화 H를 쓴 LDLQ 특수형".
 - 오차 확산/sigma-delta: 내 Round-1 후보(토큰 축, V)는 실패했다. 이번 것은 "토큰 내부 채널 축, 방향 μ, 메트릭 D"로 축과 대상이 다르고, 대상이 측정된 해로운 양(정렬 logit 오차)이라는 점이 다르다. 그러나 "방향성 오차 확산으로 특정 선형 범함수(μᵀe)를 보존"은 신호처리의 vector sigma-delta와 같은 원리다. 신규성 주장은 못 한다.
 - KV 영역에서 "query 평균 방향 보존 반올림"을 명시한 논문은 10분 내 검색하지 않았다(미검색 ≠ 부재). HeadQ/NOVA-KV/OSCAR 본문 확인 과제가 그대로 남아 있다.
 결론: 수학·알고리즘은 조합이지 발명이 아니다. 남을 수 있는 기여는 (a) "어느 H 구조가 충분한가"의 실증(full vs rank-r+diag vs rank-1+diag vs cI+μμᵀ)과 (b) 그 결과로 생기는 O(ND) 통계·O(N) 상태·단일 커널 인코더의 비용 이득. (b)는 업무 1의 full-H GPU 비용과 나란히 재야 의미가 생긴다.

4. 더 단순하고 강한 대안 1개 + 최소 CPU 검사(기존 캡처·잠긴 코드만, GPU 0)
 대안(가장 단순): H_alt = cI + μμᵀ (c = mean diag(Σ)), 즉 통계는 μ 하나(128 float/head/층), D도 없음. 이것이 D+μμᵀ와 같다면 D 수집도 불필요하다.
 검사의 핵심 단순화: 정확도 질문에는 새 재귀 코드가 필요 없다. 근사 H를 128×128 밀집으로 만들어 잠긴 codes_obq(common.py)에 그대로 넣으면 된다. 재귀 구현은 비용 단계에서 만들고, 그때 밀집 D+uuᵀ 경로와 코드 동일성(위 합성 검사처럼)만 확인하면 된다.
 팔(모두 같은 격자·scale·payload): RTN_fp32, OBQ_full(기존 결과 재사용, 해시 대조), OBQ_D+μμᵀ, OBQ_cI+μμᵀ, OBQ_D+rank4(Σ) , OBQ_D+rank16(Σ). 통계는 모두 같은 보정 q(p0 c7 call0)에서.
 입력: capacity(p0 H→p4 평가, 층 18/24)와 causal(fresh prompt, offline p0 H, 층 18/24, call0/call3). 둘 다 존재. 비용: 팔당 층당 1–2초 CPU, 전체 수 분. RSS < 3GB.
 보고 수치: 각 팔의 post-Wo SSE와 "full-H 이득 회수율" ρ = (SSE_RTN − SSE_arm)/(SSE_RTN − SSE_full). 더불어 ‖μ‖²/tr(H), top-16 중심 Σ 에너지(head별).
 판정 제안(결과 전 고정): ρ(D+μμᵀ) ≥ 0.8 두 층·모든 endpoint → 비용 경로(재귀 인코더) 구축 가치 있음. ρ < 0.5 → rank-1은 불충분, rank-r(Woodbury, 토큰당 r 스칼라)로 질문 이동. 사이 → rank-4/16 결과로 r 결정. ρ(cI+μμᵀ) ≥ 0.9·ρ(D+μμᵀ)이면 D 수집 생략.
 실패 조건: ρ(D+μμᵀ) < 0.5이고 rank-16도 < 0.8이면 "구조화 H로는 비용을 못 줄인다" → full-H GPU 비용(업무 1)이 유일한 경로.

5. 가장 강한 반론
 - 회전 후 Σ가 평탄·등방에 가깝다면 μ 한 방향만으로는 full-H 이득(37–42%)의 일부만 회수하고, 나머지는 Σ의 저랭크 구조에서 온다. 그 경우 rank-r이 필요하고 상태는 토큰당 r 스칼라·r×r 갱신으로 커지지만 여전히 O(NrD)이라 full보다 싸다. 즉 가설이 틀려도 같은 검사가 다음 질문을 준다.
 - 채널 순서: 재귀의 c_j는 뒤 채널로 갈수록 작아져 오차가 뒤로 몰린다. 고정 순서 0..127은 u_j²/d_j 내림차순 정렬보다 나쁠 수 있다(GPTQ act-order 유사). 첫 검사는 고정 순서, 정렬은 별도 팔로 추가하지 않는다.
 - 비용 주장의 근거는 아직 0이다. "O(ND)·스칼라 상태·단일 커널"은 추정이며, 업무 1의 full-H GPU 측정 없이 비교할 수 없다. 이 제안으로 업무 1을 취소하지 않는다는 root 방침에 동의.
 - μ는 보정 q(p0, call0, t=1000)의 평균이다. causal 결과에서 offline H가 call3(t=625)에도 전이됐으므로 μ도 전이될 가능성이 있으나 측정 전이다.

확인/미확인: §1 유도와 합성 수치 동등성은 직접 확인(위 스크립트, 프로젝트 파일 미사용). WoodFisher·QuIP는 기억 기반, 본문 미재확인. 실제 캡처에서의 ρ는 미측정. Codex method_gap 보고서는 읽지 않음.
