2. window 21 frame과 양자화 span 24 frame의 불일치 (CI:341-354)
- 양자화는 chunk_index k(0-based; k≥8, k%8==0) 직전에 [3(k−8), 3k) frame = 24 frame을 한 span으로 압축한다.
  - 공유 centroid를 쓰며, 0..7 block은 처음에 BF16이다.
- window W=21 frame(7 block)일 때 block k의 attention 가시 과거는 [3k−18, 3k)다.
  - 따라서 양자화 시점에 span의 앞 6 frame [3k−24, 3k−18)은 이미 window 밖이다.
  - 처음(k=8)에도 frame 0..5가 이미 밖이다.
- 결과
  (i) BF16를 즉시 퇴거하면 quantize의 read(start,end)(CI:98)가 EMPTY chunk에서 ValueError를 낸다.
  (ii) 퇴거 단위는 생성 block(3 frame) 단위로 진행되는데, span은 24 frame이라 span 경계와 정렬되지 않는다. 그래서 '부분적으로 window 밖에 있는 span'이 항상 존재한다.
- 전체 block 삭제로 window를 정의할 수 있는가: 읽기 범위만 [window_start, end)로 정하면 정의된다.
  - KV.read는 span의 일부 slice(tok_off, KV:186-194)를 지원한다. 단 매 읽기마다 span 전체를 해제한다(비용).
  - 메모리 해제는 span 단위로만 가능하다(evict_range의 centroid 규칙). 그래서 attention window(21)와 메모리 상주 범위(최대 span 24 + 진행 중 block)가 다르다. 이를 반드시 분리해서 기록해야 한다.
- 유지해야 할 정보
  - 부분적으로 살아 있는 span의 quant_data 전체: centroid, 토큰별 code, info.
  - 양자화를 기다리는 BF16 frame. 정책에 따라 다르다(4절).
  - span의 절대 start/end.
  - 마지막 정리 block 경계(global_end).

3. 주소·denoise 덮어쓰기·RoPE·sink의 상호작용
- 같은 block 반복 호출(denoise 4회와 cache update 1회): current_end==global_end이면 :288 검사를 건너뛰고, :293 local_end를 같은 값으로 다시 계산해 같은 위치를 덮어쓴다.
  → eviction은 "current_end>global_end인 새 block의 첫 호출"에서만 정확히 1회 일어나야 한다. 반복 호출에서 퇴거하면 안 된다.
- 이전 확정 구간(이미 cache update된 block)은 다시 쓰지 않는다.
  - KV.write에서 QUANTIZED chunk에 쓰면 span 전체가 제거되므로(:133-134), 현재 block이 span과 겹치지 않는다는 불변조건이 필요하다.
  - 현재 소스에서는 양자화 범위가 항상 3k 미만이라 겹치지 않는다(관찰).
- RoPE: K는 buffer 상대 위치, Q는 절대 위치다.
  - window 시작 s>0으로 읽으면 K 위치가 s만큼 어긋난다.
  - RoPE 내적은 위치 차에만 의존하므로 한쪽을 맞추면 된다. K를 절대 위치 s부터 RoPE하거나, Q를 (current_start_frame−s)로 RoPE한다.
  - 원래 rolling은 절대 위치가 이미 K에 들어 있어 sink 뒤의 위치 간격이 물리적 shift와 무관했다.
- sink(sink_size>0)
  - 가시 집합이 [0,S) ∪ [window_start, end)로 연속이 아니게 된다.
  - long_input RoPE(연속 0부터)를 그대로 쓸 수 없고, 세그먼트별 절대 위치 RoPE가 필요하다.
  - 원 rolling은 sink K의 절대 위치와 최근 K의 절대 위치를 그대로 유지했다. 원 rolling과 같은 의미를 원하면 절대 위치를 유지해야 한다.
  - 우리 대상 설정은 sink 0이며, sink 지원은 별도 범위다.
- 오답 사례
  - capacity만 키우면(max_num_chunks=126) ValueError는 사라지지만 :301 read(0,·)가 전체 과거를 읽는다. 이는 global attention이 되며 다른 방법이다.
  - assert만 삭제하면 write assert(KV:129)에 걸리거나 global이 된다.
  - rolling 함수를 직결하면 dense 전제가 깨지고 양자화 span이 손실된다.

5. GPU 없는 향후 CPU reference 검사의 최소 불변조건과 반례 (지금 구현·실행 안 함)

   - 반례: 두 번째 호출에서 eviction이 일어나면 window가 한 block 앞으로 밀린다.
4) 부분 span
   - k=8: span[0,24)이고 window 시작 6. read가 slice [6,24)를 정확히 반환하는지 확인한다.

6) RoPE: 같은 K 값을 s만큼 이동한 window로 읽을 때 q·k logits가 절대 RoPE dense 기준과 같은지(허용오차 내). 반례: offset을 누락하면 logits 불일치.
