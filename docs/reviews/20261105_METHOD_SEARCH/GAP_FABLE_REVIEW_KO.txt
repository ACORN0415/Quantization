----------------------------------------------------------------------
[관측] (R-4, tensor_vs_output) 회전은 30/30 층에서 K 텐서 오차를 ×1.2 키우고 출력 NSE를 ×0.5(층28·29는 ×0.03–0.13) 줄인다.

[관측] (R-8b) 자기 이력에서 누적되는 것은 원좌표 K4V4(10/10 g<−3)이고, 회전·등방잡음·회전+head는 0 중심 ±2–5. 등록 기준 C2 실패는 문턱 설계 오류로 기록.

[관측] 그룹 경계만 달라도 p4 FR MUSIQ 73.2 vs 71.3. 반올림 방향을 바꾸는 후보는 이 잡음과 같은 급의 효과를 낼 수 있으므로 생성 MUSIQ로는 분리 불가.
 → 판별은 CPU 출력 NSE(단일 읽기)와 보류 query 쌍으로 해야 하고, 생성 평가는 2 seed 이상에서만 의미가 있다.
[추측] 회전 후 잔여의 구성(heavy-tail 토큰, Jensen 편향, RoPE 쌍 구조, 그룹 스케일 포화)은 미측정. 후보는 이 중 어느 것도 가정하지 않고

[추측] 분산/정렬이 유일 원인이라는 해석은 하지 않는다. 후보가 성공해도 "정렬이 원인"의 증명은 아니며, 실패해도 그 반증이 아니다.

3. 수학 / 알고리즘
----------------------------------------------------------------------
설정: head h, 층 l, 청크 c. 회전 기저에서 k_i ∈ R^128 (post-RoPE, Hadamard 적용 후), 그룹 g16 채널별 FP16 스케일 s(채택 구성과 동일), 정수 격자 Z_s.
손상 함수(측정됨): 토큰 i의 오차 e_i = k̂_i − k_i 에 대해 미래 query q의 logit 오차 = qᵀe_i. 기대 logit 오차 분산 = e_iᵀ H e_i, H = E[qqᵀ].
쓰기 시점 대체: H_c = (1/n) Σ_{j∈청크 c의 자기 query} q_j q_jᵀ + λ·diag(H_c) (λ=0.01, GPTQ 댐핑). q_j도 같은 Hadamard로 회전된 좌표.
 이 H_c는 (같은 층·head·denoise step의) 쓰기 시점 입력만 쓴다. 미래 query·보정 데이터·원본 과거 KV 접근 없음.
반올림(OBQ 순차, 채널 순서 고정):
 L = chol(H_c⁻¹)ᵀ (128×128, head·층·청크당 1회).
 for 채널 t = 0..127 (토큰 전체 벡터화, N=토큰수):
   w_t ← 현재(보상 적용된) K[:,t];  ŵ_t = clamp(round(w_t / s_t)) · s_t   (격자·스케일은 RTN과 동일)
   err_t = (w_t − ŵ_t) / L_tt;  K[:, t+1:] −= err_t ⊗ L_t, t+1:
 결과 K̂는 RTN과 같은 격자·같은 스케일·같은 바이트. 다른 것은 반올림 방향뿐.
비용: head·층·청크당 Cholesky 128³ ≈ 2 MFLOP(무시), 순차 루프 N·128·128 ≈ N·16K MAC. 청크 토큰 N(청크 7 캡처: 32760/8 청크 ≈ 4095 ≈ 4680 아닐 수 있음 — 실제 N은 코드 확인)
 → 층·head당 ≈ 70 MMAC, 전체 30층×12head ≈ 25 GMAC/청크. 5 forward/chunk의 attention 연산에 비해 작다(추정; 실측 필요). GPU 미구현이므로 실제 시간은 미측정.
스케일 선택은 RTN과 동일(max-abs 또는 기존 코드의 방식)으로 고정해 "반올림 효과"만 분리한다. 스케일까지 H-최적화하는 변형은 2차 후보로 두고 처음엔 안 한다.
읽기 경로: 변경 0. 기존 K4h8_V4 커널 그대로. (후보의 가장 큰 실용 장점: 배포 시 읽기 커널·메타데이터 불변.)
head INT8 규칙과의 결합: INT8 head는 그대로. 후보는 INT4 head에만 적용. 층18·22–24 병목이 목표이므로 head 규칙과 겹치지 않는다.
RoPE 주의: K는 post-RoPE 저장. 미래 query q_m과 과거 k_n의 logit은 상대 위치에 의존하나, 저장된 것이 post-RoPE k_n이고 q_m도 post-RoPE이면 logit = q_mᵀ k_n 그대로다.
 쓰기 시점 q_j(위치 j∈c)와 미래 q_m(m>c)은 RoPE 위상이 다르다. H_c는 그 차이를 반영하지 못한다 — §7 반론 1.

4. 가장 강한 단순 기준선 (후보가 이겨야 하는 것, 동일 바이트 우선)
----------------------------------------------------------------------
B0. 채택 구성 K4h8_V4(회전 + RTN g16 + head INT8). 후보는 이것과 바이트 동일. 1차 비교 대상.
B1. 같은 바이트에서 반올림만 바꾸는 무-query 대안: (a) 감산 디더(ADDENDUM: 층0 7–20× 이득, 층29 악화) (b) 확률적 반올림. 이것이 후보와 비슷하면 "query 정보"의 가치가 없다.
B2. 스케일 최적화(반올림은 RTN): MSE-최적 또는 e^T diag(H) e 최적 스케일 탐색(채널별 몇 후보). 대각 H만으로 충분하면 Cholesky·순차 보상은 불필요.
B3. QKSA 읽기 보정(상태 0)과의 결합/비교. 층29에서 4× 먹는 부분을 뺀 뒤 남는 이득만 후보 몫.
B4. 바이트 증가 대안: 병목 층(18, 22–24)만 K8 — 층별 비트(KVTuner류, 기존). 바이트 +(4층/30)×(K 절반) ≈ +7%. 후보가 이 4층에서 K8의 100× 중 상당 부분을 바이트 0으로 회복하지 못하면 B4가 낫다.
B5. QJL/TurboQuant 1비트 잔차 스케치(+25% 바이트). 바이트가 다르므로 "바이트당 이득" 축에서만 비교.
※ "단순 K 노름 head 선택" 아이디어는 이번 후보에 포함하지 않는다(요청에 따라 선행 및 동일 바이트 고정 head와 싸워야 하며, R-8b C4에서 누적 감소 추가 근거 없음).

 대상 층: 18, 22, 23, 24 (회전 후 잔여 병목), 29 (대조: massive head 있음), 0 (대조: 디더가 잘 듣는 층). 기존 R-5 양자화기 코드(headrule_quantizer.py)의 회전·g16 스케일을 그대로 재사용.
보류 분리(필수): H_c는 청크 c 자기 query로만 추정하고, 평가 query는 (i) 다른 청크의 query — 캡처는 한 호출뿐이므로 (ii) 같은 호출의 query를 두 반으로 나눠
 쓰기-반(H 추정)과 평가-반으로 분리. 이것은 미래 청크 query가 아니므로 관문 통과가 "미래 query 일반화"를 뜻하지 않는다(명시). 미래 query 검사는 2단계.
관문 1 (비용 ≈ 분 단위, FP64 numpy): 회전 좌표에서 H = QᵀQ의 고유값 스펙트럼, head별. 상위 8/16/32 고유값 에너지 비율.
 판정: 병목 4층의 head 중앙값에서 상위 16 고유값 에너지 < 0.4 → 후보 종료(이득 기대 < 1.5×, 계산 불필요). ≥ 0.6 → 관문 2.
 0.4–0.6 → 관문 2는 실행하되 성공 문턱을 2배로 올림.
관문 2 (비용 ≈ 층·head당 수십 초, 6층×12head×2prompt, 총 1시간 내 CPU, RAM 캡처 1파일 235MB×6): OBQ 반올림 vs RTN, 같은 스케일.
 지표: (a) 평가-반 query의 logit 오차 분산 Σ_j (q_jᵀe_i)²  (b) post-W_o 출력 NSE (기존 analyze 코드 지표와 동일 정의) (c) K 텐서 상대오차(증가해도 무방, 보고만).
 성공: 병목 4층 모두에서 (b)가 RTN 대비 ≥ 2× 감소하고 B1(디더)·B2(대각 스케일 최적화)보다 ≥ 1.5× 더 낮음, 층0·29에서 악화 없음(≤1.1×).
 실패: 어느 병목 층에서든 (b) 감소 < 1.3×, 또는 B2(대각만)와 차이 < 1.2× (→ 순차 보상 불필요, 후보 축소).
 판단 불가: p0/p4가 서로 반대 방향, 또는 head 간 분산이 평균 효과보다 큼 → 2 prompt 추가 캡처는 GPU이므로 주 작업자 판단.
 관문 2 통과 시에만 GPU 단계(별도 등록): 쓰기 청크 c의 H로 양자화한 K를 청크 c+1..의 실제 query로 읽는 1-step 출력 NSE(미래 query 일반화), 그 다음 seed 2개 생성.
 p0/p4는 개발 입력이므로 생성 단계 성공 선언은 새 보류 prompt 집합에서만.

7. 가장 강한 반론
----------------------------------------------------------------------
1. [가장 강함] 쓰기 시점 자기 query ≠ 미래 query. 특히 post-RoPE에서 위치 위상이 다르고, denoise step·청크가 다르면 q 분포가 이동한다. H_c로 최적화한 반올림이
   미래 q에서는 RTN보다 못할 수 있다(과적합). 관문 2의 '같은 호출 두 반 분리'는 이것을 검사하지 못한다. 반박 가능성: RoPE 저주파 채널은 위상 변화가 작고,
   Hadamard 회전 후 H의 주성분이 W_q 구조(층 고정)에서 오면 안정적일 수 있다 — 가설이며, GPU 1-step 검사 전에는 모른다.
2. SAW-INT4 초록: "Hessian-aware 양자화는 이득이 미미". LLM 서빙 설정이고 어떤 Hessian인지 본문 미확인이지만, 가장 가까운 선행이 부정 결과를 보고한다.
   우리 설정(Q=4680 동시 query, 영상 확산)에서 다를 수 있다는 것은 추측이다.
3. 회전 후 오차는 이미 등방에 가깝다(상위 8채널 0.15, 층29 등방의 3배). 이득 상한은 H의 조건수/유효 랭크로 제한되며, 관문 1이 낮으면 후보는 처음부터 없다.
4. 순차 오차보상은 토큰 내 채널 간 오차를 상관시킨다. 이는 "채널 정렬 오차가 누적된다"는 R-8 가설과 정반대 방향의 위험이다: q 방향 오차는 줄지만
   q에 직교하는 방향의 오차가 커지고, 그 방향이 미래 q와 겹치면 FR에서 더 나쁠 수 있다. 단일 단계 NSE 성공이 생성 성공을 보장하지 않는다.
5. 생성 지표의 잡음(그룹 경계만으로 ±2 MUSIQ)이 후보의 기대 효과(p7의 −2.3 회복)와 같은 급. seed 2개·보류 prompt 없이는 어떤 결과도 등록 성공으로 못 쓴다.
6. 신규성: "query-aware rounding"이 KV 문헌에 없다고 15분 검색으로 말할 수 없다. 관문 통과 후 본문 확인 2편(SAW-INT4, QuantWM) + 검색어 4개(§2)로 재확인해야 한다.
   본문에서 같은 치환(H=QᵀQ 순차 보상)이 발견되면 후보는 "설정 이식"이 되며 기여로 남지 않는다.

8. 기존 paired kernel-feature difference 후보(ROOT_ROUND1/DECISION_KO)에 대한 수정 의견
----------------------------------------------------------------------
- ADDENDUM 4절 의견 유지: 회전 후 잔여 logit 오차 행렬 E = Q·(K−K̂)ᵀ (4680×32760, head별)의 특이값 스펙트럼이 최소 판별이다. 이것은 §5 관문 1과 같은 캡처·비슷한 비용이며,
  두 후보의 전제(저랭크 q 공간)를 한 계산으로 검사할 수 있다. 주 작업자가 원하면 관문 1 스크립트에 E의 상위 r 특이값 에너지(r=16/64/256)를 함께 넣는 것이 가장 싸다.
- 비용 측면: paired 후보는 읽기 커널 변경 + 상태 추가, 본 후보는 쓰기만 변경. 같은 캡처에서 둘을 비교하면 "바이트 0 쓰기 변경으로 회수되는 부분"을 먼저 빼고
  남는 잔차에 대해 paired 상태가 필요한지 판단할 수 있다. 순서: 관문 1 → (후보 통과 시) 관문 2 → paired 후보는 그 잔차에 대해 r 결정.
