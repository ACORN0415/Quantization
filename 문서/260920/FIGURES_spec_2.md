## 0. 전역 규칙 (여섯 장 모두)

**출력.** 벡터(PDF 또는 SVG)로 저장. 래스터 미리보기(PNG 200dpi)도 함께 내고 **사람이 눈으로 확인**한다 — 라벨 충돌·잘림·넘침은 스크립트가 못 잡는다.

**흑백 인쇄 안전.** 논문은 흑백으로 출력될 수 있다. 계열 구분은 **색만으로 하지 않는다** — 채움 해치(45°/135°)나 마커 모양을 함께 쓴다. 해치는 **값 척도 위에서 순서대로** 쓰고 장식으로 쓰지 않는다.

**축.** **이중 y축 금지.** 단위가 다른 두 양은 **패널 둘**로 나눈다(그림 5·6이 여기 해당). 0 기준선은 차이를 그리는 모든 그림에 **실선으로** 긋는다.

**그리드·마크.** 그리드와 축은 **실선 헤어라인**, 배경에서 한 단계만 어두운 색. **점선 금지**(임계선으로 오독된다). 마크는 얇게, 두꺼운 채도 높은 블록 금지.

**라벨.** **모든 점에 숫자를 붙이지 않는다.** 직접 라벨은 선택적으로 — 극단값, 0을 걸치는 막대, 캡션이 언급하는 값에만. 나머지는 축이 감당한다.

**범례.** 계열이 2개 이상이면 범례를 둔다. 1개면 제목이 이름을 대신하므로 범례를 두지 않는다.

**불확실성 — 어디에 붙이고 어디에 붙이지 않는가.** 프롬프트 짝지음 **품질 대비**에만 95% CI를 오차막대로 붙인다(t(n−1,.975), n=10). **CI가 0을 포함하는 막대는 시각적으로 구분**한다(윤곽선만 또는 옅은 채움).
**붙이지 않는 것**: 코드 변화 집계(그림 2), 단일 상태 진단(그림 3), 한 번 측정한 시간·바이트(그림 6). 이들에 n=10 t-CI를 그리면 없는 통계를 만든다.

**측정값과 계산값을 섞지 않는다.** 예측·반사실·해석식으로 계산한 양은 **해치 + "predicted"/"computed" 라벨**로 측정값과 구분한다. 색만으로 구분하지 않는다.

## 그림 1 — 정렬 × sink 상호작용 `[이 논문의 얼굴]`

**자료.** `gateK3_interaction.csv`, `gateK_aligned.csv`. n=10, 프롬프트 짝지음.

**형태.** 가로 2패널(왼쪽 INT2, 오른쪽 INT4). 각 패널에 막대 **5개**(상호작용 막대 포함), 공통 y축(MUSIQ 차이), 0 기준선.

| 막대 | INT2 | INT4 | 표시 |
|---|---|---|---|
| alignment only | +2.28 [+0.23, +4.33] | — | 실채움 + CI |
| sink only | −1.54 [−3.14, +0.06] | — | **윤곽선만** (CI가 0 포함) + CI |
| *sum of simple effects* | +0.74 [−2.72, +4.20] | +2.60 [+1.58, +3.62] | **해치 + "predicted (additive)"** |
| both | +9.96 [+6.54, +13.37] | +2.11 [+0.98, +3.23] | 실채움 + CI |
| **interaction** | **+9.22 [+5.85, +12.59]** | **−0.50 [−1.12, +0.13]** | 실채움 + CI, 다른 슬롯 색·해치로 구분 |

**상호작용 항을 직접 그린다.** 가산 예측과 결합 효과의 CI를 눈으로 비교하게 두면 독자가 상호작용 검정을 추론해야 한다. 상호작용은 그 자체로 추정량이고 CI가 있으므로 **막대로 직접 표시**한다.

INT4 패널의 alignment only·sink only 값은 `gateK_aligned.csv`에서 같은 방식으로 뽑는다.

**필수.** 세 번째 막대는 **측정이 아니라 가산 가정의 예측**이다 — 해치와 라벨로 반드시 구분한다. 이걸 실채움으로 그리면 그림이 거짓말이 된다.

**캡션에 반드시.** (a) 네 칸 모두 측정한 완전요인이다. (b) 이 그림의 목적은 **두 비트폭의 상호작용 비교**다(INT4 주효과 해석을 금지하지는 않는다 — 상호작용 비검출과 주효과 추정은 별개다). (c) INT4는 "이번 표본에서 검출하지 못했다"이지 부재의 증명이 아니다. (d) sink only의 CI가 0을 포함하므로 **악화로 읽지 말 것**.

## 그림 2 — 재양자화 코드 변화 횟수

**자료.** `requant/*.json`, `requant_a2/*.json`. 3프롬프트 × 63프레임 × 30레이어, 내용 추적.

**이 그림이 무엇을 잰 것인가 — 먼저 확정한다.** 이것은 **INT4 생성 실행 중에 돌린 audit**이다(`requant/align_off.log`, 카운터는 생성 경로에서 호출된다). **깨끗한 BF16 chunk에 저장 연산만 적용하는 진단은 `gateK1_lineage.py`이고 그것은 그림 3이다.** 둘을 섞지 않는다.

**집계 단위.** 단위는 **호출이 아니라 슬롯 비교**다 — 한 번의 호출 안에서 여러 생존 슬롯이 비교된다. 또한 이 계측기는 **K 코드만** 비교하므로 K/V 전체나 토큰 단위로 표현하지 않는다. 47,250은 **연속한 쓰기 사이의 생존 슬롯 비교 횟수**이고, 8,910은 그중 **저장된 K 코드가 달라진 비교 횟수**다.

| 집단 | 코드 변화 검출 / 비교 | 비율 |
|---|---|---|
| 이동 없음 | 1,350 / **39,690** | 3.40% |
| 이동 있음 | 7,560 / **7,560** | **100%** |
| (합) | 8,910 / 47,250 | 18.86% |

두 집단은 **47,250을 나눈다**(39,690 + 7,560 = 47,250). 다만 **변화율의 분모가 서로 다르므로** 1,350과 7,560을 같은 높이 축에 원수치로 올리지 않는다.

**x축은 시간상의 "퇴출 전/후"가 아니라 해당 비교의 "이동 없음 / 이동 있음"**으로 쓴다 — 그것이 집계 기준이다.

**형태.** 묶음 막대, y축 = **검출 비율(%)**, 각 막대에 `검출/비교` 원수치를 직접 라벨. 묶음 = {정렬 OFF, 정렬 ON}. 정렬 ON은 양쪽 0.

**필수.** 로그 축을 쓰지 않는다(0을 그릴 수 없다). ON의 0 막대는 높이 0으로 두고 **"0 / 39,690", "0 / 7,560"**을 직접 라벨한다.

**캡션에 반드시.** (a) 이것은 **K 코드 변화 검출 횟수**이지 품질 기여가 아니다. (b) 단위는 **생존 슬롯 비교**이며 호출 수도 토큰 수도 아니다. (c) 이 카운터는 **INT4 생성 실행 중에** 동작했다. (d) 이동이 있는 비교에서는 **전부**에서 K 코드가 달라졌다.

## 그림 3 — 멱등성과 격자 이동

**자료.** `gateK1_bitdiff.json` (`gateK1_lineage.py`). **이쪽이 저장 연산 단독 진단**이다 — 깨끗한 BF16 chunk에 저장 연산만 적용하므로 생성 되먹임이 들어오지 않는다. 그림 2(생성 실행 중 audit)와 혼동하지 않는다.

**y축 정의 — 이것이 틀려 있었다.** 코드가 계산하는 것은 **최초 BF16 원본 대비 오차가 아니라, 재양자화 직전 복원값 대비 변화**다. 축 라벨은 **"재양자화 전후 복원값의 상대 L2 차이"**로 쓴다.

**따라서 0의 뜻도 다르다.** 0은 "원본 양자화 오차가 없다"가 **아니라** "재양자화가 저장 내용을 바꾸지 않았다(멱등)"는 뜻이다. 라벨은 **"0 (idempotent)"**로 쓰고 "bit-exact vs original"로 쓰지 않는다.

**형태.** 묶음 막대. x축 = 비트폭 {INT4, INT2}, 묶음 = {같은 격자, 8토큰 밀림}. 값: 같은 격자 0.000e+00(양쪽) · 밀림 INT4 5.47e−2, INT2 2.01e−1. 0을 그려야 하므로 **선형 축**.

**캡션에 반드시.** (a) 재는 양은 **재양자화 전후 복원값의 변화**이며 원본 대비 오차가 아니다. (b) 이 멱등성은 **우리가 검증한 RTN 구현·dtype·격자 설정에 한정**된 관찰이다.

## 그림 4 — 앵커 효과의 분해

**자료.** `gateK0_anchor_control.csv` + 선택 이력.

**형태.** **순서를 명시한 조건부 기여**의 가로 누적 막대 — 또는 폭포(waterfall). 누적 표현이 허용되는 이유는 이것이 **순서가 정해진 조건부 대비**이기 때문이다(§5.3). **적용 순서를 축 라벨에 반드시 적는다.**

| 성분 | 값 | 표시 |
|---|---|---|
| anchor presence (chunk 1개 고정) | +7.68 [+4.86, +10.49] | 실채움 + CI |
| anchor budget 1→3 chunks | +3.50 [+1.51, +5.50] | 실채움 + CI |
| adaptive selection | **+0.00** | **오차막대 없음.** "identical selections (140/140)" 직접 라벨 |
| 합 | +11.18 (오라클 측정 +11.20) | 끝점 표시 |

**필수 둘.**
1. 세 번째 성분에 **CI를 그리지 않는다** — 구간이 아니라 "선택이 동일했다"는 관측이다.
2. **누적 끝점의 CI를 개별 CI의 합으로 만들지 않는다.** 그렇게 하면 틀린 구간이 된다. 누적 끝점(+11.18)의 CI가 필요하면 **프롬프트별 총 대비에서 다시 계산**한다. 그림에서도 **증분 CI와 누적 CI를 시각적으로 구분**한다(예: 증분은 세그먼트 위 오차막대, 누적은 끝점에 별도 표시).

**캡션에 반드시.** (a) 적용 순서. (b) 총 용량이 고정이라 앵커를 늘리면 최근 문맥이 줄어든다 — **배분 효과**다. (c) +0.00은 관측한 140회에 한정하며 **다른 입력에서 적응 선택이 불필요하다는 뜻이 아니다**.

## 그림 5 — λ sweep, 두 지표

**자료.** `vbench_lambda_per_prompt.json`, 세션 5 MUSIQ sweep.

**형태.** **세로 2패널, x축(λ) 공유.** 위 = MUSIQ 차이, 아래 = subject_consistency 차이. 각 패널에 0 기준선.

**절대 금지.** **이중 y축.** 단위가 다르고 두 축을 맞추는 순간 없는 상관을 만든다. 두 패널로 나누는 것이 이 그림의 존재 이유다 — 두 지표가 **순서를 반대로 준다**는 것을 보여야 하므로, 같은 x축 위에 세로로 쌓아 눈이 수직으로 따라가게 한다.

**표시.** λ = {0.5, 1, 2, 4, 8} + flatten(별도 마커, 축 밖 또는 주석). λ=1에 수직 안내선 하나(실선 헤어라인). λ=4가 아래 패널에서 무보정선 **아래**로 내려가는 지점을 직접 라벨한다.

**캡션에 반드시.** (a) λ≥2에서 두 지표의 순서가 반대다. (b) λ0.5와 λ1은 구별되지 않는다([−0.0057, +0.0095]). (c) **어느 지표가 옳다고 판정하지 않는다** — 불일치와 그 크기만 기록한다.

## 그림 6 — 비용

**자료.** `results/session6/b2/final_perf.bytes.json`, `gateL1_storage_*.json`.

**형태.** **가로 2패널.** 왼쪽 = 캐시 상주 메모리(GB), 오른쪽 = `inference()` 총 시간(s). **이중 축 금지.**

왼쪽 패널: BF16 6.038 · 최종 1.510(누적 표시: 패킹 세그먼트 0.647 + **BF16 pending 0.863**). pending 조각을 **해치**로 칠해 "패킹되지 않은 몫"임을 보인다.
오른쪽 패널: BF16 465.6 s · 최종 545.2 s.

**필수.** 잔차 276,960 B(전체의 0.018%)는 **그림에 그리지 않는다** — 보이지 않고, 억지로 넣으면 왜곡된다. 캡션이나 표에 적는다.

**두 패널은 같은 비교쌍의 trade-off이므로 함께 보고해도 된다** — "캐시 4.00× 감소에 시간 +17.1%"는 정당한 한 문장이다. 금지되는 것은 **하나의 점수로 환산**하거나 **양자화 단독 효과로 읽는 것**이다(두 팔은 A4 vs A1로 캐시 구성도 다르다).

**캡션에 반드시.** (a) 캐시 상주는 **peak가 아니다**(마지막 프롬프트 종료 시점, storage 단위 중복 제거). peak는 별도 값. (b) 시간은 **VAE 디코드를 포함**한 종단 시간이다. (c) 두 팔은 캐시 구성이 **A4 vs A1로 다르다** — 양자화만의 효과가 아니다. (d) 커널 단독 +26.6%는 **다른 것을 재는 값**이므로 이 그림에 넣지 않는다.
