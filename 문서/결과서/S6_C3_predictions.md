# C3 — 사전 가설과 보고 방식

**사전 등록의 한계**: 날짜를 적는 것만으로 사전 예측이 되지 않는다. 뒷받침할 당시
기록이나 commit이 없으므로 아래는 **"작성 시점의 가설, 사전 기록 여부 미확인"**이다.
또한 나는 세션 5·6 보고서와 리뷰 인용을 통해 **기존 덤프 분석 결과를 일부 본 상태**다.

**P-4는 예측이 아니다** — 정렬 ON에서 코드 변화 0은 세션 6에서 이미 관측됐다
(47,250 비교 중 0). **"기존 결과의 재현 조건"**으로 분류한다. 0이 아니게 나오면
특정 구현 오류 하나로 확정하지 않고 후보를 열거해 가른다.

## D-5 — 세 변형의 차이는 INT2에서 더 크다

**부호까지 정의한다.** 변형별 품질(평균 MUSIQ)을 $Q$라 할 때, 같은 prompt에서 짝지어

$$\Delta_b = Q_\text{global}(b) - Q_\text{query별}(b), \qquad b \in \{\text{INT2}, \text{INT4}\}$$

를 구하고, 보고할 추정량은 **difference-in-differences**

$$\text{DiD} = \Delta_\text{INT2} - \Delta_\text{INT4}$$

와 그 **90% CI**다. **DiD가 음수이면 "전역 상수의 품질 손실이 INT2에서 더 크다"**
— 이것이 가설의 방향이다.

- 각 효과의 CI 두 개를 겹쳐 보고 차이를 판정하지 **않는다**.
- INT4 효과가 0 근처이거나 음수일 수 있으므로 **비(ratio)가 아니라 차이**로 본다.
- **head별 변형은 별도 보조 분석**으로 분리한다. 주 비교는 전역 대 query별이다.
  (head별을 주 비교에 섞으면 "어느 수준의 상수가 필요한가"라는 별개 질문과
  "비트폭 의존성이 있는가"라는 질문이 뒤섞인다.)

## P-1 — INT2 코드 0 비율이 퇴출 횟수에 따라 크게 변하지 않는다

보고할 추정량: **0 비율(0~1)을 퇴출 횟수에 회귀한 기울기**(= 퇴출 1회당 0 비율 변화)와
90% CI. 결론은 "무관"이 아니라 **"선형 추세가 허용폭 이내"**로 쓰고, 비선형 관계는
잔차 플롯으로 따로 확인한다.

**독립 표본 수를 먼저 확인한다.** 군집 로버스트 SE나 혼합효과 모형을 고르기 전에
**독립 prompt 수와 군집 단위**(prompt / layer / 호출 / slot 중 무엇이 독립 단위인가)를
확인해야 한다. 현재 K1 덤프는 **prompt 1개**에서 나왔다 — 반복 관측(레이어·chunk·슬롯)이
아무리 많아도 **prompt를 넘어 일반화되는 CI가 되지 않는다.**
→ 따라서 현 덤프로는 **진단 결과로 한정**하고, 일반화 주장을 하려면 prompt 수를
늘린 덤프가 필요하다. 이 제약을 결과와 함께 적는다.

## C2 — Taylor 근사가 INT2에서 유효 범위를 벗어난다

보고할 것: $|a_{ic}| = |q_c \Delta_{ic}| / (2\sqrt d)$ 의 **분위수(중앙값·p95·p99)와
기준 초과 비율**, 그리고 **실제 보정량의 근사 오차 분포**.

**기준값(정확형)의 정의 — 중요.** 비교 기준은 현재 코드의 `exact_uniform`
(유한항 급수 + 수렴 범위 추적)이 **아니라**, 수치적으로 안정하게 계산한

$$\log\frac{\sinh a}{a}
 = \begin{cases} a^2/6 - a^4/180 + \cdots & |a| \text{ 작을 때} \\
   a - \log(2a) + \log(1 - e^{-2a}) & \text{그 외}\end{cases}$$

이어야 한다. 그래야 **Taylor 절단 오차**와 **구현의 급수 근사 오차**가 분리된다.
(현재 코드의 유한항 급수를 기준으로 쓰면 둘이 섞인다.)

**상대오차는 기준값이 0 근처일 때 불안정하므로 절대오차를 병기한다.**
$a \to 0$에서 $\log(\sinh a/a) \to 0$이므로 상대오차가 발산한다.

**최댓값 단독 판정 금지** — 표본수와 outlier에 민감하다. 0.5·3은 탐색용 참조값으로만.
