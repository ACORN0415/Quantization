## 0. 먼저 발견한 것 — 저장소의 `tools/tum_correction.py` 는 감사 전 사본이다

진단 중 실측 잔차 분산이 Δ²/12 의 **0.24~0.25 배**로 나와 모순이 생겼다. 원인: 저장소 사본 `tools/tum_correction.py` 는 Δ = **2·scale** 을 쓰고, Self-Forcing 트리의 실제 `tum_correction.py`(`6e501dd`, 2026-09-17)와 fused Triton 커널은 Δ = **scale** 을 쓴다(트리 docstring: "lam=4 reproduces the pre-audit Delta=2*scale bug"). `quantize_sym` 의 INT2 격자는 코드 {−1,0,1}·scale(실측 코드 범위 −1..1), INT4 는 {−7..7}·scale 이라 인접 간격은 scale 이다. 실제 양자화기로 재면 Δ=scale 기준 분산비는 **INT2 1.01 · INT4 0.94** 로 S5 H3(0.94~0.98)과 일치한다.

따라서 이 진단에서 **R1(λ1, Δ=2·scale) 은 프로젝트의 "λ4(버그 재현)" 이고, R1_l0.25 가 프로젝트의 실제 λ1(P3 fused λ1 과 같은 보정량)** 이다. 아래 모든 비교의 기준선은 R1_l0.25 다. 세션 6 이후의 B5~B10 은 수정된 트리로 측정됐으므로 영향이 없다. **저장소 사본은 갱신이 필요하다**(미수정 — 사용자 판단).

## 3. 판정 (사후·탐색)

1. **잔차 모형**: 잔차 분산 크기는 TUM 균등 모형 예측과 가깝다(균등·무편향 자체의 확인은 아님). "잔여 오차에 맞춘 편향 보정" 의 가치는 **PSAC 과 결합할 때** 과보정을 막는 데 있고(2.3), 단독으로는 없다(R4d0). 대각 분산이면 충분하다.
2. **PSAC 방향**: query 기저의 효과가 무작위 기저보다 훨씬 크다. **B≈E≈D 는 오프라인 대응에서의 관측**이며 온라인 성립(자기 query 로 저장 → 다음 chunk 읽기)은 v3 에서 판정한다. H 는 미측정.
3. **outlier head**: 시험한 팔 중 PSAC 계열만 B10 의 캐시 제거를 되돌렸다. Δ 기반 보정은 Δ 를 바로잡아도 끈다.
4. **0.1 목표(K4V2 보다 작은 바이트에서 품질 유지)**: attention 오차 대리 지표로는 **미달**. K4V2 λ1 과의 격차(중앙 −0.032, 층 18 −0.10)가 rollout 품질에서 비열등성 한계 안에 들어올지는 **모른다** — K4V2 λ1 자체가 BF16 과 비검출이므로 가능성은 남지만, 이 지표는 subject_consistency 를 예측하지 못한 전력이 있다(S8 §8).
5. **다음 결정은 연구 질문의 선택이다.** (a) "INT2 를 K4V2 수준으로" 는 이 자료로는 근거가 약하다. (b) "P3 INT2 λ1 의 잔여 손실(MUSIQ −6.3, subj −0.063)을 PSAC+R4d 가 얼마나 메우는가" 는 60/60 의 큰 개선이 있어 rollout 가치가 있지만, 그 결과가 좋아도 "K4V2 를 쓰면 된다" 에 답하지 못한다(r2.1 §0.1). (c) outlier head 복원과 B10 재해석은 **분석 논문 쪽 기여**로 바로 쓸 수 있다.

- 한계: 층 평균 오차는 품질이 아니고, 10층 표본을 30층으로 옮길 수 없다. 선택(consec)·평가(consec2) 분리는 사후 선택 편향을 **줄인** 것이지 없앤 것이 아니다 — 두 캡처 모두 rank·변형 결정에 이미 쓰였으므로 consec2 는 독립 확인 표본이 아니며, 이것은 **"개발 자료 안에서 선택과 평가를 분리한 탐색 결과"** 다.

1. **온라인 성립**: "시험한 chunk 20→21 전이에서, 저장 시점의 자기 query 로 고른 방향의 효과가 다음 chunk 에서 관측됐다"(B≈E≈D 회복률 1.0; 실제 λ1 대비 **59/60**). 모든 chunk 에 반복 적용한 스트리밍 실행과 생성 품질은 미확인. D 는 oracle 비교 팔이지 최적 상한이 아니다.

3. **K4V2 대비**: chunk 단위(a)·전면 대리(b) 모두 K4 쪽이 일관되게 낫다. 격차는 작고(온라인 중앙 −0.0065) 영상 품질로의 전이는 미측정. 전면 절감률은 r16 7.1% / r8 11%.

7. **권고(6차 리뷰)와 결정 사항**: r16 중단 유지, **r8 의 fused 개발은 보류**. 계속한다면 균일 PSAC8 하나를 고정하고, **참고 백엔드**(압축 상태를 저장하고 읽을 때 K 를 복원하는 dequant 경로; 설계 B 의 lowrank 백엔드와 같은 성격)로 **작업 시간 상한을 정한 품질 실험**까지만 진행한다. 기준선(K4V2 λ1·INT2 λ1)도 같은 복원 경로에서 평가해 실행 경로 차이를 통제한다. 이 구현으로 속도·peak 우위는 주장할 수 없지만 품질이 실패하면 fused 개발 비용을 아낀다. 품질 통과 시에만 실제 메모리·비용 확인과 fused 투자를 판단한다. 이 제한된 실험에도 투자하지 않으면 후보 2 로 이동한다. **어느 쪽이든 사용자 결정이며, PSAC 의 분석 결과는 남는다.**
8. **분석 논문에 쓸 수 있는 것**(투자 결정과 무관하게 남는다; 독립 기여의 강도는 선행연구 대비 차별성·재현 범위와 함께 따로 평가) — 표현은 **"기존 보정의 한계와 방향 보존 후 나타난 변화를 실측했다"** 로 쓰고, "방향 보존만이 복원한다" 는 시험한 상태·비교 팔 안으로 한정한다.: (a) INT2/INT4 잔차 분산이 Δ=scale 균등 모형 예측과 일치, (b) 층 29 outlier head 의 캐시 mass 억제(B10)는 Δ 정의를 바로잡아도 남으며, 시험한 팔 중에서는 PSAC 계열에서 완화됨, (c) 방향 선택의 온라인 성립(B≈D)과 S8 §10 행 선택 실패의 대비, (d) 저장소 사본 불일치.

**캡처의 attention 오차로 고른 λ(≈2)는 이번 P3 영상 일관성에서 λ1 보다 불리했다.** INT2 에서 λ1 은 **시험한 네 값 중 평균이 가장 좋은 기준선**이다(연속 λ 범위의 최적을 찾은 것은 아님). λ0.5 − λ1 은 CI 가 0 을 포함하므로 "0.5 < 1" 은 점추정 순서다. λ2·λ4 는 유의하게 나쁘다 — P1 경로의 M1(λ≥2 에서 subj 급락)이 P3 에서도 재현된다. K4V2 는 **λ1·λ2 차이 비검출**(평탄·동등의 입증 아님). 원인(이력 분포 vs 목적함수 vs 경로)은 이 실험으로 가를 수 없다(§4). **λ1 은 올바른 기준선으로 유지된다.** 압축 이력 재보정(C1 2단계)으로 자동 진행하지 않는다 — 국소 attention 오차가 영상 품질의 좋은 대리가 아니라는 사례가 하나 더 늘었을 뿐이다(S8 §8, S9 §6 과 함께 세 번째).

부수: (i) 이 프롬프트 집합은 BF16 에서 10/10 동적이라 앞선 eval_psac10(4/10)보다 움직임이 많다. 양자화 팔은 7/10 으로 줄고 λ4 는 1/10 — **λ 증가에 따른 동적 판정 감소가 관측됐으며 기존 캐시 mass 억제 관측(B10·S9 §2.4)과 방향이 일치한다.** 캐시 억제가 움직임 감소를 매개했는지, 또는 영상 붕괴 등 다른 변화가 dynamic_degree 를 떨어뜨렸는지는 이 자료로 가르지 못한다(λ4 MUSIQ −13 이 붕괴 쪽을 시사). (ii) K4V2 λ1 의 flicker 는 BF16 보다 **높다**(+0.006 [+0.003, +0.010], 9/10) — 깜빡임이 적다는 뜻이나 움직임 대체 지표는 낮다(−0.006). 함께 읽으면 "조금 더 정적" 쪽이다(n=10, 미검정). (iii) 시간(10 프롬프트 평균, 디코드 포함): BF16 **46.9 s** · INT2 λ1 **72.3 s (+54.2%)** · K4V2 λ1 **73.8 s (+57.4%)** — 창 21f(A1). 앞선 판의 "55~60 s" 는 오기였다. claim S2 의 +17.1% 는 **다른 구성(A4: 창 12f·sink 3)** 의 값이며 별도로 표시한다.

### 9.3 판정 (사전 등록 §3)

- **(a) 위치**: fused − BF16 증분의 과반은 **attention 커널**이고(λ1 에서 89%), 그 안에서는 **in-kernel bias(λ1)** 가 λ0 대비 커널 시간을 2 배로 만든다. 패킹은 무시 가능. 커널 밖 증분(+1.4~2.1 s device, 소형 커널 3.5 배)은 둘째 요인.
- **(b) 증거**: 2부에서 λ0 +20~24%(창 무관) vs λ1 +128~167%(창 비례). fused λ0 < 복원→FA2. 즉 §8 의 "창이 길수록 오버헤드 증가" 는 **bias 항이 창 길이에 비례해 커지는 것**과 대응한다(호출 단위; 메커니즘 확정은 3부 후).
- **(c) 개선 상한**: 완벽한 attention 커널(FA2 수준)이 얻을 수 있는 종단 이득 ≤ attention 증분 / wall. 프로파일 없는 §8 wall 로 환산(21f 창·63f 출력, device 증분을 chunk 수 비례 1.75 배로 외삽): λ1 ≈ 21.8 s / 72.3 s ≈ **30%** (λ0 ≈ 2.7 s / 54 s ≈ 5%). **10% 기준을 넘는 지렛대는 bias 구현 하나**다. 외삽이므로 ±10%p 로 읽는다.
- 커널 수정은 하지 않았다(합의). 가장 작은 후보(2차 리뷰로 정정): **같은 group 16 토큰은 Δ 가 같으므로 bias 를 group 당 한 번만 계산해 재사용**한다 — 기존 보정식을 그대로 유지하며 중복 계산만 없앤다. 이것은 **R1p(창 전체 Δ² 평균)와 다른 것**이므로 R1p 의 품질 결과를 근거로 끌어오지 않는다. segment 끝의 8 토큰 group 과 보정하지 않는 self 구간의 경계 처리가 필요하다. 공유 메모리·속도 개선 폭은 **예상**이며(타일 크기·padding·레지스터·컴파일러 배치에 의존) "16 배" 로 단정하지 않는다. 구현 개선이지 방법 기여가 아니다. 착수 여부는 사용자 결정.

**읽는 법 (호출 단위 증거 → 커널 내부 지표로 확인).**
- **메모리 대역폭 병목이 아니다.** 세 커널 모두 DRAM 처리량 ≤ 4%, L2 적중 96~99.6%. 창 21f 의 KV 는 L2 에 머문다. §8 의 체제 가설("긴 창에서 저비트 읽기의 대역폭 이득")이 기각된 이유가 여기 있다 — 읽기 바이트가 병목이 아니므로 2 bit 로 줄여도 얻을 것이 없고, rw_D 5 항("KV 는 대역폭이 아니라 용량 문제")과 일치한다.
- **세 커널 모두 지연(latency)·issue 바운드다.** eligible warp 가 스케줄러당 0.14~0.27 개, "No Eligible" 사이클 77~87%. 레지스터 255/thread 로 SM 당 블록이 2 개로 묶인다(FA2 도 같다).
- **λ1 의 2 배 비용 메커니즘**: bias 경로가 동적 공유 메모리를 49 → **75.8 KB** 로 늘려 **SM 당 블록 1 개**(공유 메모리 한도)로 떨어지고, 점유율이 8.3% 로 반감, 스케줄러당 활성 warp 1.0 개가 된다. 여기에 tensor 일(q²·Δ²ᵀ)이 더해져 tensor 활용은 26.5% 로 내려간다. 즉 λ1 비용에는 추가 연산과 점유율 반감이 함께 작용한다(합성 방식은 미확정).
- fused λ0 vs FA2: 점유율은 같고 tensor 활용이 46.5 → 36.0% — 복원 산술(언패킹·스케일)이 issue 슬롯을 더 쓰는 쪽으로 읽히나, 소스 수준 stall 표는 확인하지 않았다.
- ncu 의 "Est. Speedup"(60~77%, 점유율/지연 휴리스틱)은 **도구의 상한 힌트**이지 측정이 아니다.

**이것이 (c) 에 주는 뜻 (범위 한정, 2차 리뷰).** λ1 에서 공유 메모리 증가 → 블록 상한 1 → 점유율 반감은 **중요한 증거**다. 다만 (i) 낮은 DRAM 처리량만으로 모든 메모리 지연 병목을 배제하지 않고, (ii) 높은 L2 적중률로 모든 층의 KV 가 L2 에 상주한다고 결론내리지 않으며, (iii) 한 shape(21f) 의 결과로 전체 창 길이 실험의 원인을 설명하지 않고, (iv) 추가 연산과 점유율 감소의 비용을 단순한 "곱" 으로 표현하지 않는다. **v1 입력 단서는 해제됐다** — v2(chunk 별 패킹) 입력으로 재실행한 ncu(`ncu_fused_w21_v2.ncu-rep`, 2026-10-25 21:10)에서 모든 지표가 v1 과 ±0.3%p 안에서 같다(FA2 8.04 ms·DRAM 3.66%·점유율 14.85% / fused λ0 9.66 ms·0.83%·14.71% / fused λ1 20.33 ms·0.42%·공유 메모리 75.78 KB·블록 한도 1·점유율 8.32%). 입력 오류는 scale 값만 바꾸고 제어 흐름·메모리 배치는 바꾸지 않았으므로 예상과 일치한다. group-16 bias 재사용은 공유 메모리와 계산 비용을 줄일 **유력한 후보**다. 속도 회복 폭은 구현 후 측정한다.
