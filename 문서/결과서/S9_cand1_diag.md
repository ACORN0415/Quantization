## 0. 먼저 발견한 것 — 저장소의 `tools/tum_correction.py` 는 감사 전 사본이다

진단 중 실측 잔차 분산이 Δ²/12 의 **0.24~0.25 배**로 나와 모순이 생겼다. 원인: 저장소 사본 `tools/tum_correction.py` 는 Δ = **2·scale** 을 쓰고, Self-Forcing 트리의 실제 `tum_correction.py`(`6e501dd`, 2026-09-17)와 fused Triton 커널은 Δ = **scale** 을 쓴다(트리 docstring: "lam=4 reproduces the pre-audit Delta=2*scale bug"). `quantize_sym` 의 INT2 격자는 코드 {−1,0,1}·scale(실측 코드 범위 −1..1), INT4 는 {−7..7}·scale 이라 인접 간격은 scale 이다. 실제 양자화기로 재면 Δ=scale 기준 분산비는 **INT2 1.01 · INT4 0.94** 로 S5 H3(0.94~0.98)과 일치한다.

따라서 이 진단에서 **R1(λ1, Δ=2·scale) 은 프로젝트의 "λ4(버그 재현)" 이고, R1_l0.25 가 프로젝트의 실제 λ1(P3 fused λ1 과 같은 보정량)** 이다. 아래 모든 비교의 기준선은 R1_l0.25 다. 세션 6 이후의 B5~B10 은 수정된 트리로 측정됐으므로 영향이 없다. **저장소 사본은 갱신이 필요하다**(미수정 — 사용자 판단).

## 3. 판정 (사후·탐색)

1. **잔차 모형**: 잔차 분산 크기는 TUM 균등 모형 예측과 가깝다(균등·무편향 자체의 확인은 아님). "잔여 오차에 맞춘 편향 보정" 의 가치는 **PSAC 과 결합할 때** 과보정을 막는 데 있고(2.3), 단독으로는 없다(R4d0). 대각 분산이면 충분하다.
2. **PSAC 방향**: query 기저의 효과가 무작위 기저보다 훨씬 크다. **B≈E≈D 는 오프라인 대응에서의 관측**이며 온라인 성립(자기 query 로 저장 → 다음 chunk 읽기)은 v3 에서 판정한다. H 는 미측정.
3. **outlier head**: 시험한 팔 중 PSAC 계열만 B10 의 캐시 제거를 되돌렸다. Δ 기반 보정은 Δ 를 바로잡아도 끈다.
4. **0.1 목표(K4V2 보다 작은 바이트에서 품질 유지)**: attention 오차 대리 지표로는 **미달**. K4V2 λ1 과의 격차(중앙 −0.032, 층 18 −0.10)가 rollout 품질에서 비열등성 한계 안에 들어올지는 **모른다** — K4V2 λ1 자체가 BF16 과 비검출이므로 가능성은 남지만, 이 지표는 subject_consistency 를 예측하지 못한 전력이 있다(S8 §8).
5. **다음 결정은 연구 질문의 선택이다.** (a) "INT2 를 K4V2 수준으로" 는 이 자료로는 근거가 약하다. (b) "P3 INT2 λ1 의 잔여 손실(MUSIQ −6.3, subj −0.063)을 PSAC+R4d 가 얼마나 메우는가" 는 60/60 의 큰 개선이 있어 rollout 가치가 있지만, 그 결과가 좋아도 "K4V2 를 쓰면 된다" 에 답하지 못한다(r2.1 §0.1). (c) outlier head 복원과 B10 재해석은 **분석 논문 쪽 기여**로 바로 쓸 수 있다.

- **10% 기준 안에서는 K4 승격이 한 층도 선택되지 않는다.** 예산이 모자라서다(K4 한 층 = PSAC8 대비 +110 KB). 10% 경계의 최적 배분은 "전층 PSAC8 + 층 9·18 만 PSAC16" 이고, 평가표본에서 균일 PSAC8 대비 **0.2438 → 0.2313 (오프라인), 0.3160 → 0.3119 (온라인)** — 작은 이득.
- K4 승격은 **7% 절감(PSAC16 전층) 예산에서만** 층 18·22 에 들어오고, 균일 PSAC16 대비 이득은 0.2070 → 0.1991 로 작다. 전층 K4(0.1742)와의 격차가 더 크다.
- 정확한 결론(6차 리뷰 정정): **시험한 10층·네 선택지·오차 목적함수에서, 10% 절감 예산의 최적 배분에는 K4 가 선택되지 않았다.** K4 혼합이 예산상 불가능한 것은 아니다 — 예: K4 1층 + PSAC8 8층 + INT2 1층은 층평균 271,552 B 로 절감 10.31% 다. "불가능" 과 "최적해로 선택되지 않음" 은 다르다. 10% 아래의 고정 소수 후보는 **{균일 PSAC8, PSAC8 + 층 9·18 PSAC16}** 이다.
- 한계: 층 평균 오차는 품질이 아니고, 10층 표본을 30층으로 옮길 수 없다. 선택(consec)·평가(consec2) 분리는 사후 선택 편향을 **줄인** 것이지 없앤 것이 아니다 — 두 캡처 모두 rank·변형 결정에 이미 쓰였으므로 consec2 는 독립 확인 표본이 아니며, 이것은 **"개발 자료 안에서 선택과 평가를 분리한 탐색 결과"** 다.

**BF16 최종 반올림 확인 (v3b).** 복원 K(K̂0, K̂0+E_keep, K̂4)를 attention 직전 BF16 으로 반올림하는 옵션(`K_FINAL_BF16=1`)을 추가해 층 18·29 × 3프롬프트(온라인 scope)에서 비교: 모든 팔에서 fp32 대비 차이 **최대 9e−5**. 저장 정밀도의 마지막 단계도 결과를 바꾸지 않는다(6 상태 한정). 원자료 `v3b_{bf16,fp32}_L18_29.json`.

### 5.5 판정 (v3·3차 리뷰 반영, 탐색)

1. **온라인 성립**: "시험한 chunk 20→21 전이에서, 저장 시점의 자기 query 로 고른 방향의 효과가 다음 chunk 에서 관측됐다"(B≈E≈D 회복률 1.0; 실제 λ1 대비 **59/60**). 모든 chunk 에 반복 적용한 스트리밍 실행과 생성 품질은 미확인. D 는 oracle 비교 팔이지 최적 상한이 아니다.
2. **보정식**: 대각 잔여 분산(R4d)이면 거의 충분. 평균항(R4m)은 일관된 작은 추가 이득 — 오프라인 r8 평균 0.0018·중앙 0.0013·최대 0.0074, r16 평균 0.0007; 온라인은 그 절반 이하. 비대각 공분산(R4f)은 오프라인 0/60 손해. PSAC 후 Δ 기준 TUM 의 과보정은 두 scope 에서 재현.
3. **K4V2 대비**: chunk 단위(a)·전면 대리(b) 모두 K4 쪽이 일관되게 낫다. 격차는 작고(온라인 중앙 −0.0065) 영상 품질로의 전이는 미측정. 전면 절감률은 r16 7.1% / r8 11%.
4. **투자 기준(4차 리뷰에서 합의)**: §3.6 중단 3 의 **10% 를 유지**한다. 결과를 본 뒤 7% 로 낮추지 않는다. 그 기준으로 **r16 의 전면 구현 투자는 중단**하고 탐색 결과로 보존한다 — "방법으로 성립 불가" 가 아니라 현재 목표 대비 투자 가치 부족이다. **r8 은 계산상 11.0% 로 통과**하지만 (i) 1 pt 여유는 이 문서의 바이트 산식 기준이며 실측 상주(S8 memory_model)로 확인해야 하고, (ii) K4 chunk 대비 격차가 r16 보다 크며(4/60), (iii) 영상 품질은 미확정이다.
5. **같은 예산의 배분 비교 — 완료 (d)**: 10% 예산의 최적 배분에 K4 는 선택되지 않았다(불가능은 아님). 고정 후보는 **균일 PSAC8** 과 **PSAC8 + 층 9·18 PSAC16** 이며, 후자의 평가표본 이득은 작다(오프라인 0.244→0.231, 온라인 0.316→0.312). 둘 다 K4V2 λ1 과의 격차(오프라인 0.174, 온라인 0.299)는 남는다. 기존 JSON 으로 할 주요 배분 비교는 여기서 끝난다.
6. **자료가 지지하는 현재 상태(6차 리뷰 합의)**: *PSAC8 은 예산 안에서 보존할 만한 탐색 후보다. 그러나 K4 와의 attention 오차 차이가 남아 있고, 영상 품질과 실제 실행 비용은 미확인이다.* 남은 확인 항목은 하나가 아니라 넷이다.

   | 남은 항목 | 확인할 내용 |
   |---|---|
   | 연속 실행 | 각 chunk 가 자기 query 로 저장한 상태(기저·계수·분산)를 창 전체에서 계속 읽어도 정상 작동하는가 (chunk 15~19 의 자기 기저는 미시험) |
   | 실제 저장량 | PSAC 상태를 실제로 저장했을 때 절감이 10% 이상인가 (현재는 산식 추정 ≈11%) |
   | 영상 품질 | **사전에 정한** 비열등성 한계를 subject_consistency·MUSIQ·dynamic degree 에서 만족하는가 |
   | 실행 비용 | peak 메모리·생성 시간 증가 — 설계 A 가 보였듯 상주 절감이 peak·시간 이득을 보장하지 않는다 |

7. **권고(6차 리뷰)와 결정 사항**: r16 중단 유지, **r8 의 fused 개발은 보류**. 계속한다면 균일 PSAC8 하나를 고정하고, **참고 백엔드**(압축 상태를 저장하고 읽을 때 K 를 복원하는 dequant 경로; 설계 B 의 lowrank 백엔드와 같은 성격)로 **작업 시간 상한을 정한 품질 실험**까지만 진행한다. 기준선(K4V2 λ1·INT2 λ1)도 같은 복원 경로에서 평가해 실행 경로 차이를 통제한다. 이 구현으로 속도·peak 우위는 주장할 수 없지만 품질이 실패하면 fused 개발 비용을 아낀다. 품질 통과 시에만 실제 메모리·비용 확인과 fused 투자를 판단한다. 이 제한된 실험에도 투자하지 않으면 후보 2 로 이동한다. **어느 쪽이든 사용자 결정이며, PSAC 의 분석 결과는 남는다.**
8. **분석 논문에 쓸 수 있는 것**(투자 결정과 무관하게 남는다; 독립 기여의 강도는 선행연구 대비 차별성·재현 범위와 함께 따로 평가) — 표현은 **"기존 보정의 한계와 방향 보존 후 나타난 변화를 실측했다"** 로 쓰고, "방향 보존만이 복원한다" 는 시험한 상태·비교 팔 안으로 한정한다.: (a) INT2/INT4 잔차 분산이 Δ=scale 균등 모형 예측과 일치, (b) 층 29 outlier head 의 캐시 mass 억제(B10)는 Δ 정의를 바로잡아도 남으며, 시험한 팔 중에서는 PSAC 계열에서 완화됨, (c) 방향 선택의 온라인 성립(B≈D)과 S8 §10 행 선택 실패의 대비, (d) 저장소 사본 불일치.
