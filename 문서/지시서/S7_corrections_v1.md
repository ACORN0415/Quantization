## A. 본문 정정 (GPU 불필요, 최우선)

### A0. 숫자를 손으로 옮기는 것을 중단한다 — 근본 원인
본문 표가 CSV보다 뒤처진 것(잔여 ±3.82 vs 실제 ±4.4122, 회복량 ±6.02 vs 실제 ±6.9481)은 **사람이 옮겨 적기 때문**이다. 통계 코드를 고쳐도 본문이 따라오지 않는 구조가 남아 있는 한 재발한다.

**할 것.** `tools/render_tables.py`를 만들어 `results/session6/*.csv`에서 본문 표를 **생성**하고, `RESULTS_session6.md`의 해당 구간을 마커로 감싼다:

```markdown
<!-- AUTO:gateO_residual BEGIN -->
(스크립트가 채움)
<!-- AUTO:gateO_residual END -->
```

스크립트는 마커 사이만 교체한다. CI는 `t.ppf(0.975, n-1)`을 쓰고 표 각주에 `n`과 사용한 임계값을 **찍는다**. 그리고 `make tables && git diff --exit-code` 를 커밋 전 검사로 넣어, 본문과 CSV가 어긋나면 커밋이 실패하게 한다. 이게 A1~A5를 영구히 불필요하게 만드는 유일한 조치다.

### A3. 정렬 효과의 원인 귀속 (line 255) — 철회 후 재작성
"정렬 효과는 전부 퇴출 시 계보 효과"는 **철회.** 같은 문서가 퇴출 **전** 코드 변화 1,350회를 보고하므로 내부 충돌이다. 다음으로 교체한다.

> 재양자화는 **그룹 구성원이 바뀔 때** 일어나며 경로가 둘이다. (A) 쓰기 시 경계 블록 재스케일링 — chunk가 4,680 = 292.5그룹이라 append마다 절반 찬 경계 그룹이 남고 다음 append가 이를 재스케일한다(append당 그룹 1개). (B) 퇴출 시 격자 밀림 — 살아 있는 모든 그룹의 구성이 바뀐다(퇴출당 전체). 정렬은 두 경로를 모두 닫는다. 관측된 효과 크기는 노출량이 압도적인 (B)가 지배한다.

노출량 근거를 각주로: 상주 토큰당 재양자화 횟수가 21f는 56/32,760 ≈ 0.0017회, 63f는 14회로 **약 8,200배** 차이다. 따라서 **21f 비교의 비유의는 (A)의 부재가 아니라 모델의 예측 그대로다.** 21f에서 유의했다면 오히려 모델이 틀린 것이다. (계산: 63f=21 chunk, window=7 chunk, 퇴출 14회, 상주 32,760토큰.)

### A4. "잔여의 77%는 내용 오염" (line 82) — 인과 주장 철회
19.18 = 4.36 + 14.82는 **지표 차이의 산술 분해**이고, TF/FR 대조만으로 history·query·현재 양자화의 상호작용을 분리하지 못한다. 교체 표현: **"BF16-history 대조군 대비 추가 rollout 손실"**. "오염", "기인한다", "때문이다" 삭제.

덧붙여, 잔여의 일부는 내용 오염이 아니라 **보정식 자체의 오류**일 수 있다(C2 참조). 이 가능성을 §6에 한 문장 남겨 77% 귀속을 더 약화시킨다.

### A5. flickering trade-off (line 297)
ON−BF16 유의 + OFF−BF16 비유의로 ON−OFF를 주장하는 것은 오류다. **직접 대비의 95% CI는 [−0.002066, 0.000182]로 0을 포함한다.** 교체: "점추정은 ON이 OFF보다 나쁘나(Δ=…), 직접 대비의 95% CI가 0을 포함해 확정할 수 없다." 확정된 trade-off로 서술하는 문장 전부 제거.

### A6. 전역 점검
정정 후 `rg -n '동등|equivalent|기여.*0|no contribution|BF16 수준|on par|입증|확정|때문|caused by'` 로 전 문서를 훑어 남은 강한 주장을 개별 확인한다. **`CODEX_BRIEF.md`, `STATUS`, `THESIS_by_section.md`, `OUTLINE_unified_12p.md`도 같이** — 본문만 고치면 파생 문서가 옛 주장을 들고 있게 된다.

## B. 최종 경로 하나의 증거 통합 (GPU 필요)

리뷰의 핵심: **"BF16 동등 품질 + 8배 압축 + 속도"를 함께 달성했다는 시스템 주장은 성립하지 않는다.** 성립시키려면 하나의 실행에서 셋을 동시에 재야 한다.

### B1. 최종 경로를 K4V2 + λ1 + A4로 확정한다
K3 패킹은 `triton_kv_quant.py:91 assert bits in (2,4)` 때문에 **미지원**이다. K3V2 품질 수치에 다른 INT4 구현의 시간·메모리를 붙이는 것은 서로 다른 실험을 한 구현처럼 보이게 하므로 금지. K3V2 행은 **"이론 payload, 커널 미구현"**으로 표기하고 레시피 표에서 시간·메모리 칸을 비운다. K3는 커널 트랙 T4(비트 평면) 이후로 미룬다.

### B2. 메모리 계측을 고친다 — 현재 수치는 쓸 수 없다
`inference.py:505`의 방식(`data_ptr()`로 중복 제거 + `numel()*element_size()` 합산)은 **view를 공유하는 backing storage를 정확히 세지 못한다.** 재현 가능한 반례를 첨부한다(`memreport.py` 실행 결과):

```
storage bytes (correct) : 2250
data_ptr method (old)   : 2450   <-- offset view 중복 계상
```

`data_ptr()`는 storage_offset이 적용된 **뷰의 시작 포인터**라, 같은 storage의 다른 오프셋 뷰가 별개 버퍼로 잡힌다. 반대로 narrow 뷰는 자기 numel만 세어 상주 중인 나머지를 놓친다.

**교체.** `untyped_storage().data_ptr()` + `untyped_storage().nbytes()`로 storage 단위 중복 제거(`memreport.py:resident_bytes`). 그리고 세 값을 **모두** 보고한다:
- `torch.cuda.max_memory_allocated()` — peak 라이브 텐서
- `torch.cuda.max_memory_reserved()` — peak allocator footprint
- `resident_bytes(kv_tensors)` — 캐시 자체 몫

현재 수치는 "마지막 prompt 종료 시점의 캐시 텐서 집계"이지 peak가 아니므로, **"실제 allocation"이라는 표현을 쓰지 않는다.** 측정 시점(마지막 chunk 직후 등)을 캡션에 명시한다.

### B3. LongLive 메모리 주장 분리
`causal_model.py:953`이 BF16 `k/v`를 유지한 채 `quant_state`를 **추가**하므로, 현재 코드로는 상주 메모리가 줄지 않는다. **"메모리 20% 감소"는 이론 payload 주장으로 격리**하고, 보정 품질 결과와 실제 상주 메모리를 별도 문장·별도 표로 분리한다. BF16 master를 실제로 해제한 경로를 만들기 전에는 M1-a 수치를 시스템 주장에 인용하지 않는다.

### B4. P0 동시 측정
같은 실행 manifest에서 원본 Self-Forcing(pristine)과 최종 경로를 **같은 4090, 같은 seed, 같은 프롬프트**로 돌려 품질·bytes(B2 방식)·latency를 한 표에. 압축률은 항상 **토큰당(4.6×)과 전체(8× = 4.6 × window 1.75×)를 분리 표기**하고, window 축소는 "압축"이 아니라 "문맥 예산 선택"으로 쓴다.

## C. 분석 항목 (GPU 불필요, 덤프만 필요 — A와 병행)

### C1. d_eff 정의 검증 (최우선)
$b_i=\sum_c w_c\Delta_{ic}^2$, $w_c=q_c^2/(24d)$에서 두 정의를 모두 계산해 실측 $\sigma_b/\mu_b$와 대조:
- (A) query-only: $(\sum q_c^2)^2/\sum q_c^4$
- (C) **기여 가중**: $v_c=q_c^2\,\mathbb{E}_i[\Delta_{ic}^2]$, $d_{\text{eff}}=(\sum v_c)^2/\sum v_c^2$

합성 데이터에서는 (A)가 2~2.3배 과소예측하고 (C)가 6개 조건 전부에서 맞았다(`l3_deriv2.py`). **실측에서 (C)가 맞으면 리뷰 1차의 "예측 미지지" 지적은 수식 정정으로 해소된다.** 채널 상관 $r$을 포함한 형태: $\mathrm{CV}_b\approx\bar\rho_v\sqrt{r+(1-r)/d_{\text{eff}}}$.

### C2. Taylor 형의 유효성 (잔여 손실의 후보 원인)
$a_{ic}=q_c\Delta_{ic}/(2\sqrt d)$의 실측 분포를 뽑고, Taylor $\frac{a^2}{6}$ 대 정확형 $\log\frac{\sinh a}{a}$의 비를 비트폭별로. 합성에서 INT4 1.002, INT3 1.040, **INT2 1.712**(`l3_deriv3.py`) — INT2에서 Taylor가 편향을 71% 과대평가한다. 사실이면 보정식을 정확형으로 바꾸는 것만으로 개선되고 **추가 GPU 비용이 없다.**

**긴장 하나를 반드시 기록할 것.** Taylor가 과대평가라면 $\lambda^*\approx0.58$이어야 하는데 세션 5는 $\lambda^*\approx1$, FR 점추정 최대는 $\lambda=4$(과소보정 방향)였다. 반대 방향이다. 해석 후보: (i) 합성이 $a$ 범위를 과장, (ii) **$\lambda$ sweep이 Jensen 편향이 아닌 다른 오차원을 보상**, (iii) 상쇄. (ii)라면 O1 잔여 분해의 핵심 단서다. 실측 $a$ 분포가 셋을 가른다.

### C3. 예측 선언 (결과 나오기 전에 기록)
- **P-6.** 토큰당 코드 변화 횟수의 63f/21f 비가 10³~10⁴ 규모일 것(A3의 노출량 논거).
- **P-4.** 정렬 ON에서 코드 변화율이 **정확히 0**일 것. 0이 아니면 정렬 구현이 아직 연속 텐서를 재양자화하고 있다는 뜻 — 검사 한 줄, 가장 값싸고 결정적.
- **P-1.** INT2 코드 0의 비율은 퇴출 횟수와 **무관**할 것(소실 가설은 합성에서 기각됨). 단조 증가하면 합성이 실제 분포를 놓친 것이므로 소실 가설을 되살린다.
- **D-5.** L1 세 변형(query별/head별/전역)의 품질 차이는 **INT4에서 작고 INT2에서 클 것**(σ_b가 Δ²에 비례, CV는 비트 불변). 비트폭 의존적 차이가 예측.

이 넷은 **결과를 보기 전에** 문서에 박아둔다. 맞으면 유도가 사후 설명이 아니라는 증거가 되고, 틀리면 그것대로 보고한다.
