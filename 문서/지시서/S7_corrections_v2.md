### A3. 정렬 효과의 원인 귀속 (line 255) — 재작성
"전부 퇴출 계보 효과"는 철회. 다만 v1의 대체 문장도 과했다. 다음으로 쓴다.

> 재양자화는 **그룹 구성원이 바뀔 때** 일어나며, 구성원이 바뀌는 경로는 둘이다. (A) **쓰기 시 경계 블록 재스케일링** — 4,680 mod 16 = 8이므로 append 후 부분 그룹이 남는 경우와 정확히 맞아떨어지는 경우가 **번갈아** 나타나고, 부분 그룹은 다음 append가 채울 때 재스케일된다. (B) **퇴출 시 격자 밀림** — 퇴출 폭이 16의 배수가 아니면 생존한 모든 그룹의 구성이 바뀐다. 정렬은 두 경로를 모두 닫는다. **두 경로의 존재는 코드로 확인되며, 각 경로가 품질에 기여하는 크기는 별개 문제로 아직 분리되지 않았다.**

**노출량은 별도 문단으로, 사건 수 진술로만.** `[계산: exposure.py]` 63f 실행(21 chunk, 창 7 chunk)에서 토큰당 재양자화 **사건 수**는 퇴출 경로 4.67회(개별 토큰 최대 7회 = 창 깊이), 경계 경로 0.0014회(전체 토큰의 0.14%만 1회 겪음)로 약 **3,400배** 차이다.

이 문단에 반드시 붙일 단서 두 개.
1. **사건 수는 품질 효과가 아니다.** 노출량으로 MUSIQ 차이나 유의성을 예측할 수 없다. v1의 "21f에서 유의했다면 모델이 틀린 것"은 **삭제**한다.
2. **정합성 확인이 필요하다.** 위 계산은 경계 경로가 토큰 136개에 영향을 준다고 예측하는데, 문서는 퇴출 전 코드 변화 **1,350회**를 보고한다 `[읽음: 리뷰 인용]`. 두 수가 맞물리는지는 **세는 단위**(토큰? 원소? 레이어·헤드 합산?)에 달렸다. 단위를 확인해 대조하고, 설명되지 않는 초과분이 있으면 **제3의 경로**를 의심한다. 이것을 확인 전에 "경계 경로로 설명된다"고 쓰지 않는다.

## B. 최종 경로의 증거 (GPU)

**전제 완화.** 품질과 성능을 한 실행에서 잴 필요는 없다. **동일 소스·설정·backend를 고정하고, 진단 없는 성능 실행을 품질 실행과 추적 가능하게 연결**하면 된다(실행 manifest에 소스 해시·설정·backend·seed 기록).

### B1. 최종 경로 = K4V2 + λ1 + A4
K3 패킹은 `assert bits in (2,4)` 때문에 미지원 `[읽음: triton_kv_quant.py:91 — 리뷰 확인]`. K3V2 행은 **"이론 payload, 커널 미구현"**으로 표기하고 시간·메모리 칸을 비운다. K3V2 품질에 다른 INT4 구현의 속도를 붙이지 않는다.

### B2. 메모리 계측
storage 단위 중복 제거 + allocated/reserved peak 기록으로 **수정 완료** `[읽음: 리뷰 확인]`. self-test 결과는 **올바른 값 2250, 옛 방식 5610** `[읽음: memreport.py self-test — 리뷰 인용]`. (v1이 인용한 2450은 내 합성 예시이므로 본문에 쓰지 않는다.)

**남은 것 둘.**
1. **실험 검증 미완료** — CPU self-test만 통과했다. 4090 실행에서 세 값(allocated peak / reserved peak / 캐시 몫)을 실제로 기록해야 한다.
2. **재현성 기록 보강** — 실행 보고서가 HEAD commit만 기록하는데 관련 소스에 미커밋 변경이 있다 `[읽음: 리뷰 확인]`. 같은 commit 표기가 실행 코드의 동일성을 보장하지 못하므로 **소스 해시 또는 diff**를 manifest에 남긴다.

측정 시점(마지막 chunk 직후 등)을 캡션에 명시하고, peak가 아닌 값을 "실제 allocation"이라 부르지 않는다.

### B3. LongLive 메모리 주장 분리
`causal_model.py:953`이 BF16 `k/v`를 유지한 채 `quant_state`를 **추가**한다 `[읽음: 리뷰 확인]`. "메모리 20% 감소"는 **이론 payload 주장으로 격리**하고 보정 품질 결과와 별도 표로 분리. BF16 master를 실제로 해제한 경로 전에는 M1-a 수치를 시스템 주장에 인용하지 않는다.

### B4. 압축률 — K4V2의 값으로 교체
**4.6배·8배는 K3V2의 값이므로 최종 경로에 쓰지 않는다.** K4V2는 문서의 payload 기준으로 토큰당 **4배**(6144/1536), window 21→12를 포함해 **7배** `[읽음: 리뷰 인용 — 기준 재확인 필요]`.

그리고 이 값도 잠정이다. **최종 packed 경로의 실제 비율은 BF16 잔류 영역과 metadata까지 측정한 뒤 별도로 보고**한다(B2의 계측으로). 압축률은 항상 토큰당과 전체를 분리 표기하고, window 축소는 "압축"이 아니라 **"문맥 예산 선택"**으로 쓴다.

### B5. B6 결과를 재사용하지 않는다
B6 완료 마커는 성공을 뜻하지 않는다. 로그상 pristine과 커널 검사만 성공했고 **나머지 네 실행은 EXIT=1**(원인: `--kv_bytes_report` 중복 등록)인데 마지막에 `P0_METRICS EXIT=0`, `B6_DONE`이 찍혔다 `[읽음: b6_driver.log — 리뷰 확인]`. 중복 등록은 제거됐고 새 `b7bytes` 실행이 진행 중이다.

**할 것.** (a) 기존 B6를 성공 결과로 인용하는 곳을 전부 찾아 무효화. (b) 드라이버가 **부분 실패를 완료로 마킹하지 못하도록** 종료 코드 집계를 고친다 — 이것이 없으면 같은 사고가 반복된다. (c) 새 실행의 결과만 통합한다.

## C. 분석 (GPU 불필요)

### C1. 산점도 대응 오류 수정 — 이 절의 최우선
**현황 정정:** 기존 코드는 이미 기여 가중 d_eff를 계산한다(`a = wh * m_c`) `[읽음: gateL3_concentration.py — 리뷰 확인]`. v1의 "수식을 고치면 해소된다"는 **틀렸고**, 내 합성 유도는 그 코드를 독립 확인한 것 이상이 아니다. 불일치의 원인은 따로 있다.

**실제 결함:** 산점도가 예측값과 실측값을 **각각 정렬한 뒤 짝짓는다** `[읽음: gateL3_concentration.py:140 — 리뷰 확인]`. 이러면 관측 대응이 깨지고, **주변분포만 비슷해도 예측이 잘 맞는 그림**이 나온다. 중앙값 0.150 대 0.151이 가깝다는 사실은 관측별 예측력의 근거가 되지 못한다.

**할 것.** 행 대응을 유지해 다시 비교하고, 관측별 상관·잔차·Bland-Altman을 함께 보고한다. 이 수정 **전에는** d_eff 관련 어떤 결론도 문서에 쓰지 않는다. 수정 후 결과가 나쁘면 나쁜 대로 보고한다.

### C2. Taylor 대 정확형
`[합성]` Taylor/정확 비는 INT4 1.002, INT3 1.040, INT2 1.712였다. **합성 결과이고 실측이 아니다.**

**v1의 두 주장을 철회한다.**
- "추가 GPU 비용 없음" — `exact_uniform` 경로는 Taylor의 단일 행렬곱과 달리 여러 급수항을 계산하고 수렴 범위를 추적한다 `[읽음: tum_correction.py:215 — 리뷰 확인]`. 이름과 달리 **유한항 근사**다. 비용 동일 주장은 **실측 필요**.
- "λ* ≈ 1/1.712 ≈ 0.58" — 채널·query·key별 오차 구조와 softmax·rollout의 비선형 때문에 비율의 역수로 최적 λ를 정할 수 없다. **삭제.**

또한 "정확형"도 **독립 균일 오차 가정 아래의 식**이지 실제 양자화 오차의 보편적 정답이 아니다. RTN 오차는 값에 의존하고 채널 간 상관이 있다.

**할 것.** 실측 $a_{ic}=q_c\Delta_{ic}/(2\sqrt d)$ 분포를 뽑아 Taylor 유효 범위를 확인하고, 두 경로의 비용을 실제로 잰다. 결과가 "INT2에서 Taylor가 과대평가"를 지지하면 그때 **λ sweep과의 방향 불일치**(세션 5는 λ*≈1, FR 점추정 최대는 λ=4로 과소보정 방향)를 O1 잔여 분해의 단서로 다룬다. 지지하지 않으면 합성 결과를 폐기한다.

### C3. 예측과 재현 조건을 분리한다
**P-4(정렬 ON 코드 변화 0)는 예측이 아니다.** 세션 6에서 이미 관측됐다 `[읽음: 리뷰 확인]`. **"기존 결과의 재현 조건"**으로 분류한다. 그리고 코드 변화가 0이 아닐 때 곧바로 특정 구현 오류 하나로 원인을 확정할 수 없다 — 후보를 열거하고 가른다.

**진짜 예측으로 남길 것은 아직 관측되지 않은 것뿐**이고, 각각 **대상 데이터와 기록 시점**을 명시한다.

| 예측 | 대상 데이터 | 기록 시점 |
|---|---|---|
| D-5: L1 세 변형의 품질 차이가 INT4에서 작고 INT2에서 클 것 | L1 INT4·INT2 양쪽 실행 | 2026-09-18, 실행 전 |
| P-1: INT2 코드 0 비율이 퇴출 횟수와 무관할 것 | K1 덤프 | 2026-09-18, 분석 전 |
| C2: 실측 $\max|a|$가 INT4에서 ≲0.5, INT2에서 ≫1 | H3/L3 덤프 | 2026-09-18, 분석 전 |

이미 관측된 것을 예측표에 넣지 않는다. 이 규칙을 어기면 사전 등록의 의미가 사라진다.

## D. 미완 항목 — 완료로 표기하지 않는다
B3(고정 상수 독립 동등성), B4(최초 양자화 오차 진단), B5(저장 조건 맞춘 TF/FR n=10), B7(새 prompt×seed, 사람 평가) — **완료 근거 없음**. B8은 **부분 검증**(self 제외·Δ 배치·보정 로그는 확인, 그러나 chunk 0 동일·이후 상이만으로 보정 수식·cache reset·attention 입력까지 검증했다고 볼 수 없음).

## 우선순위
`§0 과장 제거(이 문서로 완료) → C1 산점도 대응 수정 → A0·A1 본문·CSV 동기화 → A2~A6 해석 정정 → B5 드라이버 종료코드 수정 → 성공한 최종 경로 결과만 통합(B1·B2·B4) → C2 실측 → B3 → D 표기`

## 논문 주장의 현재 위치
**분석 논문**("저장·재양자화 이력 × 캐시 구성의 상호작용")의 근거는 유지된다.
**시스템 논문**("BF16 동등 품질 + 압축 + 속도")은 성립하지 않는다. K3 패킹 커널, B2 실험 검증, B4 실측 비율이 끝난 뒤 별도 편으로 미룬다.
