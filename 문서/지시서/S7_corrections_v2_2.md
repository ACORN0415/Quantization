**표기 규칙.** 모든 정량 주장 뒤에 근거를 표시한다.

### A3. 정렬 효과의 원인 귀속 (line 255) — 재작성
"전부 퇴출 계보 효과"는 철회. 다음까지만 쓴다.

> 검토한 RTN 경로에서는 **그룹 구성 변화가 추가 재양자화 오차를 일으킬 수 있다.** 구성이 바뀌는 경로는 둘이다. (A) **쓰기 시 경계 블록 재스케일링** — 부분 그룹이 남으면 다음 쓰기가 채울 때 재스케일된다. (4,680 mod 16 = 8이므로 **창이 차기 전, 퇴출 없이 append만 하는 구간에서는** 부분 그룹이 남는 경우와 맞아떨어지는 경우가 번갈아 나타난다. **창이 찬 뒤에는 퇴출 후 남은 길이와 sink 경계가 개입하므로 이 교대 규칙이 성립하지 않는다.**) (B) **퇴출 시 격자 밀림** — 퇴출 폭이 16의 배수가 아니면 **rolling 영역의** 생존 그룹 구성이 바뀐다(**고정 sink 내부는 제외**). 정렬은 두 경로를 모두 닫는다.
> **두 경로의 존재는 코드로 확인되지만, 각 경로가 품질에 기여하는 크기는 아직 분리되지 않았다.**

서술 시 **재양자화 호출 · 코드 변화 · 오차 발생을 구분한다.** 호출이 있어도 코드가 그대로일 수 있고, 코드가 바뀌어도 오차 기여는 별개다. 세 가지를 같은 말로 쓰지 않는다.

**노출량 비율 문단은 넣지 않는다.** 세 번 틀렸고, 장부 계산이 sink·반복 denoising 호출·고정 용량 버퍼의 미사용 영역을 생략하므로 실제 코드 변화 횟수의 측정값이 아니다. 필요해지면 **실측**으로 대체한다. 장부 스크립트(`exposure2.py`)는 실측과 대조할 기준선으로만 보관하고, 문서 본문에는 인용하지 않는다.

**1,350회 관련.** 이 카운터는 토큰 수가 아니라 **이전과 코드가 달라진 chunk 슬롯 수를 비교 호출마다 합산**한 것이고, 슬롯 안에서 원소 하나만 달라도 1회다 `[간접: causal_model.py:94]`. 따라서 토큰 수와 직접 비교할 수 없다. **먼저 prompt·layer·호출·slot의 집계 단위를 맞춘다.** 단위를 맞추기 전의 불일치를 "제3의 경로"로 해석하지 않는다(v2 초판의 그 문장은 삭제).

## B. 최종 경로의 증거 (GPU)

**전제.** 품질과 성능을 한 실행에서 잴 필요는 없다. **동일 소스·설정·backend를 고정하고 추적 가능하게 연결**하면 된다(manifest에 소스 해시·설정·backend·seed).

### B1. 최종 경로 = K4V2 + λ1 + A4
K3 패킹 미지원 `[간접: triton_kv_quant.py:91]`. K3V2 행은 **"이론 payload, 커널 미구현"**으로 표기하고 시간·메모리 칸을 비운다. K3V2 품질에 다른 INT4 구현의 속도를 붙이지 않는다.
**단, K3 패킹 구현은 시스템 주장의 필수조건이 아니다.** 최종 경로가 K4V2인 이상 필요한 것은 **K4V2 경로의 품질·상주 메모리·속도 증거**다. K3는 별개의 향후 항목.

### B2. 메모리 계측
storage 단위 중복 제거 + allocated/reserved peak 기록으로 수정 완료. self-test 결과 **올바른 값 2250, 옛 방식 5610** `[간접: memreport.py self-test]`.
**남은 것 둘.** (1) **실험 검증 미완료** — CPU self-test만 통과. 4090 실행에서 세 값(allocated peak / reserved peak / 캐시 몫)을 실제 기록. (2) **재현성** — 보고서가 HEAD commit만 기록하는데 관련 소스에 미커밋 변경이 있다 `[간접: 리뷰 인용]`. **소스 해시 또는 diff**를 manifest에 남긴다.
측정 시점을 캡션에 명시하고, peak가 아닌 값을 "실제 allocation"이라 부르지 않는다.

### B3. LongLive 메모리 주장 분리
`causal_model.py:953`이 BF16 `k/v`를 유지한 채 `quant_state`를 추가 `[간접: 리뷰 인용]`. "메모리 20% 감소"는 **이론 payload 주장으로 격리**, 보정 품질과 별도 표로 분리. BF16 master를 실제 해제한 경로 전에는 M1-a 수치를 시스템 주장에 인용하지 않는다.

### B4. 압축률 — K4V2의 값으로
**4.6배·8배는 K3V2의 값이므로 최종 경로에 쓰지 않는다.** K4V2는 문서의 payload 기준으로 토큰당 **4배**(6144/1536), window 21→12 포함 **7배** `[간접: 리뷰 인용 — 기준 재확인 필요]`.
이 값도 잠정이다. **최종 packed 경로의 실제 비율은 BF16 잔류 영역과 metadata까지 측정한 뒤 별도 보고**(B2의 계측으로). 토큰당과 전체를 분리 표기하고, window 축소는 **"문맥 예산 선택"**으로 쓴다.

### B5. B6 결과 재사용 금지 + 드라이버 수정
pristine과 커널 검사만 성공, **나머지 네 실행 EXIT=1**(원인: `--kv_bytes_report` 중복 등록)인데 `P0_METRICS EXIT=0`, `B6_DONE`이 찍혔다 `[간접: b6_driver.log]`.
(a) 기존 B6를 성공으로 인용하는 곳 전부 무효화. (b) **드라이버가 부분 실패를 완료로 마킹하지 못하도록 종료 코드 집계를 고친다** — 없으면 재발. (c) 새 `b7bytes` 실행 결과만 통합.

### B6. 보정 경로의 계산 비용 실측 (C2에서 이관)
Taylor 경로(단일 행렬곱)와 `exact_uniform` 경로(다항 급수 + 수렴 범위 추적)의 **실제 시간·메모리**를 같은 설정에서 측정한다. C2의 "정확형으로 바꿔도 비용이 같다"는 주장은 이 측정 없이는 쓸 수 없다.

## C. 덤프 분석 (GPU 불필요 — 성능 측정은 전부 §B)

### C1. 산점도 대응 오류 수정 — 이 절의 최우선
**현황 정정:** 기존 코드는 이미 기여 가중 d_eff를 계산한다(`a = wh * m_c`) `[간접: gateL3_concentration.py]`. v1의 "수식을 고치면 해소"는 틀렸고, 내 합성 유도는 그 코드의 독립 확인 이상이 아니다.
**결함:** 산점도가 예측값과 실측값을 **각각 정렬한 뒤 짝짓는다** `[간접: gateL3_concentration.py:140]`. 관측 대응이 깨져 주변분포만 비슷해도 잘 맞는 그림이 나온다. 중앙값 0.150/0.151의 근접은 관측별 예측력의 근거가 못 된다.
**할 것.** 행 대응을 유지해 재비교하고 관측별 상관·잔차·Bland-Altman을 보고.
**금지 범위(좁힘).** 수정 전에 금지되는 것은 **"관측별 예측이 검증됐다"는 주장**이다. d_eff 정의 자체와 올바르게 계산된 기술통계(분포·중앙값·범위)는 그대로 보고해도 된다.

### C2. Taylor 대 정확형
`[합성]` Taylor/정확 비 INT4 1.002, INT3 1.040, INT2 1.712. **합성이고 실측이 아니다.**

**철회 둘.** "추가 GPU 비용 없음" — `exact_uniform`은 여러 급수항을 계산하고 수렴 범위를 추적하는 **유한항 근사**다 `[간접: tum_correction.py:215]`. 비용 동일은 **실측 필요**. / "λ* ≈ 1/1.712 ≈ 0.58" — 비선형 때문에 비율의 역수로 최적 λ를 정할 수 없다. **삭제.**

**λ 관련 표현 교정.** "세션 5는 λ*≈1" → **"λ=1은 이론 기본값"**. "λ=4로 과소보정 방향" → **"FR 점추정 최대는 λ=4이나 λ1과의 차이는 비유의"**. **품질 최댓값의 방향만으로 보정식이 과소보정한다고 결론내지 않는다.**

"정확형"도 **독립 균일 오차 가정 아래의 식**이지 실제 양자화 오차의 보편적 정답이 아니다(RTN 오차는 값 의존적이고 채널 간 상관이 있다).

**할 것(덤프 분석, GPU 불필요).** 실측 $a_{ic}=q_c\Delta_{ic}/(2\sqrt d)$ 분포로 Taylor 유효 범위 확인(C3의 보고 방식대로). 실측이 합성과 다르면 **폐기가 아니라 "해당 합성 조건에서는 성립하나 실제 분포를 설명하지 못함"**으로 기록한다.

**두 경로의 계산 비용 실측은 §B6으로 옮긴다** — 성능 측정이므로 이 절(GPU 불필요)에 두지 않는다.

### C3. 예측과 재현 조건을 분리
**P-4(정렬 ON 코드 변화 0)는 예측이 아니다** — 세션 6에서 이미 관측 `[간접: 리뷰 인용]`. **"기존 결과의 재현 조건"**으로 분류. 코드 변화가 0이 아닐 때 특정 구현 오류 하나로 원인을 확정하지 않고 후보를 열거해 가른다.

**사전 등록의 한계를 명시한다.** 날짜를 적는 것만으로 사전 예측이 되지 않는다. 뒷받침할 당시 기록이나 commit이 없으면 **"작성 시점의 가설, 사전 기록 여부 미확인"**으로 표기한다. 또한 나는 기존 덤프 분석 결과를 **일부 본 상태**이므로(세션 5·6 보고서, 리뷰어 인용) 그 사실을 함께 적는다.

**무엇을 보고할지를 정한다.** 임의의 임계값을 박는 것은 기준이 아니다. 사전에 정하는 것은 **추정량·비교 구조·불확실성 보고 방식**이고, 방향성 가설만 기록한다.
