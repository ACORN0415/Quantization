### 0.1 먼저 답해야 할 질문 — INT2 를 고치면 무엇을 사는가

[S8 계획 §6](S8_PLAN_iso_memory_v1.md) 의 결론을 그대로 가져온다. 같은 창(W=7)에서 INT2 − K4V2 = **323 MB (K4V2 대비 15%)**. 이 모델은 21프레임(7 chunk) 창으로 학습됐으므로 K4V2 W=7 예산에서 INT2 가 더 넣을 수 있는 8번째 chunk 는 **학습 창 밖**이다. 24 GB 카드에서 동시 스트림 수도 단순 계산으로는 2 vs 2 로 바뀌지 않는다(실측 아님).

그리고 **P3 K4V2+λ1 은 이미 BF16 과 차이가 검출되지 않는다** — MUSIQ −0.41 [−1.24, +0.43], subject_consistency −0.011 [−0.024, +0.001] (S8 계획 §4). 따라서 "P3 INT2 λ1 의 −6.26 을 메운다"는 목표는 성공해도 K4V2 를 그냥 쓰는 것과의 차이를 설명하지 못한다.

**r2 의 목표 재설정.** 후보 1·2 의 평가 목표는 **"K4V2+λ1 보다 작은 실제 상주 바이트(인자·scale·metadata·pending 포함)에서 품질을 유지하는가"**다. INT2 λ1 대비 개선은 중간 진단일 뿐 최종 판정 기준이 아니다. INT2 가 의미를 갖는 체제(8~12 GB 카드, 더 긴 학습 창을 가진 모델, 더 큰 배치)는 우리가 측정하지 않았으므로, 논문에서 쓰려면 그 체제를 가정으로 명시한다.

**판정 방식 (r2.1).** "K4V2 와 차이가 검출되지 않으면 성공" 으로 정의하지 않는다. 그 정의는 표본이 적거나 변동이 클수록 통과하기 쉬워진다. 대신:
- K4V2 λ1 대비 **메모리 절감률과 품질 차이의 95% CI 를 그대로 보고**한다.
- "품질 유지" 판정이 필요하면 **사전에 정한 비열등성 한계**(예: subject_consistency −0.01, MUSIQ −1.0 — 값은 실행 전 고정)를 쓰고, CI 하한이 한계 안에 들어올 때만 유지로 쓴다.
- 후보가 K4V2 보다 **좋을** 가능성도 배제하지 않는다. 기존 K4V2−BF16 대비가 비유의였다는 사실은 새 후보−K4V2 대비의 검출 가능성을 결정하지 않는다.

### 1.2 저랭크와 잔차 선택

- B(전층 저랭크): 캡처 attention 오차 우위가 rollout 의 subject consistency 우위로 이어지지 않았다. 국소 오차만으로 최종 품질을 보장할 수 없다.

### 1.3 보정(TUM)에 대해 우리가 이미 측정한 것 — r2 추가

후보 1 은 "TUM 의 균등 오차 가정이 깨진다"는 TUM 저자의 한계 선언에서 출발한다. 우리에게는 **그 가정과 관련된 측정이 몇 개 있지만, 실제 양자화 잔차의 분포를 잰 것은 아니다.** [claim_table](../결과서/claim_table.md) 의 상태를 그대로 쓰고, 각 측정이 **무엇을 쟀는지**를 먼저 적는다.

**측정 대상 주의 (r2.1).** B5·B6 의 대상은 보정량 b_i = (1/24d) Σ_c q_c² Δ_ic² 이고, 채널 간 변동은 **양자화 step 의 제곱 Δ²** 에 대한 것이다([집중도 분석 §1](../결과서/S6_gateL_concentration.md)). 실제 잔차 E = K − K̂ 의 채널 공분산, 평균, 분포는 **측정하지 않았다.** 따라서 아래 표는 "보정량의 채널별 기여가 집중돼 있고 독립채널 근사가 그 분산을 다 설명하지 못한다" 까지만 말하며, "균등 오차 가정이 깨졌다" 나 "PSAC 이 보존할 방향이 발견됐다" 로 읽지 않는다. 실제 잔차와 PSAC 이후 잔차의 평균·공분산·분포는 §3.5 에서 **새로 측정**한다.

## 3. 후보 1 — 중요한 K 오차 방향 보존 + 남은 오차에 맞춘 편향 보정

**우선순위 1. 연구 가설이며 효과 미측정.**

### 3.1 결합 논리

TUM 은 quantized cached/current 사이의 통계적 attention mass 편향을 보정한다. QuantWM PSAC 은 historical query 의 중요한 방향에 투영된 K 잔차를 보존해 개별 logit 오차를 줄인다. 둘은 같은 목표/보정량이 아니다.

우리의 질문: P3 INT2 위에서 중요한 오차 방향을 먼저 복원하고, 남아 있는 오차 분포에 대해서만 통계적 보정을 하면, **K4V2+λ1 보다 작은 바이트에서** 그와 구별되지 않는 품질을 얻는가?

**가설과 기존 자료의 관계 (r2.1 — 전부 검증할 가설).** B6 은 예측 보정량이 소수 채널에 집중돼 있음을 보인다. 만약 실제 잔차 E 의 에너지도 같은 소수 방향에 집중돼 있고 PSAC 이 그 방향을 보존한다면, 직교투영의 성질상 E_rem 의 **제곱합은 줄어든다.** 그러나 (i) E_rem 이 더 균등해진다, (ii) 채널 간 독립에 가까워진다, (iii) 모든 query 에서 logit 오차가 줄어든다 — 는 **어느 것도 투영의 성질에서 따라오지 않는다.** 또 B10 의 head 9 억제가 부당한 과보정인지는 참조 attention 과의 오차로 판정하지 않았다. 따라서 "PSAC 후 제거 전 Δ 기준 TUM 은 과보정이다" 는 R3/R4 와 BF16 참조 비교로 **검증할 가설**이지 기존 자료가 지지하는 결론이 아니다. 캡처에서 E 와 E_rem 의 평균·공분산·채널 집중도를 직접 재는 것이 첫 측정이다(§3.5).

### 3.2 수학적 출발점과 미해결 부분

원본 K 와 기본 복원 K_hat0 에 대해 E=K−K_hat0 라 둔다. PSAC 의 보존 성분을 E_keep 이라 하면:

- K_hat1 = K_hat0 + E_keep
- E_rem = K − K_hat1
- 다음 통계 보정의 대상은 E 전체가 아니라 E_rem 으로 검토한다.

**R4 는 함수 하나의 값 교체가 아니다 (r2.1).** 기존 구현 [tools/tum_correction.py](../../tools/tum_correction.py) 의 보정량은 b = (1/24d) Σ_c q_c² Δ_c² 이고, 이 계수는 **평균 0·균등 오차에서 Var(e_c) = Δ_c²/12** 를 전제한 것이다(그래서 (1/2d)·Var 가 (1/24d)·Δ² 가 된다). 따라서 `delta_sq` 자리에 실측 분산을 그대로 넣으면 **기존 계수 아래서 12배 작게** 계산된다. R4 는 **잔여 오차의 통계 모형에 맞춰 보정식을 재정의**하는 작업이다:

- 모형 선택: 대각(채널별 분산)으로 충분한지, 평균항(E_rem 의 평균이 0 이 아닐 수 있다 — PSAC 투영 후 특히)과 교차항(채널 공분산)이 필요한지를 §3.5 의 실측으로 정한다. 단순히 step size 에 상수 배율을 곱하는 것으로 해결됐다고 가정하지 않는다.
- 계수와 부호: 선택한 모형에서 Jensen 항을 다시 유도하고, Δ² 기반 식과 **같은 입력에서 같은 값**을 내는지 검산한다(균등 오차를 넣으면 기존 식으로 환원돼야 한다).
- 근사 오차: Taylor 가 outlier head 의 합산 보정량을 과대평가한다(**B8**; B11 은 `exact_uniform` 급수의 발산으로 다른 항목이다). R3 와 R4 에 같은 근사를 써도 **잔차 크기가 달라지면 근사 오차도 달라지므로** 섞이지 않는다고 가정할 수 없다. 작은 진단에서는 수치 안정형 정확식(느리지만 캡처에서는 가능)과 Taylor 를 둘 다 계산해 근사 오차를 따로 보고한다.
- 기대값의 score 보정은 softmax 출력 전체의 불편성이나 개별 logit 복원을 보장하지 않는다.
- 온라인 가능성과 비용: E_rem 의 통계를 **저장 시점에** 계산할 수 있어야 한다. 그 시점에는 원본 K 가 있으므로 가능하지만, 저장할 통계의 바이트(head 당 128 채널 fp16 = 256 B 수준인지, 그룹별인지, 공분산이면 훨씬 큰지)를 예산에 넣고, 배포 비용은 진단 뒤에 따로 평가한다.

### 3.3 PSAC 의 "historical query" 를 배포형으로 정의한다 — 성립 조건

**정정 (r2.1).** r2 는 "저장 시점에 쓸 수 있는 query 는 chunk j 자신의 query 뿐" 이라고 썼는데 **틀렸다.** 이전 chunk 들이 생성될 때 관측한 query 는 이미 지나갔으므로 그 **통계**는 누적해 둘 수 있다. QuantWM 원문(2026-10-24 웹 원문 확인)이 바로 그 방식이다: "이전 생성 단계에서 관측한 query" 의 head 별 2차 통계를 유지하고, **현재 chunk 를 양자화한 뒤 그 chunk 의 query 를 통계에 편입해 후속 chunk 에 쓴다.** 첫 chunk 는 이력이 없어 QSAC 은 균등 민감도, PSAC 은 비활성. 부록 D.1 은 과거 query 텐서를 보관하지 않고 head 별 통계를 점진 갱신하며 chunk 경계에서 주성분 기저를 계산하는 streaming 구현을 설명한다. K 는 모델 관례를 따르며 pre-RoPE 면 복원 후 RoPE, post-RoPE 면 직접 복원. 설정은 strictly causal, chunk 단위 streaming.

따라서 방향 추정 팔은 **원문 방식 H 를 기준선으로 포함해** 네 가지로 정의한다. S8 §10 의 B·E·D 는 그대로 재사용한다.

| 팔 | 방향 추정에 쓰는 query | 배포 가능 | 비고 |
|---|---|---|---|
| **H** | **chunk < j 들의 누적 query 2차 통계** (QuantWM 원문 방식) | 가능 | r2 에 빠져 있던 **원문 기준선**. 캡처에는 chunk 20 이전 query 가 없으므로 §3.4 참조 |
| **B** | chunk j 자기 query (step 0~4) | 가능 | S8 §10: 잔차 행 선택에서 SVD46 과 비구별 (중앙 −0.0005) |
| **E** | 자기 query 를 다음 chunk 상대 위치로 RoPE 회전 (+3 프레임) | 가능 | S8 §10: B 대비 30/30 개선 (두 캡처 재현), D 와 격차 절반, 층별 7~8/10 |
| **D** | chunk j+1 의 실제 query | **불가 (oracle)** | S8 §10: 29/30 개선 |

H 와 B/E 의 차이: H 는 과거 query 가 **더 오래된 chunk 를 읽던** 통계이고, 그 query 와 chunk j 의 상대 위치는 음수(과거가 미래를 읽지 않음)이므로 chunk j+1 이 chunk j 를 읽을 때의 상대 위치(+1 chunk)와 다르다. RoPE 상대 위치 의존이 H 에도 걸리는지, 아니면 누적 평균이 그것을 희석하는지는 **측정 전에 모른다.** H 에도 E 와 같은 위치 보정을 건 변형 **H′** 를 둘 수 있다.

**판정 기준(사전, 팔별).** 각 배포형 팔(H, H′, B, E)에 대해 **D 의 이득 중 사전에 정한 비율** 회복 여부와 층 18·22·29 에서의 부호를 따로 판정한다. 비율은 실행 전에 고정한다(예: 50% 이상이면서 세 층 중 2개 이상 양수). **한 팔의 탈락은 그 팔의 탈락이다.** E 가 떨어져도 H 는 살아 있고, 반대도 같다. 후보 1 전체가 배포형으로 성립하지 않는다고 쓰는 것은 **모든 배포형 팔이 기준에 못 미쳤을 때**뿐이다. r1 이 "RoPE 좌표계 확인" 으로 적은 것은 이 판정이다.

**S8 §10 과의 차이도 적어 둔다.** S8 §10 은 저랭크 위에 잔차 **행(토큰)** 을 골랐고, PSAC 은 **채널/방향** 을 고른다. 행 선택이 실패했다고 방향 선택이 실패한다고 단정하지 않는다. 다만 상대 위치 의존성은 logit q·k 의 성질이므로 두 선택 모두에 걸릴 수 있다.

| BF16 원본 | INT8 실행 상태(≈BF16, 오차 ~0.3%). 이 수준의 차이가 R0~R4 결과를 바꾸는지는 **R0 에서 INT8→INT2 재양자화 오차와 비교해 보고** |
| 30층 | 10층뿐. 30층 일반화는 하지 않는다 |
| 독립 표본 | 두 캡처 모두 S8 §10 에 사용됨. **사전 등록 확인은 새 캡처가 필요** (§6.5) |

**→ 진단 (a) 는 GPU 없이 이 캡처에서 돌린다.** 새 캡처는 H 기준선(b)과 사전 등록 확인 때 뜬다. 캡처 비용은 §6.5 의 실측값을 쓴다.

### 3.5 최소 진단 명세

동일 Q · 같은 원본 K/V · 같은 그룹 · 같은 마스크 · BF16 self chunk 에서:

| 팔 | 내용 | 바이트 |
|---|---|---|
| R0 | P3 INT2, 보정 없음 | INT2 |
| R1 | P3 INT2 + 기존 TUM (Taylor λ1) | INT2 |
| R2 | P3 INT2 + PSAC (H / B / E / D 변형; H 는 새 캡처 후) | INT2 + 인자 |
| R3 | R2 + 제거 전 Δ 기준 TUM | INT2 + 인자 |
| R4 | R2 + E_rem 기준 보정: **제안** | INT2 + 인자 + 통계 |
| **K4V2 λ1** | **최종 비교 대상** (0.1 목표) | K4V2 |

1차는 같은 INT2 양자화와 같은 PSAC 용량으로 R2/R3/R4 의 효과를 분리한다. 2차는 인자·통계·scale·metadata·pending 을 포함한 **실제 상주 바이트**로 K4V2 λ1 과 비교한다. 비트/rank 를 바꿔 예산을 맞춘 비교는 별도 표로 낸다. 같은 바이트가 불연속 비트폭 때문에 불가능하면 그렇게 쓰고, 바이트–오차 곡선으로 제시한다.

**측정.**
- **먼저 잔차 자체**: E = K − K̂₀ 와 E_rem 의 head 별 평균, 채널 분산, 채널 공분산(또는 그 고유값 집중도), 토큰 그룹 간 비균등성. 이것이 §1.3 에 없는 측정이고 R4 의 모형 선택 근거다.
- 캐시/self attention mass, logit·attention 출력 오차(절대·상대, BF16 참조 기준), 집중도(d_eff)와의 관계, 실제 상주 바이트.
- R3 vs R4: head 별 b 분포와 **BF16 참조 attention 대비 오차**. 특히 층 29 head 9(b 160~330)와 head 0·2(b 5~7.5)에서 R3 가 캐시 mass 를 없애는지, 그것이 참조 대비 오차를 **키우는지 줄이는지**(억제 = 과보정이 아닐 수 있다), R4 가 어떻게 달라지는지.
- **층 18·22·29 를 반드시 따로 보고.** S8 §10 에서 온라인 후보가 실패한 층이자 오차가 큰 층이다. 평균이 좋아도 이 층에서 안 되면 의미가 없다.

**지표의 한계 (r2 강조).** S8 §8 에서 30층 attention 출력 오차는 MUSIQ 순서를 예측했지만 **subject_consistency 를 예측하지 못했다.** 따라서 이 진단은 **거름망**이다. 통과한 후보만 짧은 rollout 으로 보내고, 진단 수치로 성공을 말하지 않는다. 가능하면 진단 단계에 프레임 간 유사도 대리 지표(예: 인접 프레임 attention 출력의 상관)를 함께 넣되, 그것이 rollout 지표를 예측하는지는 별도로 확인해야 한다.

**oracle 과 배포형 분리.** 팔 D 와 원본 K 를 쓰는 분석은 가능성 진단으로 표시한다. 배포형은 쓰기 시 사용 가능한 원본/자기 query 와 읽기 시 현재 query 만 쓴다. 폐기한 BF16 원본이나 미래 query 를 암묵적으로 요구하면 온라인 후보가 아니다.

### 3.6 다음 단계와 중단 조건

- **중단 1 (§3.3, 팔별):** 배포형 팔(H, H′, B, E) **모두**가 D 이득의 사전 비율을 회복하지 못하면 후보 1 은 배포형으로 종료. 일부만 탈락하면 살아남은 팔로 진행하고 탈락 팔은 기록한다. E 만 시험하고 H 를 시험하지 않은 채 종료하지 않는다.
- **중단 2:** R4 − R3 가 outlier head 를 포함해 사전 폭 이하이면 "잔여 오차 기준 보정" 은 접고 R2 단독으로 돌아간다.
- **중단 3 (투자 기준):** R4 의 실제 바이트가 K4V2 의 90% 를 넘으면 **"최소 10% 절감" 이라는 프로젝트 투자 기준을 충족하지 못한 것**이다. 95% 도 K4V2 보다 작은 예산인 것은 맞으므로 "작다고 쓸 수 없다" 가 아니라 "투자 기준 미달로 중단" 으로 쓴다. 10% 는 S8 계획 §6 의 323 MB(15%) 를 참고한 값이며 실행 전에 확정한다.
- R4 의 이득이 단순 스칼라 λ 조정으로 설명되면 복잡한 방법으로 확대하지 않는다 (λ 스윕을 R4 와 같은 표에 둔다).
- 진단 통과 후: 후보 고정 → 새 평가 표본에서 짧은 rollout (63f, A1, 7~10 프롬프트) → 비용 측정. rollout 지표는 **subject_consistency 주지표**, MUSIQ · dynamic degree · flickering 보조, 상주·peak·종단 시간을 K4V2 λ1 과 같은 표에 둔다. dynamic degree 는 정적 영상으로 일관성만 올리는 경우를 막기 위해 필수다.
- 통과 수치·허용 손실은 실행 전 고정하고 결과를 본 뒤 옮기지 않는다.

## 4. 후보 2 — 실제 압축 이력을 사용하는 calibration

**우선순위 2. Q&C 의 문제의식과 우리 rollout 관측을 연결한 제안. r2: 첫 자료점이 이미 있다.**

가설: BF16 상태에서 고른 설정보다, 압축 캐시를 실제로 사용하며 생성된 상태에서 고른 설정이 배포 시 분포에 더 맞을 수 있다.

**동기가 되는 기존 자료 (S5 NOTES §H1) — C1 의 답이 아니다 (r2.1).** teacher-forced(이력 = BF16)에서 λ4−λ1 = −4.46 (t=−3.02, λ1 우세), free-running(이력 = 압축)에서 λ4−λ1 = +2.08 (n.s.). 이것은 **이력 조건에 따라 λ 반응이 달라질 가능성**을 보여주는 자료이지, "최적 λ 가 달라졌다" 의 확정이 아니다. λ1 은 두 조건 모두에서 유효한 선택으로 남아 있고, 두 대비의 차이(상호작용)를 직접 검정하지 않았다. 또 이 실험은 calibration 상태만 바꿔 파라미터를 고른 뒤 **동일 평가 조건에서 검증**한 설계가 아니다. 단서: (i) MUSIQ 기준이며 subject_consistency 는 λ≥2 에서 순서를 반대로 준다(M1), (ii) P1 rolling 경로 측정이다. 후보 2 는 이 자료를 동기로 삼되, C1 은 **P3 경로·두 지표·같은 평가 조건**에서 새로 수행한다. "우리는 처음으로 압축 이력을 사용한다" 고 쓰지 않는다. TempoKV 도 복원 이력을 쓴다.

처음에는 P3 저장 형식·TUM 사용 여부·커널·파라미터 수를 고정한다. 작은 clipping/scale 배율 집합과 λ 로 시작하고 전체 모델이나 새 adapter 부터 학습하지 않는다.

| 단계 | 바꾸는 것 | 고정하는 것 |
|---|---|---|
| C1 | calibration 상태: BF16 이력 vs 실제 압축 이력 | 목적함수, 파라미터 종류/수, 탐색 예산 |
| C2 | 목적함수: 국소 attention 오차 vs 다음 2~3 chunk 결과 | calibration 표본 정책, 파라미터와 예산 |

오프라인 보정은 미래 결과를 평가할 수 있지만, 배포 시 파라미터는 고정해야 한다. 다중 chunk 목적함수는 동일 seed/noise 의 BF16 참조에 대한 fidelity 와 생성 품질을 구분해 정의한다. BF16 궤적과 비슷하다는 것만으로 더 좋은 영상이라고 하지 않는다.

핵심 대조: 같은 탐색 계산량으로 얻은 설정을 새로운 프롬프트/seed 에서 비교. 더 많은 데이터·탐색 비용으로 얻은 이득을 새 목적함수의 효과로 오인하지 않는다. **천장이 낮다**는 점을 미리 적는다 — 자유 파라미터가 λ 와 clipping 배율 정도면 얻을 수 있는 것은 "재사용 가능한 calibration 규칙" 이지 새 압축 방법이 아니다. 그래도 비용이 낮으므로 후보 1 이 중단 1 에서 끝나면 바로 넘어갈 수 있다.

## 5. 후보 3 — JoLT 의 배포 비용 문제 + randomized 분해 + 인자 기반 attention

**우선순위 3. 알고리즘·시스템 공동 설계 후보. r2: 비용 상한 분석 외에는 착수하지 않는다.**

- JoLT 는 fused reconstruction–attention 을 후속 과제로 명시하지만 FlashJoLT 의 randomized SVD 는 이미 구현한 방법이다.
- STAR-KV 도 Triton 커널과 재구성 비용 절감을 다룬다. "커널을 만들었다" 만으로 차별화하지 않는다.
- RTTD 는 이미 TT 형식인 텐서의 절단을 가속한다. dense KV 에 TT 를 씌우면 빨라진다는 증거가 아니다.
- 우리의 인자 직접 계산 정확성 시험(S8 §4, 30/30 통과)은 수치 대응의 출발점이며, fused 커널의 속도·peak 우위를 증명하지 않는다.
- **우리 커널 경험:** fused packed 커널 +26.6%(FA2 대비), 보정을 커널에 넣으면 +150% 이상(S8·S9). 커널 작업은 비싸고 이득은 작았다.

첫 작업은 구현보다 비용 상한 분석이다. A 의 SVD 11.1초를 줄여도 4.2% 저장 절감은 그대로다. 종단 지연·peak 가 의미 있게 개선될 여지가 있는지 판단한 뒤에만 대표 shape 에서 측정한다. 고정 rank/바이트/품질에서 비교하고, oversampling 임시 버퍼와 인자 양자화 비용을 포함한다. randomized 방법은 seed 에 따른 오차 변동도 확인한다. B 의 일관성 실패는 분해 속도 개선으로 해결되지 않는다.

## 6. 실험 공통 원칙

1. 강한 내부 기준선은 **P3 + λ1 (INT2·K4V2 둘 다)**, 외부 기준선은 목적에 따라 QuantWM/QVG/TempoKV 등을 검토한다. P1 대비만으로 새 방법을 주장하지 않는다.
2. 같은 비트 수와 같은 실제 메모리는 다르다. 상주·peak·보정 metadata·pending·임시 버퍼를 분리해 기록한다. S8 계획 §1 의 `memory_model.py` 닫힌식은 실측 3점과 0.000 MB 차로 검증돼 있으므로 새 항목(인자·통계)을 거기에 추가해 쓴다. **이 스크립트는 이 저장소 `tools/` 에 없다** — Self-Forcing 작업 트리 쪽에 있을 것이므로 위치를 찾아 여기에 기록한다.
3. 모듈별 기여를 판별하는 고정 형식 비교와 전체 같은 예산의 경쟁 비교를 별도로 낸다.
4. 관측한 tensor 오차는 품질 영향의 상한이 아니다(D10). 비검출은 동등성이 아니다.
5. **표본 분할 (r2 명시).** 이미 쓴 표본: prompts 0~2 (consec, S8 §10.1·10.2), prompts 3~5 (consec2, S8 §10.3 사전 등록 확인), prompts 3~9 (설계 A·B 탐색 rollout, 층 선택), holdout10 (설계 A 독립 확인 — 이제 개발 표본). **남은 것: prompts 6~9 는 캡처 실험에 미사용**(rollout 에는 사용). 후보 1 의 사전 등록 캡처 확인은 prompts 6~9 또는 새 프롬프트로 하고, rollout 최종 확인은 **새 프롬프트 집합**이어야 한다. 캡처 비용 **실측**: consec·consec2 각 3프롬프트 × 10층 × 9지점 = 270 파일 · **34.1 GB** (manifest). S8 §10 의 "≈12 GB" 는 사전 추정치였고 실측과 맞지 않으므로 쓰지 않는다. H 기준선용 캡처는 chunk 14~20 query 가 추가되므로 이보다 크다 — 지점 수로 미리 계산한다.
6. 실행 소스/commit/diff 해시, 명령, seed, 프롬프트 hash, 좌표계, chunk/layer/head/step/call-site 와 원자료를 연결한다. 덤프 식별자는 `(prompt, seed, chunk, step, 호출 종류, layer, head, K/V)` 다.
7. 실행 중 소스를 수정하지 않는다. GPU 배치나 캡처를 이 문서만 보고 자동 시작하지 않는다.
8. 새 검정/지표가 많으면 탐색임을 표시하고 다중 비교를 고려한다. 한 지표의 우위로 전체 품질 우위를 선언하지 않는다.

## 8. 이 인계 시점의 결론

우선 검토 후보는 **중요한 K 오차 방향을 보존한 뒤 남은 오차에 맞춰 편향을 보정하는 방식**이다. TUM 의 명시적 한계, QuantWM 의 기존 보정 수단(누적 query 통계 기반 PSAC), 그리고 우리의 기존 측정 — **보정량의 채널 집중(B6), 독립채널 근사의 불일치(B5b), outlier head 의 캐시 억제 관측(B10)** — 을 연결한다. 이 측정들은 동기이지 실제 잔차 분포의 측정이 아니며, 그 측정은 첫 산출물이다.

후보의 성립 조건은 두 가지다. **첫째**, 저장 시점에 쓸 수 있는 정보(과거 누적 query 통계 H, 자기 query B, 위치 보정 E)로 고른 방향이 미래 query(D)로 고른 방향의 이득을 사전 비율 이상 회복해야 한다 — S8 §10 은 행 선택에서 B 가 실패하고 E 가 절반 회복했음을 보였고, **H 는 아직 시험하지 않았다.** **둘째**, 결과가 INT2 λ1 보다 좋은 것이 아니라 **K4V2 λ1 보다 최소 10% 작은 실제 바이트에서 사전 비열등성 한계 안의 품질**이어야 한다 — 그렇지 않으면 K4V2 를 쓰면 된다는 질문에 답이 없다.

이는 검증할 문제를 정한 것이며, 과보정의 존재·신규성·영상 품질 이득을 확인한 것이 아니다. 문헌 중복 확인과 기존 캡처에서의 작은 인과 대조 없이 "새 방법 확보" 로 보고하지 않는다.
