# L1 해석 정정 목록 (2026-09-20)

리뷰 9차 반영. **원자료와 재현은 문제없다** — 정정 대상은 전부 **해석 문장**이다.
적용 순서: `claim_table.md` → `L1_storage_design.md` → `THESIS_position` → `S6_FINDINGS`.

## 1. "복원값을 다시 양자화하지 않는 성질"이 원인이라는 설명 — **철회**

**틀린 이유는 사실 관계다.** `L1_storage_design.md`의 설계 표 자체가 반증한다:

| 팔 | 재양자화 입력 | 격자 | MUSIQ |
|---|---|---|---|
| P1 | 복원값 | **밀림** | 41.98 |
| P2 | **복원값** | 고정 | 44.26 |
| P4 | 원본 BF16 | **밀림** | 43.96 |
| P3 | (재양자화 없음) | 고정 | 44.63 |

**P2는 복원값을 다시 양자화한다.** 따라서 P2·P3·P4를 "재양자화하지 않는다"로 묶을 수 없다. 실제 구조는 두 축이고, **P1만 두 축 모두에서 나쁜 쪽**이다(복원값 입력 AND 밀리는 격자). 나머지 셋은 **서로 다른 축을 하나씩** 고쳤다.

그리고 세 팔 사이의 **비유의로 단일 원인을 입증할 수 없다.** D6을 "조건부"로 두는 것으로는 부족하다 — 문장 자체를 바꾼다.

**교체 문구(이대로 쓴다).**
> 이 조건에서 P2와 P3는 P1보다 높은 MUSIQ를 보였다. P4의 개선은 검출되지 않았으며, P2·P3·P4 사이의 차이도 검출되지 않았다.

**"P4는 검정력이 모자랐다"도 삭제.** 가능한 설명이지 이번 결과로 확인된 사실이 아니다. (`L1_storage_design.md` §읽는 법 2의 "방향은 같고 검정력이 모자란 것으로 읽는 편이 자료에 맞다"가 해당 문장이다.)

**claim_table**: D6을 **불가**로 내리거나, 주장 문구를 위 교체 문구로 바꾸고 상태를 확정으로 둔다. "단일 원인" 해석을 조건부로 남겨두지 않는다.

## 2. "저장 방식만 바꿨다" — P3에는 성립하지 않는다

P3는 **별도 Triton 양자화 커널과 fused attention 경로**를 쓴다. 현재 문서는 이 차이를 **속도 해석의 한계로만** 적었는데, **품질의 인과 해석에도 똑같이 걸린다.**

**할 것.** 같은 입력에서 P1/P2 경로와 P3 경로의 **양자화 상태(codes·scales)와 attention 출력 대응**을 확인한다. 확인 전에는 P3의 +2.65를 "저장 설계의 효과"로 귀속하지 않고 **"P3 경로 전체의 효과"**로 쓴다.

§범위와 한계에 있는 "속도는 비교하지 않았다" 항목에 **"품질 인과 귀속도 같은 이유로 제한된다"**를 추가한다.

## 3. "내용 보존과 메모리 절감을 동시에 주는 것은 P3뿐" — 기준 명시

기준이 없으면 틀린 문장이다. **BF16 대비라면 P2도 줄어든다** `[계산]`:

| 비교 | 비 |
|---|---|
| BF16 / P3 | 3.292× |
| BF16 / P2 | 1.775× |
| P1 / P3 | 1.852× |
| P1 / P2 | 0.999× (사실상 같다) |
| P4 / P3 | 5.145× |

**교체 문구**: "**P1 대비 추가 절감**을 주는 것은 P3뿐이다(P2는 P1과 0.999×로 사실상 같다)." BF16 대비를 말하려면 그렇게 명시한다.

## 3-b. "품질 2.7점·메모리 5배"는 **서로 다른 쌍이다** — 한 쌍의 개선처럼 요약 금지

- 품질 **+2.65**: **P3 vs P1**
- 메모리 **5.145×**: **P4 vs P3**
- P1 vs P3 메모리: **1.852×**

세 값을 한 문장에 묶어 "저장 설계가 품질 2.7점·메모리 5배를 가른다"로 쓰면 안 된다. 쌍을 각각 밝혀 쓴다.

## 4. LongLive 메모리 주장 — "직접 반증"이 아니다

이번 측정이 보이는 것은 **Self-Forcing 안에 구현한 P4가 BF16 master와 quant_state를 함께 보관해 더 커진다**는 사실뿐이다. **LongLive 실제 실행의 메모리를 측정한 것이 아니다.**

**claim_table S7 교체**: 주장을 "LongLive 메모리 20% 감소"의 반증이 아니라 **"BF16 master를 유지하는 설계를 Self-Forcing에 구현하면 상주 캐시가 BF16 단독보다 크다(9.436 vs 6.038 GB)"**로 좁히고, LongLive 본체에 대한 판정은 **미측정**으로 남긴다.

`L1_storage_design.md` §읽는 법 4의 "같은 모델 안에서 직접 반증됐다"도 같은 취지로 고친다.

## 5. 문서 동기화 — 남은 셋

**5-a.** `S6_FINDINGS.md`에 **L1 저장 설계 표가 아직 없다.** 추가한다.

**5-b.** `S6_FINDINGS.md:597` 부근에 **이미 철회한 문장이 살아 있다** — "L3가 head 간 10,527배 편차를 보였으므로 **전역 상수로는 부족할 가능성이 크다**". 두 가지가 틀렸다: (i) 10,527배는 **Taylor 기준**이고 정확형은 483배다, (ii) **편차만으로 전역 상수의 품질 열세를 예측하지 않기로** 이미 정했다. 삭제하고 "전역 상수 대체 가능성은 미검증(L1 스칼라 스윕 미실행)"으로 바꾼다.

**5-c.** `THESIS_position`의 세 표현을 좁힌다.

| 현재 | 교체 |
|---|---|
| "**널리 쓰이는** 한 구현에서" | "**우리가 조사한 패치**에서" |
| "기존 평가는 …을 **묻지 않았다**" | "우리는 **저장 조건 의존성을 평가한다**" |
| "저장 조건을 **명시하지 않으면 재현되지 않는다**" | "**저장 조건 차이가 비교 결과를 바꿀 수 있다**" |

세 번째가 특히 중요하다 — 현재 문장은 **재현 불가능성**을 단언하는데, 우리가 보인 것은 **한 패치에서 조건을 바꾸면 sink 효과의 부호가 바뀐다**는 것이다.

관련해서 §2의 "**평가들**"(복수)도 근거가 없다. 조사가 찾은 P1형 경로는 우리가 쓴 패치 하나다. 독립 출판 평가를 이름 댈 수 없으면 **"우리 자신의 앞선 결론이 교란됐고 그것을 실증한다"**로 줄인다.

## 6. 정정 후 남는 것 — 이게 현재 가장 확실한 성과다

> **같은 명목 비트폭(INT2)이라도 구현 경로에 따라 품질과 실제 상주 메모리가 달라진다.** 이 조건(A1·보정 없음·n=10)에서 P2와 P3는 P1보다 높은 MUSIQ를 보였고(+2.28 [0.24, 4.33], +2.65 [1.09, 4.21]), P4의 개선은 검출되지 않았으며, P2·P3·P4 사이의 차이도 검출되지 않았다. 상주 캐시는 P3 1.834 · P1 3.397 · P2 3.402 · P4 9.436 GB다.

**이보다 강한 것은 전부 걷어낸다** — 단일 원인, 유일한 설계, 외부 구현 반증.

L1은 **분석 근거를 강화했지 새 방법의 기여를 입증하지 않았다.**
