# 세션 6 결과 — 확정된 것, 철회한 것, 확정되지 않은 것

2026-09-19 · 기준 커밋 `cfc8584` + 미커밋 변경(해시는 `final_recipe_manifest.json`)
지표: 21 chunk 평균 MUSIQ 1차. 프롬프트 10개, 63프레임, seed 0, 짝지은 t.
CI는 t(n−1, .975)×SE (n=10에서 2.262).

**표기 규칙**: 비유의를 "동등"으로 쓰지 않는다. "차이가 검출되지 않음"은 동등의
증명이 아니다. 동등성 검정(TOST)은 이 세션에서 **실시하지 않았다.**

## 1. 확정된 것

### 1.1 재양자화 격자 — 메커니즘

RTN은 **같은 격자에서 비트 단위로 정확히 멱등**하고(rel = 0.000e+00), 격자가
8토큰 밀리면 멱등이 아니다(INT4 5.47e−2, INT2 2.01e−1). 모델의 rolling은 chunk가
4,680 = 292.5블록이라 퇴출마다 8토큰씩 격자를 어긋낸다.

살아남은 슬롯이 **다른 코드로** 재양자화된 횟수(내용 추적, 3프롬프트·63프레임·30레이어):

| | 전체 | 퇴출 전 | 퇴출 후 |
|---|---|---|---|
| 정렬 OFF | 8,910 / 47,250 | 1,350 | 7,560 |
| 정렬 ON | **0 / 47,250** | 0 | 0 |

A2(sink 1 chunk)에서는 **위치가 고정된 sink 슬롯이 804회** 재양자화된다
(4,680 mod 16 = 8이라 292번째 블록이 sink/rolling 경계를 걸침).

**원인 경로는 둘이다**: (A) 쓰기 시 경계 블록 재스케일, (B) 퇴출 시 격자 밀림.
정렬은 둘 다 닫는다. **각 경로가 품질에 기여하는 크기는 분리하지 않았다.**

한계: 저장 오차만 잰 측정이다(깨끗한 BF16 chunk를 저장 체제에만 흘려넣어 생성
되먹임을 배제). 창이 7슬롯이므로 한 슬롯은 최대 6회만 재양자화되고, 오차는 그
지점에서 포화한다 — **이 상한은 메커니즘이 아니라 창 길이에서 온다.**

### 1.5 앵커 효과의 분해

오라클(오염 기준 적응 선택)이 **140회 결정 전부**에서 고정 정책 {0,1,2}와 같은
집합을 골랐고, 프롬프트별 MUSIQ가 소수점까지 동일하다 — 같은 실행이다.

| 성분 | 값 | CI95 |
|---|---|---|
| 앵커 존재 (chunk 1개 고정) | +7.68 | [4.86, 10.49] |
| 앵커 예산 1→3 chunk | +3.50 | [1.51, 5.50] |
| **적응 선택** | **+0.00** | 140/140 동일 |

합 +11.18 (세션 5가 "정책 효과"로 보고한 +11.20). 적응 선택의 기여는 **검출되지
않는다** — 오라클은 선택 이력이 동일하므로 이 경우에 한해 "동일"이 근거 있다.
주의: 총 용량이 고정이므로 앵커를 늘리면 최근 문맥이 줄어든다. **"앵커 개수 효과"가
아니라 "고정 용량에서 앵커와 최근 문맥의 배분 효과"**다.

### 1.6 보정의 효과 크기와 잔여의 산술 분해

| 양 | 평균 | CI95 | t |
|---|---|---|---|
| INT2 전체 손실 (BF16 − FR λ0) | +29.23 | ±4.83 | +13.68 |
| 보정 후 잔여 (BF16 − FR λ1) | +19.18 | ±4.41 | +9.84 |
| └ 주입 (BF16 − TF λ1) | +4.36 | ±2.14 | +4.60 |

**이것은 지표 차이의 산술 분해이지 인과 분해가 아니다.** TF/FR 대조만으로는
history·query·현재 양자화의 상호작용을 분리하지 못한다. 14.82를 "내용 오염"이라
부르지 않고 **"BF16-history 대조군 대비 추가 rollout 손실"**로 쓴다.

### 1.7 Jensen 보정의 구조 (L3)

head **안에서**: σ_b/μ_b 중앙값 0.150, 독립채널 예측 0.151.
행 대응을 유지한 관측별 비교(n=108): Pearson r = **+0.783**,
Bland–Altman [−0.107, +0.123]. **d_eff = 12** (128이 아니다 — 기여가 outlier 채널
십여 개에 몰림).
→ "분포 수준에서 예측과 일치"까지 쓸 수 있다. **"관측별로 검증됐다"는 쓸 수 없다**
(잔차 한계가 예측값 자체와 같은 자릿수).

head **사이에서**: 층 29의 한 head가 bias 2,461~6,496으로 중앙 head의 최대
**10,527배**. 층 0·15는 2~4배.
→ 세션 5의 flatten 대조군은 per-(query, head) 상수라 **per-key 구조만** 지우고
head 간 스케일은 유지한다. 따라서 세운 것은 "**per-key** 구조의 추가 기여를
검출하지 못함"이고, **"상수 하나로 대체 가능"은 별개 주장이며 미검증**이다.

### 1.8 `exact_uniform` 구현 결함

출하된 8항 급수가 수렴 반경(π)을 넘는 꼬리에서 발산한다. 수치 안정형
log(sinh a / a) 대비 최대 절대차:

| 층 | 최대 절대차 |
|---|---|
| 0 | 2.0e−03 |
| 15 | 1.3e−01 |
| **29** | **2.3e+27** |

층 29에 \|a\| 최대 192인 꼬리가 있다(\|a\|>3이 0.69%).
→ **미결이던 "H2 exact_uniform 본런"은 이 상태로 실행하면 안 된다.**
한편 두 경로의 wall-clock 비는 **1.010**이므로, 수치 안정형으로 고치면 사실상
비용 없이 교체 가능하다.

같은 측정에서 **Taylor 근사는 실측 분포에서 충분하다**: \|a\| 중앙값 0.003~0.107,
Taylor 상대오차 중앙값 1e−5~4e−4, p95에서도 1e−2 미만.
합성에서 나왔던 "INT2에서 Taylor가 1.712배 과대평가"는 **실측에서 지지되지 않는다**
(합성이 a 범위를 과장). 제약: 이 덤프는 **prompt 1개**에서 나온 진단 통계다.

### 1.11 VBench (독립 지표)

BF16 대비, 10프롬프트. **VBench의 `imaging_quality`는 MUSIQ 기반이라 우리 MUSIQ와
독립 증거가 아니다.** 독립적인 것은 `subject_consistency`(DINO)와 `temporal_flickering`.

| 런 | MUSIQ | subject_consistency | temporal_flickering |
|---|---|---|---|
| A1 INT4 | −4.61 | −0.0440 (t−10.1) | −0.0023 (t−5.2) |
| A1 INT2 | −29.23 | −0.2284 (t−40.5) | −0.0163 (t−7.6) |
| A1 INT2 + λ=1 | −19.18 | −0.1547 (t−16.2) | −0.0143 (t−7.8) |
| A1 INT2 + flatten | −18.74 | −0.1507 (t−14.2) | −0.0156 (t−6.3) |

- flatten과 taylor의 차이는 두 번째 지표에서도 검출되지 않는다(동등의 증명은 아니다).

- **정렬이 flickering을 악화시킨다고는 말할 수 없다**: ON−OFF 직접 대비의 95% CI
  [−0.002066, +0.000182]가 0을 포함한다.

### 1.12 λ sweep — MUSIQ와 subject_consistency가 순서를 다르게 준다

A1 INT2 무보정 대비, 10프롬프트 짝지은 t:

| λ | MUSIQ (세션 5) | subject_consistency |
|---|---|---|
| 0.5 | +7.09 | +0.0756 (t+5.4) |
| 1 | +10.04 | +0.0737 (t+5.4) |
| 2 | +9.33 | **−0.0541 (t−2.0)** |
| 4 | **+12.12 (점추정 최대)** | **−0.1602 (t−18.3)** |
| 8 | +11.16 | −0.1588 (t−18.5) |
| flatten | +10.49 | +0.0778 (t+5.4) |

직접 대비(subject_consistency):

| 비교 | 값 | CI95 | t |
|---|---|---|---|
| λ1 − λ2 | +0.1278 | [+0.0691, +0.1866] | +4.92 |
| λ1 − λ4 | +0.2339 | [+0.2059, +0.2618] | +18.92 |
| **λ4 − 무보정** | **−0.1602** | [−0.1800, −0.1404] | **−18.27** |
| λ0.5 − λ1 | +0.0019 | [−0.0057, +0.0095] | +0.56 **n.s.** |
| flatten − λ1 | +0.0041 | [−0.0029, +0.0111] | +1.32 **n.s.** |

두 가지를 말할 수 있다:

1. **λ=4는 subject_consistency에서 무보정보다 나쁘다** (t=−18.27). MUSIQ는 λ=4를
   점추정 최대로 보고했다. 두 지표가 λ≥2에서 **순서를 반대로 준다.**
   → 세션 5의 "FR 점추정 최대는 λ=4"는 **이 사실과 함께 쓰지 않으면 오해를 낳는다.**
   λ=1을 넘기면 self mass가 37%→74%로 BF16(≈48%)을 크게 넘는데, MUSIQ는 그 방향을
   벌하지 않고 DINO 특징 일관성은 벌한다는 해석과 정합적이다(확인된 인과는 아니다).
2. **λ=0.5와 λ=1은 구별되지 않는다** (n.s.). 최적이 1보다 아래라는 근거는 없다.
   `temporal_flickering`도 같은 방향이다: λ1 − λ4 = +0.0110 (t=+3.20).

한계: 두 지표는 다른 것을 측정하므로 "MUSIQ가 틀렸다"고 쓰지 않는다. **불일치가
있다는 사실과 그 크기**까지만 기록한다.

## 2. 철회하거나 보류한 것

| 주장 | 상태 | 이유 |
|---|---|---|
| "실측 ε은 균일하다 / 비-self 슬롯 ε = 0 / (a)(c) 기각" (세션 5 §4) | **보류** | 계측이 잰 것은 Q(x̂)−x̂이고, K1이 그 값이 같은 격자에서 **정확히 0**임을 증명했다. 항등적으로 0인 양을 측정하고 있었다 |
| "캐시 구조는 INT4에서만 돕는다" | **철회** | 정렬하면 INT2에서 sink +7.68 |
| "오라클의 정책 효과 +11.2 = 적응 선택" | **철회** | 적응 선택 기여 +0.00, 전부 앵커 예산 배분 |
| "0.75 GB, 8× 압축" | **철회** | K3 패킹 커널 없음. 최종 경로 K4V2의 **실측은 4.00×** |
| "잔여의 77%는 내용 오염" | **인과 주장 철회** | 산술 분해다 |
| "정렬이 flickering을 악화시킨다" | **철회** | 직접 대비 CI가 0 포함 |
| "per-key 구조 기여 0" | **범위 축소** | per-key에 한정. head 간 스케일은 flatten이 유지 |
| "key 단독 원인" | **범위 축소** | key **병목**. value도 유의(K4V2−K4V4 = −2.62, t=−4.75) |
| "3비트가 하한" | **범위 축소** | RTN에서. KIVI K2가 반례 후보 |
| "λ\* = 1 확정" | **표현 교정** | λ=1은 이론 기본값. FR 점추정 최대는 λ=4이고 λ4−λ1은 비유의 |
| 교차모델 목표선 21.68 | **정정** | 같은 도구·10프롬프트로 **14.67** |
| 전파:주입 5:1 · 2:1 | **n=3 예비** | `run_tf.sh --max_prompts 3`, 낙폭 지표 |
| "RTN은 near-idempotent" | **정정** | 같은 격자에서 **exact** |

## 3. 확정되지 않은 것

### 3.1 실행하지 않은 것
- **동등성 검정(TOST)** — 홀드아웃 프롬프트(`prompts_holdout10.txt`)는 만들었으나

- **O2 잔여 후보** — 게다가 1.4 때문에 INT2에서 쌓인 막대 표현 자체가 무효
- **M1-b LongLive 핵심표**, **L2**, **L4**, **M2**

- **저장 조건 맞춘 TF/FR n=10**
- **새 prompt×seed 확인, 사람 평가**

### 3.2 측정했으나 주장으로 쓸 수 없는 것
- **LongLive의 메모리 절감**: `causal_model.py:953`이 BF16 k/v를 유지한 채
  quant_state를 **추가**한다. 현재 코드로는 상주 메모리가 줄지 않는다.
  1.9의 품질 결과는 유효하나 "−20% 메모리"는 **이론 payload 주장**이다.
- **K3V2의 메모리·속도**: 패킹 커널 없음(`triton_kv_quant.py:91`). 품질만 유효.

### 5.1 고쳐야 할 것 — 보고된 수치에 영향

**F1. P0 정면 비교가 없다 (GPU ~25분).**
`b6/p0_pristine`에 릴리스 코드(`33593df`) 비디오 10개는 있으나

**"우리 패치 스택이 릴리스 코드의 BF16 경로를 바꿨는가"를 한 번도 답하지 않았다.**
63프레임 회귀는 **우리 트리의 과거 latent**와 비교한 것이라 다른 질문이다 —

**F2. 커널 오버헤드 기준선이 섞여 있다 (GPU ~10분).**

**F3. `exact_uniform`을 수치 안정형으로 교체 (GPU 불필요).**

**F5. L3·C2를 다중 프롬프트로 (GPU ~40분).**

### 5.4 이 세션에서 내가 만든 도구 버그 (재발 방지)

전부 결과에는 영향이 없었으나 기록해 둔다. 공통 원인은 **알려진 답이 있는
경우로 먼저 돌려보지 않은 것**이다(L3 분석은 합성 데이터로 검증했고 그건 잘 작동했다).

1. 재양자화 카운터를 **슬롯 인덱스**로 비교 — 퇴출로 내용이 밀린 것을 재양자화로
   셌다. 내용 추적으로 수정.
2. `analyze_s6.py`의 CSV를 f-string으로 작성 — 라벨의 쉼표 때문에 **오른쪽 모든 열이
   밀렸다**. A0(표 자동 생성)이 드러냈다. `csv.writer`로 교체.
3. `--kv_bytes_report` **argparse 중복 등록** — B6 배치 5행 중 4행을 죽였다.
4. 메모리 집계를 `t.data_ptr()`로 중복 제거 — 오프셋 뷰 중복 계상, narrow 뷰 누락.
   `memreport.py`의 storage 단위로 교체(반례 self-test 포함).
5. `pgrep -f <스크립트명>` 대기 루프가 **자기를 띄운 셸을 매칭** — 체인이 두 번
   영구 대기했다. 마커 파일 대기로 교체.
6. **실행 중인 bash 스크립트를 편집** — bash가 바이트 오프셋으로 재읽어 실행이
   어긋났고 두 GPU 작업이 동시에 돌아 하나가 OOM. 단계 추가는 **새 파일**로.

### 5.5 보고 과정에서 내가 틀린 것

1. **B6를 "한 행 실패"라고 보고** — 실제로는 5행 중 4행 실패. `tail -3`만 봤다.
2. **교차모델 목표선을 n=3 자료로 계산** — 10프롬프트 같은 도구 자료가 이미 디스크에
   있었다. 21.68이 아니라 14.67이고, "재학습 수준 달성"은 성립하지 않았다.
3. **보정의 실효 스칼라를 균일 평균으로 보고**(70.08) — outlier head 하나가 만든
   값이고 중앙 head는 ~0.6. 그대로 뒀으면 L1이 캐시를 전멸시키는 c를 sweep했다.
4. **"최적 λ가 1보다 아래일 가능성"** — 점추정 두 개(+0.0756 vs +0.0737)를 검정 없이
   비교했다. 실제로는 λ0.5 − λ1이 **n.s.**다(CI [−0.0057, +0.0095]).

공통 패턴: **집계·표본·검정을 확인하기 전에 수치를 말했다.** 절차로 옮긴 것 —
`ls results/*_per_prompt.json`을 먼저 보기, 평균과 중앙값을 함께 보기,
두 점추정을 비교할 때는 직접 대비의 CI를 먼저 계산하기.
