# S9 프로파일 v2 리뷰 및 group-16 bias 재사용 검증 권고

작성일: 2026-10-25  
대상: 사용자 및 다음 커널 개선 담당자  
성격: 리뷰·후속 검증 권고. 실행 결과 또는 신규 실험의 사전 등록을 대신하지 않는다.

## 1. 결론

**group-16 bias 재사용을 작은 구현 개선으로 시험할 근거는 충분하다.** QVG 환경 설치는 이 개선의 결과 뒤에 판단한다. 같은 그룹의 scale로 계산하는 bias를 한 번 계산해 16개 토큰에 재사용하는 것이 목표다. 서로 다른 그룹의 scale을 평균내는 근사는 포함하지 않는다.

성공하더라도 동일 수식의 중복 계산 제거만으로 독립적인 새 방법론이 생기는 것은 아니다. 현재 경로의 실용성과 시스템 평가를 개선하는 작업으로 다룬다.

이 문서 작성에서는 GPU 실행, 커널 수정, 커밋 또는 푸시를 수행하지 않았다.

## 2. 대조한 자료와 확인 범위

- [S9 결과서](../결과서/S9_cand1_diag.md) §9.1~§9.6.
- [프로파일 사전 등록](../지시서/S9_profile_prereg.md).
- 사용자 보고의 ncu v2 요약 및 커밋 식별자 `54e5a54`, `ab64948`.

본 리뷰에서는 결과서의 v2 기록을 확인했다. 원본 `.ncu-rep`를 새로 분석하거나 GPU 측정을 재실행하지 않았으며, 보고된 커밋의 개별 변경을 전수 감사한 것은 아니다.

## 3. v2가 확인한 것

v1 벤치는 과거 6개 chunk를 통째로 양자화해 head당 scale 1,755행을 만들면서, 커널에는 chunk별 293행씩 총 1,758행인 것으로 전달했다. 실제 생성 경로처럼 chunk별로 양자화·연결하도록 수정한 v2를 이후 성능 해석의 근거로 사용한다. v1은 오류·정정 이력으로 보존한다.

결과서 §9.6에서 λ0 출력 비교는 NaN·큰 오차 대신 네 창에서 약 3.0~3.1e−3으로 기록됐다. 이 관측값 자체가 일반적인 허용 오차나 모든 입력의 정확성 상한은 아니다. λ1 개선 커널은 별도의 출력 대응 검증이 필요하다.

결과서 §9.5의 ncu v2 기록:

| 지표 | FA2 | fused INT2 λ0 | fused INT2 λ1 |
|---|---:|---:|---:|
| ncu 실행 시간 | 8.04 ms | 9.66 ms | 20.33 ms |
| 달성 점유율 | 14.85% | 14.71% | 8.32% |
| DRAM 처리량 | 3.66% | 0.83% | 0.42% |

λ1의 공유 메모리는 75.78 KB, 공유 메모리에 따른 SM당 블록 한도는 1개다. 보고된 v1·v2 자원 지표와 실행 시간이 거의 같으므로, 잘못된 scale 입력 때문에 기존 성능 관측이 발생했다는 우려는 해소된다. 이것이 v1의 잘못된 입력이나 출력 비교를 소급해서 유효하게 만드는 것은 아니다.

ncu 아래 실행 시간은 일반 CUDA 이벤트 측정과 구분한다. 특히 값의 차이와 비율이 계측 밖에서도 그대로 유지된다고 가정하지 않는다.

## 4. 주장 범위를 좁힐 두 문장

### 4.1 “오버헤드의 89%가 attention 커널”

권장 문구:

> 계측한 1프롬프트·36프레임 출력·21프레임 창 조건에서, BF16 대비 증가한 GPU 실행 시간 중 약 89%가 attention 구간의 증가로 집계됐다.

이는 모든 창 길이, 모든 프롬프트 또는 종단 벽시계 시간에 적용되는 비율이 아니다. 프로파일 없는 실제 생성 시간은 별도로 측정한다. 다른 출력 길이로 선형 외삽한 약 30%는 엄밀한 개선 상한이 아니며, 근거 없는 ±10%p를 신뢰구간처럼 제시하지 않는다. 기존 메모리 절감 투자 기준 10%와 실행 시간 개선 목표도 구분한다.

### 4.2 “공유 메모리 증가가 시간 두 배의 원인”

권장 문구:

> 시험한 shape에서 λ1 경로는 공유 메모리 사용량 증가로 SM당 블록 상주 한도가 1개로 제한됐고, 낮은 점유율과 긴 실행 시간이 함께 관측됐다. 추가 연산과 점유율 감소에 각각 어느 정도의 비용을 귀속할지는 아직 확인하지 않았다.

같은 수식을 유지하면서 자원 사용량을 줄인 개선 커널이 이 설명을 시험하는 대조가 된다. “추가 연산 × 점유율 반감”이라는 정량적 분해는 사용하지 않는다.

## 5. 구현 전 고정할 관문

### 5.1 출력 대응

- 동일한 Q, packed K/V, scale, self chunk, 마스크와 경계를 두 커널에 넣는다.
- INT2와 K4V2, 여러 창 길이, chunk 끝의 8토큰 부분 그룹, self 구간, λ0·λ1을 포함한다.
- 비트 일치 여부와 절대·상대 오차를 보고한다. 계산 순서가 달라질 수 있으므로 비트 일치만을 필수 조건으로 삼지 않고, 허용 오차와 집계 방식을 구현 결과를 보기 전에 고정한다.
- 기존 벤치의 관측 오차를 그대로 새 허용 오차로 승격시키지 않는다. 실제 활성과 무작위 입력의 검사 범위를 구분한다.
- 현재 보정식과 scale·dtype·반올림 규칙을 유지한다. 그룹별 계산 재사용은 R1p의 창 전체 scale 평균과 다른 작업이다.

### 5.2 커널 비용

공유 메모리, 레지스터, 블록 상주 한도, 달성 점유율, CUDA 이벤트 실행 시간을 함께 측정한다. 기존 커널과 같은 입력·워밍업·반복 조건을 사용한다. Nsight 측정은 자원과 병목 해석에 사용하고 일반 실행 시간과 분리한다.

49 KB 복귀, λ0 수준 속도, 16배 가속은 보장하지 않는다. 타일 크기, padding, 레지스터 생존 구간 및 컴파일러 배치가 결과를 바꿀 수 있다.

### 5.3 실제 생성

프로파일 훅을 끈 동일 조건에서 종단 시간과 peak 메모리를 측정한다. 출력 차이가 있다면 미리 고정한 소수 프롬프트로 영상 지표도 확인한다. 짧은 rollout은 회귀 점검이며 품질 동등성 입증으로 표현하지 않는다.

비트 일치한 경로에 불필요한 품질 배치를 반복하는 대신, 실제로 달라진 부분과 남은 불확실성에 맞춰 검증 범위를 정한다.

## 6. 프로파일 해석에서 유지할 제한

- 낮은 DRAM 처리량은 해당 실행에서 DRAM 대역폭 포화를 지지하지 않는다. 모든 메모리 지연이나 L2 병목을 배제하지는 않는다.
- 높은 L2 적중률은 전체 모델의 모든 층 KV가 L2에 상주한다는 증거가 아니다.
- eligible warp 부족은 관측된 현상이다. 구체적인 stall 원인을 추가 확인하지 않고 단일 원인으로 확정하지 않는다.
- 21프레임 창의 단일 shape 결과로 전체 창 길이 실험의 원인을 설명하지 않는다.
- ncu의 Est. Speedup은 휴리스틱 제안이며 측정된 개선이나 엄밀한 상한이 아니다.

**결과서 내부 잔존 표현:** §9.5 앞부분의 “메모리 대역폭 병목이 아니다”, “KV는 L2에 머문다”, “도구의 상한 힌트”는 뒤쪽 범위 제한 문단보다 강하다. 후속 편집에서는 위 제한과 일치하도록 앞부분도 고친다. 본 리뷰 작성에서는 원 결과서를 덮어쓰지 않았다.

## 7. 권고 순서와 결과의 용도

1. 기존 v2 벤치를 기준으로 출력 관문과 시간 측정 기준을 고정한다.
2. 그룹별 동일 bias 계산 재사용을 구현한다.
3. 출력 대응과 컴파일 자원·커널 시간을 확인한다.
4. 가능성이 있으면 실제 생성 시간·peak 및 필요한 회귀 점검을 수행한다.
5. 결과를 보고 QVG의 동일 하드웨어·동일 창 비교 투자 여부를 판단한다.

성공 시 주장할 것은 시험한 조건에서 기존 보정식을 유지하며 줄인 자원·실행 비용이다. 개선 폭이 작거나 종단 이득이 없으면 그것도 기록하고 확장을 멈출 수 있다. PSAC 및 calibration 탐색의 종료 판단과는 별개의 구현 평가로 보존한다.
